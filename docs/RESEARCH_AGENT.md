## 1. 研究的输入先是事实

一次研究先回答：当前真的装了什么，实际做了什么，哪里未达到要求，之前试过什么。

Context 中的 `inspection` 从实际运行时生成，包含加载的 W/R、策略目标、输入规格、默认策略、启用状态及动作路线。候选计划只是预期，不能作为已生效证据。加载失败、规则覆盖模型、输入字段为空和机制没有触发，应能从记录中区分。

执行结果与评价意见按来源保留。环境给出任务结果；人可以提出业务要求；LLM 归纳原因只是待检验解释。LLM 不能把自己的诊断改写成 env 真值。

### 1.1 行为缺口

拟建 Requirement 是现有实验记录内的有类型载荷：

| 字段 | 意义 |
|---|---|
| `context` | 行为发生的情境、任务阶段与合法可见输入 |
| `expected_behavior` | 来自任务或业务材料的期望行为 |
| `observed_behavior` | 实际发生了什么，不推断未观测动作 |
| `evidence_refs` | Context 中实际存在的轨迹、结果或材料 |
| `acceptance` | 可观察的验收行为；正式评分规则仍由 K 决定 |
| `recurrence` | 有证据的复发次数，区分新问题和旧要求未兑现 |
| `status` | open / addressed / regressed / insufficient_evidence |

“应该核对已执行操作是否覆盖任务要求”是行为要求；“训练一个小模型”是实现候选。候选可以采用 prompt、规则、工作流或小模型，不能在诊断时就把实现锁死。

同一行为有多个来源时合并并保留来源；不同问题分开。缺材料、基础设施故障和已解决要求不默认触发训练。Requirement 的验收说明不能覆盖官方任务评分。

## 2. 从诊断到实验

1. 按缺口检索相关成功、失败与回归，核对旧经验在当前版本是否适用。
2. 判断是信息不足、流程遗漏、明确约束、可学习判断，还是暂时没有干预机会。
3. 选择最简单的可执行改动，并说明为什么可能改变完整结果。
4. 需要训练时引用已登记反馈构造器、数据组和配方；没有可靠动作标签则不进入监督训练。
5. 输出候选或明确后续动作：继续采集、补材料、修复运行、停止。为保持接口兼容，无候选可沿用空列表，原因进入实验日志。

默认一轮一个候选。同一假设可包含多个必要改动，不强制单变量或遍历消融矩阵。小模型价值和研究策略价值分别用对应最小对照验证。

### 2.1 Experiment

Experiment 包装现有 Candidate；不是新的作业平台。

| 研究员填写 | 含义 |
|---|---|
| `owner` | worker 或 research；research 目标在 M7 才开放 |
| `requirements` | 有来源的行为缺口；research 候选描述研究过程的缺口 |
| `hypothesis` | 行为为何失败、改动预期怎样生效 |
| `evidence_refs` | 当前 Context 允许引用的证据 |
| `changes` | 对已注册目标的 spec、recipe、prompt、rule 或 workflow 差异 |
| `training` | null，或已登记决策点、反馈构造器、允许配方与数据选择 |
| `expected` | 预期任务效果或研究效果，仅是假设 |
| `abandon_if` | 什么开发结果意味着停止这个方向 |
| `notes` | 适用范围、替代解释和局限 |

框架填写并锁定：实验 ID、W/R 父版本、实际候选差异、经验快照、模型身份、数据与反馈版本、对照、评测范围、资源上限、作业引用、实际费用、结果及裁决。研究员可以建议对照，不能降低正式比较标准。

业务示例（格式示意，无真实证据，不可直接执行）：

```json
{
  "owner": "worker",
  "requirements": [{
    "context": "agent 准备结束业务任务",
    "expected_behavior": "结束前根据任务要求和合法工具返回核对是否有未执行步骤",
    "observed_behavior": "已执行部分操作后直接声称全部完成",
    "evidence_refs": ["train/example-placeholder"],
    "acceptance": "完整任务通过，且没有不必要地重复已完成操作",
    "recurrence": 0,
    "status": "open"
  }],
  "hypothesis": "结束判断没有对照任务要求，先明确该流程，再检验是否需要学习策略。",
  "evidence_refs": ["train/example-placeholder"],
  "changes": [{
    "kind": "prompt",
    "target": "worker.finish",
    "change": "结束前将用户要求与已有工具执行证据对应；缺证据时使用已授权工具核查。"
  }],
  "training": null,
  "expected": {"metric": "task_completed_correctly", "direction": "up"},
  "abandon_if": "完整开发评测没有改善，额外查询增加了成本。"
}
```

示例 target 也须由实现注册才可运行。模型输入不得包含离线 rubric、世界快照或参考答案。

## 3. Context 与经验继承

| 部分 | 内容 |
|---|---|
| `goal` | 固定任务目标、预算、可改目标和正式比较协议 |
| `inspection` | 实际 W/R、输入覆盖、策略与默认路线、运行配置摘要 |
| `task_metrics` | train/dev 成功、失败、成本、延迟；分数与任务身份可追溯 |
| `requirements` | 有证据的行为缺口、处理状态与复发 |
| `activity` | 被调用、适用/不适用、提出动作、实际执行、回退及覆盖原因 |
| `feedback` | 允许使用的反馈方法、标签数量、歧义与适用版本 |
| `experience` | 检索到的正负实验、回归、机制活动与原始证据引用 |
| `research_history` | 当前 R 的提案、执行、缺陷与费用，供 M7 定位研究问题 |
| `budget` | 剩余候选、轮次、分支、训练、模型调用、时间与费用 |

框架按允许字段生成序列化 Context；现有 Workspace 包含 runtime 引用，不能直接作为隔离完成的证明。未来允许策略代码或研究工具时，文件和网络访问范围必须与声明一致。test 内容、结果和轨迹不进入研究输入。

原始记录不改写；经验摘要与索引另存版本。检索首先采用问题标签、owner、策略版本和适用条件过滤，按需读取原始轨迹。材料相同不等于任务独立；同任务及分支保持同一数据组。

每轮把“预期改变什么”与“实际改变什么”对照：

- 未调用或输入缺失：先定位接线/可达性，不继续堆训练。
- 调用了但没有改变默认动作：记录覆盖和适用性，不将触发当成收益。
- 改变动作且任务变好：保存证据和适用条件，不直接推断因果普遍成立。
- 修复目标问题却损害原成功任务：下一次提案必须看到回归轨迹。
- 环境或下游策略变化：重验旧标签和经验，不把旧结论永久生效。

## 4. Worker 候选的执行

M5 使用固定 R0。框架执行：检查 → 构建/可选训练 → 少量机制与回归检查 → 预定完整 dev 比较 → 固定裁决 → 隔离装配 → 更新 W。

prompt、规则与小模型共享策略身份和运行证据；未知类型没有评测器就拒绝。候选程序错误是候选缺陷；基础设施故障单独处理，不由研究员自行选择性删除失败。

最终按开发协议锁定 W；test 由独立评测入口执行，不参与继续研究。当前完成度探针只在 train 运行，按每次决策快照离线标注；它证明能得到完成状态标签，不证明是否继续一定有用。

## 5. 研究策略自己的改进

### 5.1 可修改的对象

M7 开放 R 的有限策略目标，先选择一个有实验证据的瓶颈：

| 目标 | 允许的改动 | 不能改动 |
|---|---|---|
| `research.diagnose` | 诊断 prompt、行为缺口提取步骤 | 伪造观测或把解释当真值 |
| `research.retrieve` | 经验过滤、排序和呈现 | 原始记录、split 归属、隐藏结果访问 |
| `research.propose` | 候选生成流程、优先顺序 | 已登记动作空间之外的权限或无限模型扩张 |
| `research.preflight` | 加载、输入充分性或重复实验的辅助检查 | 正式评分器、晋升标准、总预算与最终测试协议 |

基础研究模型保持固定。首个 research 候选只允许 prompt 或已注册的声明式规则/工作流配置，无需创建第二个训练模型。生成策略代码需要后续独立隔离能力；首版不执行。R 的变化必须绑定到实际研究步骤的调用，不能只替换 manifest 中的版本名。

一个合理的递归实例：多轮实验显示研究员没有发现决策输入遗漏任务要求，R0 提议增加有依据的输入检查与诊断步骤；固定比较显示 R1 改善后续实验产出；安装 R1，由它产生下一轮 worker 候选。它的价值来自后续结果，不来自“检查多了一层”。

### 5.2 谁评估改进者

现任 R 可以提出 R'，但不能自评、自安装。固定 K 调用 `research/campaign.py`，从相同 W、经验快照、任务池和预算派生两个隔离改进过程。每支内部用自己的固定 R 改 W，不能继续改 R；新经验不跨支传播。

每支用内层 train/dev 选择 W，外层保留任务评价该 W。用于选择 R 的外层结果属于研究开发证据，不能再作为最终独立结论。数据分组、独立 campaigns、重复次数与最终冻结按 DESIGN §6.2；已经看过的业务 test 不重用于后续 R 优化的独立证明。

正式比较的是：

- 同研究预算下最终 W 的任务表现；
- 或达到预先规定任务质量所需的全部研究成本。

无效实验、分支、训练和内外评测均计费；达不到目标的运行保留。接受率、提案数、LLM 自评分不能替代上述指标。

### 5.3 何时闭合递归

R' 通过固定裁决及加载检查后，在下一研究轮替换 R；当轮仍保持旧版本。记录产生 R' 的研究员、对照、裁决、安装和 R' 后续产生的候选，形成明确的回用链。

研究策略变更失败时恢复上一套完整版本。预算不足以验证 R' 时只保存提案。人工输入候选可测试接线；自动递归案例要求候选确实由系统从经验中提出。

工程验收是“提出—评测—安装—回用”可执行；C4 是后续独立研究比较获得支持。两者分别报告。

## 6. 预算、停止与不扩张

一个框架预算覆盖任务改进与研究改进，包括嵌套评测；每层不重新领一份无限预算。达到上限、预定无收益耐心耗尽、无可执行提案或连续基础设施失败时停止。

默认每轮一个候选、一个业务决策点、一个可训练模型。M7 初期只开放一个研究目标；研究评测期间禁止自修改，不扩无限元研究层。不因为“完整 RSI”增加多层 agent、专家池、独立记忆服务或实时控制台。

## 7. 验收

- M2/M3：行为缺口与训练信号有实际证据，输入与离线真值分开。
- M4：策略能替换、实际影响行为、按完整任务比较并整体安装或回退。
- M5：至少两个相连改进轮次，后续提案使用前轮事实与经验；R 身份固定且可追溯。
- M7：至少一条系统提出的研究改动经验证并进入下一轮研究的完整链；C4 效果另由独立比较支持。

业务收益、训练收益、研究收益都可能未被证实。遇到负结果应改假设或保留简单方案，不靠扩大模型数量补叙事。
