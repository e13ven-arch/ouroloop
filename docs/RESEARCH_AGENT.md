# 改进函数与递归回用（v0.6）

> “研究员”保留为逻辑职责，不新增独立研究服务或训练研究专用模型。自动发现、实验选择和经过验证的策略回用是首版核心；人不承担每轮准备优化工作流与训练配方的工作。

## 1. 输入与职责

用户提供任务环境、目标、工具/权限、初始模型、资源和预算。框架提供 bootstrap runtime、R0 默认策略及有限配方。R 读取授权的任务反馈和实验记录，诊断失败，提出工作流/模型/决策候选；固定代码检查、执行、评分和决定安装。

首版 R 读取 train/fit 失败摘要（逐轮动作、工具错误、终止原因、实际工具/hook/技能事件）与断言明细（type/params/passed）、包内文件和固定 API；dev 只给汇总，final 不进入，dev/final 都不给断言明细和轨迹（M0 §4、M4 §1）。R 产出受限工具/中间件代码及技能/经验 patch；代码由固定流程隔离检查和执行，不直接修改仓库。第二版 R 可与 teacher 共用 provider，但输入权限/协议/成本分开，teacher 只纠正采集下一步；两者都不能自定环境得分。

## 2. 每轮怎样自动推进

复用 `run_worker_round` 的 context（train/fit 失败摘要与断言明细）→ 逐题笔记（research.diagnose）→ 汇总 propose（research.propose）→ 冻结前草稿检查/有界修订 → admission → freeze → execute → experience。默认每轮至多一个候选或一批受限补采，有限轮数和耐心。无 proposal 且请求 collect 时自动采集并重建 context；无方法、补采无进展/额度耗尽或缺必要能力才结束当前 worker 段，不能把所有空提案统一当停止。

首版从失败摘要经逐题笔记→汇总形成至多一个包内 patch，应用到新副本形成草稿包；冻结前做草稿检查（含代码时 package_check → isolated_probe → package_test，只含 skills/memory 时只查结构/路径/manifest），失败时 R 只见检查输出，在 preset/K 固定次数内修订，通过才冻结，用尽则本轮以无效提案结束；再执行同 actor 的正式 deployment gate，在完整固定 dev 清单上比较当前版本与候选，包含对照版本本次成功的任务；按整体收益与退化比例的冻结门槛采用新包。下一轮以已采用包为起点；不要求 source_validation/teacher/trainer。修改固定宿主 API 或权限不属于包演化；真正切换获准宿主才走新起点/基线准备。

第二版保留 source_validation → 教学适配 → 学生采集/SFT → 无教师验证的链路；教学源无需先过生产 gate，直接发布仍需完整 gate。controller 新训练仍需状态真值。两版都复用相同执行器/预算/发布，材料来源不能跨分区洗白。

train 材料构造使用单独的受限上下文；dev 只用于选择和诊断的允许投影。失败的候选与费用保留，下一轮不得无条件重试相同实验。实现细节、准入和用例见 [M4](modules/04_RESEARCH_LOOP.md)。

## 3. 为什么还需要 R 的更新

如果系统只更新业务 W，随后仍以相同方法提出所有改进，就只能证明业务迭代。首版利用已有 R0/R1 campaign 检验改进方法：相同 W0/E0、相同资源和允许方法，比较两支实际产生的 W*，通过后安装 R1，并在下一次真实诊断/提案调用中加载它。

首版只开放诊断与提案两段提示，具体改哪段由实验结果决定；检索规则与辅助预检保留注册，首版不作为候选，等真实结果显示需要时再接入（[DESIGN §7](DESIGN.md)）。不把某一个 prompt 当作 RSI 的全部。首版不要求研究权重训练或让 R 修改评分器。改变的策略、下游结果及实际回用引用均记录；见 [M6](modules/06_RESEARCH_CAMPAIGN.md)。

## 4. 交付边界

首版必须实现自动包代码/材料演化、实验反馈、应用发布、R 候选比较与实际回用；训练完善归第二版。人工入口/scripted fixture 只用于工程验证，不能代替真实自动提案证据；C1 不自动证明 C4，R1 不通过就保留 R0。

暂不开发独立研究 UI、常驻服务、多专家调度、研究员专用模型训练或无限递归 campaign。首版的 campaign 内禁用 research slots，只有一层方法比较；所有请求共用活动预算根。
