# v0.5 agent 内 RL：不训练权重，RL 在 RSI 里怎么发生、怎么生效（2026-10-06）

> 设计稿，待批准。用户方向（2026-10-06）：不训练模型时，能调的是提示、工具和工作流；但算法本身也是 agent 的工具，让 agent 具备 RL 的能力同样算数。要设计的是：在实际的 RSI 过程里，这个 RL 怎么发生，又怎么生效。
> 先文档后执行：本文只写设计。实现与任何付费阶段，都排在 v0.4 finance 活动（三轮加封存 final）结束并提交之后。本文与 [V0_5_METHOD_LIBRARY.md](V0_5_METHOD_LIBRARY.md)（方法库；它 §3 的选择表就是本文 RL 层的第一个实例）、[V0_5_EVOLVING_SEARCH.md](V0_5_EVOLVING_SEARCH.md)（框架层进化搜索）之间的接口写在 §7.1 和 §8。三份文档对齐之后才写代码。
> 依据：finance W0 的 train 读数与轨迹（`workspace-claude-v4-finance`；dev 只用汇总和逐题的稳定性），v3 五领域里三个候选的逐领域翻转，v0.4 finance 第 1 轮的三个候选及其筛选，[V0_4_PLAN](V0_4_PLAN.md)，[五领域诊断](../history/DIAGNOSIS_FIVE_DOMAIN_2026-10-06.md)。三份候选设计（上下文老虎机 OAB、决策点价值学习 DPV、进化的路由程序）先做了一轮对照仿真，共 82,080 次运行；本稿又追加了四类混合形式和探针的仿真，约 46,000 次运行（§6.7、§6.8）。没有调用模型，没有付费阶段，没有读 test。

## 0. 结论先行

**RL 落在哪里。** 包里有两样东西：

1. **选项集**，即结构，由 R 写。一个选项就是在某个决策点上的另一种做法，例如：
   - 写入之前先核对一次，或者不核对；
   - 遇到 401 时换一个服务，或者停下来报告；
   - 结束之前做一次自查，或者不做。
2. **策略表**，即参数，由固定代码从 train 奖励拟合。它给每个（选项，决策点，情境格）一个动作：开或关。

决策点有四个：开始、第一次写入、第一次 API 错误、结束。agent 在每个决策点第一次出现时查表。这张表就是 π(选项 | 情境)，它从奖励里学出来。这就是不训练权重的 RL：参数在表里，不在权重里。

**RL 怎么发生。** 只在 train 上发生：
- 一次 learn 读数把每道 train 题跑两遍（对偶孪生）。每个开关在其中一遍开、另一遍关，不同开关的开关顺序彼此独立。
- 判分器的逐断言结果就是奖励。
- 配对差按题记功，用 Beta 后验表示，再按一条冻结规则定动作。
- 一次读数约 $47～50。

**RL 怎么生效。**
- 拟合结果冻结成贪心表，作为一次包改动（精修候选），走 v0.4 的筛选和 gate。
- dev/test 只见到 `mode = "greedy"` 的表，dev/test 的结果不回流。
- 装上以后，W\* 的表就是下一轮的默认动作。

**仿真的结论。** 这一段必须先读。下表是 $600 预算下、相对 v0.4 贪心环的真实增益差（pp，按 finance 标定）：

| 形式 | 单领域基准世界 | 无情境效应（het 0）| 有利世界（强烈的“这里帮、那里伤”，特征完美）| 坏安装 P(false gain) |
|---|---|---|---|---|
| 三种完整设计（OAB / DPV / 路由），自付探索 | −2.1 ～ −3.2 | −2.9 ～ −4.9 | +0.8 ～ +2.3 | 0～3%（贪心 3～12%）|
| 本稿的混合形式，自付探索（§6.7）| −0.4 ～ −1.9 | −0.1 ～ −3.3 | −0.3 ～ +1.1 | 3～6% |
| **搭方法库 learn 读数的车，1～2 次（本稿推荐）** | **−0.4 ～ +0.3** | **−0.2 ～ −0.1** | **−0.1 ～ +0.6** | **4%（贪心 6%）** |

差值的标准误约 0.3～0.37。

- **为什么贪心赢。** 瓶颈不在学习器，而在两处：
  - 25 题的 dev gate：真实增益在 +4～+8 pp 之间的候选，也只有约一半被接受；
  - R 写出的选项的质量。

  每 $600，贪心环有 11 次 gate 机会，各种 RL 形式只有 2～8 次。RL 候选每次的质量约高一倍，抵不过次数少 1.5～6 倍。还有一点：贪心的筛选只跑 R 预测会被修好的那几道题。随机分配要把一半的钱花在这个选项无事可做的题上。
- **贪心不能替代的一点：containment（收住伤害）。** RL 的坏安装更少。它的价值取决于真实任务里有多少“这里帮、那里伤”的选项。这一点只有一个真实数据点，而且 §6.8 表明：单领域的 50 道 train 题，分不出我们处在哪种世界。

**推荐：一条路。**
- v0.5 把 RL 做成与方法库共用的一层：同一个 learn 读数、同一个估计器、同一张表、同一种标记。
- 把开关从“方法”推广到每个已装组件，再加上至多 4 个近失候选。
- **不另设探索预算。**
- 学到的表经现有的候选路径生效。预计增益低于 gate 的分辨率时，不单独付 gate，并入下一轮最好的候选。
- 完整的 agent 内 RL 推迟：RL 取代筛选、DPV 的快照分支、Thompson 在线探索都在此列。等 finance 和 support 的 learn 读数显示出真实的情境差异，再由用户决定。

**保留、推迟、删：**

| 部件 | 决定 | 原因 |
|---|---|---|
| 选项与策略表的格式；已装组件转成开关，全开时与原包逐字节相同 | 保留，S0 | 零成本；这是 RL 在包里的落点，也是收住伤害的前提 |

| 改进器层对 R 变异类型的老虎机 | 推迟 | 仿真里每一格都是负的（−0.3 ～ −1.1 pp）；每次 run 只装 0～1.5 次，没有奖励信号 |
| 包内 Thompson 探索、fold 切分、TD 价值、每轮多决策、按领域合并非方法选项、测试时在线学习 | 删 | §10 |

**预期。**
- 单领域：相对贪心 +0～+0.5 pp（仿真），坏安装少约 1/4。
- 真实的增益取决于 finance 和 support 的 learn 读数里，有没有“这里帮、那里伤”的选项。目前只有一个真实的格：source_memory 在点名会计 app 的 6 道 dev 题上修 0/5、坏 1/1，在其余 19 道上净 +4。这是设计阶段的标定，不进任何环路。

## 1. 不训练权重时，RL 落在哪里

### 1.1 “算法是 agent 的工具”的两种读法

| 读法 | 什么时候跑 | 奖励从哪来 | 结论 |
|---|---|---|---|
| 任务内：actor 在一道题里调用一个学习算法 | 回合内 | 没有。判分在回合结束之后；dev/test 的分数也不能回给 agent | 不成立。回合内能用的是确定性的方法（方法库），不是学习算法 |
| 跨任务：算法在 train 回合之间改进 agent 的策略，结果作为包的一部分交给 agent | 批与批之间 | train 判分器的逐断言结果 | 本设计 |

所以 agent 在 test 时用到的“工具”，是学出来的表，以及表所调度的选项。算法本身是固定的宿主代码。

原因：
- 学到的部分不能被 actor 或 R 的叙述左右；
- test 必须面对一个固定的策略，否则留出的证据就不成立。

### 1.2 选项集

一个选项由这些字段组成：`id`、位点、载体、文字或代码、触发、`meant_for`（R 写给人看的用途）、`not_when`。

| 位点 | 何时决策 | 载体与动作 | finance train W0：触发 / 50 | 触发时 W0 通过 | support train W0（v3）|
|---|---|---|---|---|---|
| `start` | 第一次 act 之前 | 文字：系统提示里的一段；工具：列出与否 | 50 | 25/50 | 50/50 |
| `first_write` | 第一次 POST/PUT/PATCH/DELETE 之前 | before_tool：`block_once`。这次写入不执行，返回 “Stopped before execution: <文字>”，本回合余下的调用跳过（与今天 hook 的 block 相同）| 49 | — | 50/50 |
| `api_error` | 第一个 4xx 结果之后 | after_tool：一条反馈 | 26（其中 401 有 21，Xero 14、QuickBooks 9、Airtable 6、Wave 3）| 11/26（401：9/21）| 9/50（401：4/50）|
| `finish` | 第一次请求结束、且还有 act 次数时 | on_finish：一次追问，计入 `MAX_PUSHBACKS = 2` | 50（最终消息带推迟措辞的 18）| 带推迟 6/18，不带 19/32 | 带推迟 18/50 |

规则：

1. **每个位点在一次尝试里只在第一次出现时决策一次。**
   - 原因：一次尝试里同一位点的后续出现，与第一次的情境高度相关；按回合决策会把格数乘上去，但没有更多的题来撑。
2. **默认动作就是 W\* 现在的行为。**
   - 原因：比较的对象始终是现行冠军。偏离要靠证据（安全策略改进，SPIBB 式）。
3. **上限：** 每个位点至多 3 个选项加默认；方法以外的开关合计至多 8 个；方法的上限照方法库。
   - 原因：开关越多，配对差里来自其他开关的噪声越大。8 个与 OAB 设计的上限相同；本稿的仿真每次读数用到 6 个。
4. **已装组件转成开关。**
   - memory.md 的每一段 → `start` 位点的文字选项；
   - R 的 hook → 同位点的 hook 选项，表说关时就不调用它；
   - 包工具 → `start` 位点的工具选项（列出与否）；
   - 方法 → 照方法库。

   转换由固定代码完成：在 memory.md 里加段标记，在 manifest 里加选项条目。
   - 原因：v0.4 装上的 source_memory 是一段 memory 文字；不转成开关，它在会计 app 那一格里的伤害就收不住。
   - **全开表 = 原包**：系统提示与工具列表逐字节相同，由测试保证（§8）。

### 1.3 策略表

```
TABLE = {"schema": "ouroloop.option_table.v1", "mode": "greedy",
         "cells": {"source_survey|start|names_accounting_app=1": {"action": "off"},
                   "source_survey|start|names_accounting_app=0": {"action": "on"},
                   "svc_switch|api_error|*": {"action": "on"},
                   "send_review|first_write|write_is_send=1": {"action": "on"},
                   "send_review|first_write|write_is_send=0": {"action": "off"}},
         "learner": {"code_ref": "...", "k_ref": "...", "runs": ["..."], "tasks": 50, "episodes": 100}}
```

- **格的键：** `选项 | 位点 | 一个分桶特征的取值`，或者 `*`（不切）。
- **动作：** `on` 或 `off`。方法另有变体，照方法库 §3.1。
- **`mode`：** `greedy` 或 `explore`。只有 learn 阶段的孪生包是 `explore`（§2.1）。
- **只有固定代码写这张表。** 宿主和路由用 `ast.literal_eval` 读它，从不 import。

原因：表是从奖励拟合出来的统计量；如果 R 能写，学到的那部分就会被 R 的叙述左右（方法库 §2.5 同理）。

### 1.4 情境特征

- **只用 agent 观察得到的东西：** 题目文本、它已经发出的调用和收到的结果（端点、状态码类别）、计数、最终消息。不加任何工具调用或模型调用。
- **固定的语法：**
  - 题目文本上的正则；
  - 端点或错误类别；
  - 计数阈值，例如 `writes ≥ 3`。

  特征都是二值的，以数据形式存在，不是代码。
- **每个选项至多一个分桶特征**，由 R 提议。只有两边各有 ≥5 道触发题，并且两边按冻结规则得出的动作不同，才保留这次切分（与方法库 §3.5 相同）。

原因：
- 50 道 train 题撑不起两个以上的特征；只出现在 1～4 道题上的特征，等于换了个名字的题号。
- 方法库 §1.5 显示，题目关键词和简单的状态特征只能把失败率拉开约 ±0.1。真实的特征是弱的，格不能多。

### 1.5 为什么算 RL

- **它有 RL 的全部要素：**
  - 一个策略：π(选项 | 位点, 情境)；
  - 来自环境的奖励：判分器；
  - 一个从奖励更新策略的算法：后验与冻结规则；
  - 探索与利用：train 上随机化，dev/test 上贪心。

  在每个位点上，它就是一步的情境老虎机。四个位点合起来，是选项框架（Sutton, Precup & Singh 1999）里的一个高层策略：
  - 选项的起始集合 = 位点的触发；
  - 选项内部的策略 = 带着这段文字或 hook 的 LLM；
  - 选项在一次出手后终止。
- **为什么不做序列的价值学习（TD）。**
  - 一次尝试至多 4 个决策，奖励只在最后才有，抽象状态又是粗粒度、彼此混叠的；
  - 在这种条件下，自举的价值估计有偏（Singh, Jaakkola & Jordan 1994），而配对的蒙特卡洛估计无偏，也更省样本。
- **和不训练权重的 LLM 自我改进做法相比：**
  - Reflexion 是回合内的口头强化，不验证；
  - ExpeL 学到的洞见总是开着；
  - Agent Workflow Memory 与 Voyager 按相似度检索。

  本设计多出的是：**在哪里用，由按情境测得的价值决定，并在 train 之外验证。**

### 1.6 它针对的失败

| 证据 | 数 | 含义 |
|---|---|---|
| v0.3 的三个 gate 候选，逐领域的修复 / 退步 | marketing +3/0、+6/0、+5/−1；sales +2/−3、+2/−6、+1/−3 | 跨领域的“这里帮、那里伤”。v0.4 已经用“一个领域一个活动”在结构上消掉了它 |
| source_memory（v0.4 finance 第 1 轮，已装）在 dev 上 | 点名会计 app 的 6 道：修 0/5、坏 1/1；其余 19 道：净 +4 | 领域内的情境差异，n = 6 |
| send_review（第 1 轮，未装）的 train 筛选 | 修 3 道，在 6 道通过样本里坏 2 道 | 宽泛的核对，可能只在一部分格里有利 |
| 方法库 §1：系统日期这个选择 | 对 wave_client_statement 是对的，对 ap_aging_report 是错的 | 同一个选项在不同题族里对错相反 |

设计的要点是：这样的规则不再是“全装或全拒”，而成为选项，它的适用处按格学出来。

## 2. RL 怎么发生（只在 train）

### 2.1 learn 读数：对偶孪生

- **孪生包。** 固定代码给当前的 W\* 造两个孪生包 A 和 B，它们只在表上不同：`mode = "explore"`，带一个盐值 s（由 (`order_seed`, 阶段) 定）和孪生标签。
- **分配。** 对每个开关 d，u = H(s, 任务文本, d) ∈ {0, 1}。A 取 u，B 取 1 − u。每道 train 题在 A、B 下各跑一次，50 道题共 100 次尝试。
  - 每个开关在每道题上恰好开一次、关一次；
  - 不同开关的符号相互独立（因子设计）；
  - 倾向值精确是 0.5。
- **决策标记。** 每次决策打一个 `option_decision` 标记，字段包括：选项、位点、格、动作、倾向值、触发回合、表的摘要、模式。标记种类不在 `MARK_KINDS` 里时，今天的宿主也会把它记作 `package_mark`。

原因：
- **目标是冻结后的策略好不好，不是 train 上的累计奖励**（纯探索，Bubeck, Munos & Stoltz 2009）。
  - 在 n = 25～50 时，Thompson、top-two Thompson 与平衡分配的结果相同（OAB 设计的仿真）；
  - 平衡分配还多两样东西：精确的倾向值，以及每道题上的开/关配对。
- **配对能消掉题与题之间的差异。** 题间方差（二值 0.25、shaped 0.13）几乎就是 finance 里方差的全部：dev 上 25 道题有 24 道在四次读数里结论一致。
- **按任务文本做哈希，包看不到题号**，分配却确定、可复现，也不用往 view 里传种子（方法库 §3.3）。

### 2.2 哪些东西是开关

- **W\* 里每个已装组件**（§1.2 第 4 条）。
- **方法库的方法。**
- **至多 4 个近失候选：** 在本活动里筛选过、修好 ≥1 道题、却没装上的候选，取最近的。包括 gate 拒掉的，也包括因样本退步超过 1 而不合格的（send_review 修 3 坏 2 就属于这一类：退步上限正是分格可能解决的问题）。它们以 `off` 为默认进入孪生。仿真里的近失候选只取合格的那些。

原因：
- 近失候选正是可能“这里帮、那里伤”的那一类。v0.4 只给它们一次全有或全无的机会；在孪生里，它们多一个分格的机会，而且不多花钱，因为孪生对所有开关同时随机化。
- 近失候选的修复带有样本内的膨胀：它们的修复题是 R 读过的。所以它们只能通过 gate 生效，不能直接写进 W\*（§3.2）。

### 2.3 奖励

每道题、每个孪生，从 grading 行里记下：
- **断言类得分**：选项声明了 `footprint` 时，取这些断言类里未排除断言的通过比例；没有声明时，footprint 就是全部断言；
- **题级成败** r_task ∈ {0, 1}；
- **“不得做”记账**：一条 `_not_` 断言在开的那一遍失败、在关的那一遍通过，就记在这个选项的这一格上。

原因：
- 失败的 finance train 题里，12/25 只差一条断言。按断言记功能看到“只修好一半”的选项；
- 题级成败另记，保证 gate 读的仍是成败；
- “不得做”记账防止“写得越多部分分越高”的钻空子：失败断言里有 13 条是“不得做”。

参照数（v3 与 v4 两次 W0 finance train 读数，每题差值的方差）：二值 0.118，shaped 0.067，部分分 0.041。断言级的信号把噪声压到二值的一半左右。

### 2.4 功劳分配

- 对格 c 里触发过的每道题，比较开的一遍和关的一遍：
  - k_c 是得分上升的题数，m_c 是下降的题数，持平的题丢掉；
  - 题级的修复数和退步数另外计。
- **按题聚类，不按回合。** W0 下一次尝试的结果近似是题的函数，所以一道题上的一次配对，就是一条事实。
- **不做启发式的切分。** 一个回合里几个开关的功劳，靠独立随机化来区分：每个开关的效应在加性模型下可以识别，其他开关的效应在配对差里只表现为噪声。
- **互补的选项**（例如 LEDGER → SCRUB）用方法库的 `couples_with` 作为一个组合开关来随机化。

原因：在 W0 下题是确定性的，按回合计会把一个事实数成几个（OAB 的仿真：按回合的后验在空选项上的部署数随轮数增长，从 1.5 涨到 4.3 道 dev 题；按题聚类时稳定在 0.3～0.7）。

### 2.5 更新与冻结规则（与方法库 §3.5 是同一条）

- **后验。** p_c ~ Beta(1 + k_c + ½·k′_c, 1 + m_c + ½·m′_c)。k′、m′ 是本领域在上次安装之前的计数（W\* 的底子变了，取半权）。方法另有跨领域半权；**非方法的选项不跨领域合并。**
- **转 on**，全部条件都要满足：
  - n_c ≥ 5；
  - P(p_c > ½) ≥ 0.8；
  - 题级的修复 − 退步 ≥ 0；
  - “不得做”记账 ≤ 1；
  - 触发题的平均尝试成本上升 ≤ 25%。
- **转 off**：n_c ≥ 5 且 P(p_c < ½) ≥ 0.8；或者“不得做”记账 ≥ 2。
- 其余情况保持当前动作。

原因：
- 5 道题是匿名性的底线，一格不可能编码某一道题；
- 0.8 加上“题级不为负”，在单次读数 ±7～9 个点的 dev 噪声之下仍站得住；
- 非方法选项不跨领域合并：行为类文字的符号会跨领域翻转（v3 的 rulesmem，以及仿真的两领域世界里 65% 的选项翻转）。方法是只读的证据工具，方法库 §2.9 的论证只对方法成立。

## 3. RL 怎么生效

### 3.1 冻结与贪心

三条收据（方法库 §3.7，推广到全部选项）：
1. 装配 dev/test 运行时，表不是 `mode = "greedy"` 就拒绝运行，不花一分钱；
2. dev/test 运行结束后，所有 `option_decision` 标记的倾向值都必须是 1.0，否则这次读数作废；
3. 孪生包的引用只出现在 `learn` 阶段的运行记录里。

原因：这三条靠构造和检查成立，而不是靠 agent 守规矩；agent 也分辨不出自己是不是在 dev 上。

### 3.2 精修候选怎样进入环路

- **默认做法（方法库 §3.6）：** 拟合出的表与已装的表不同时，加一个只改表的第 k+1 个候选。它的 `predicted_affected` 是格变了的那些触发题。照常筛选、gate、确认。
- **新增一条规则：**
  - 先在 learn 读数上算精修的配对净值（变了的格里修复减退步）；
  - 净值低于 gate 的分辨率（每 50 道 train 题 +2.5 题，对应 `min_gain` 0.05）时，精修不单独 gate，而是并入下一轮筛选里最好的那个候选；
  - 那个候选的筛选要加上精修变了的格里的触发题；
  - 下一轮没有候选过筛选时，精修留到再下一轮；它的证据不会过期，直到 W\* 改变为止。

原因：
- 仿真里单独 gate 的精修，每次 run 有 2.1～2.4 次，只装上 0.2 次左右（约 10%）。一格的修正多半是 +1 题量级，过不了要求 1.25 题的 gate，钱白花了。
- 并入候选不多花 gate 钱，结果相近或略好：基准世界里，1～2 次读数、自付时 −0.4～−0.6 pp，搭车时 −0.4～+0.3 pp。
- 风险是一个有害的精修跟着好候选混过 gate。这一点由三样东西挡住：
  - 冻结规则只在证据足够时才偏离冠军；
  - 合并后的筛选覆盖了精修变了的格；
  - gate 的退步上限对整个候选生效。

  §6.7 里没有看到坏安装增加：base 在 $600 时是 0.042，贪心是 0.058。

### 3.3 gate、final、下一轮

- **gate 不变：** dev 25 题，对照是冠军三次读数的合并，`min_gain` 0.05 在第一次读数、确认读数和合并读数上都要满足，加上退步上限和确认读数。
- **final 不变：** 封存的 W0 对 W\*。方法库要求的“W\* 表全开”那一臂，同时也量出本层的增量。本文不另加臂。
- **装上之后：**
  - W\* 的表成为下一轮的默认；
  - 安装前的计数取半权；
  - 下一个 learn 读数重新拟合。

### 3.4 有效性

每条后面写了原因。

1. **学习只读 train。** 学习器只接受这样的行：`split == "train"`，运行的阶段是 `learn`（孪生）或 `measure`（冠军的读数）。别的行是错误，不是跳过，有测试覆盖。原因：dev 是 gate 的面板，任何逐题的 dev 数字进了拟合，几轮之后 dev 就成了 train。
2. **dev/test 不回流。** R 和学习器能看到的 dev 信息，只有 gate 的结论。不在 dev 读数之后追加读数，不按 dev 结果挑快照。test 封存到 final。原因同上，另外还要防止可选停止。
3. **不切 fold。** learn 读数用全部 50 道 train 题。
   - 仿真：OAB 不切 fold 时 +3.81，切 fold 时 +2.92（$600）。半数的数据比它所防止的膨胀更值钱。
   - 膨胀的方向是有利于选项的。所以：
     - 收住伤害（转 off）是保守的，不受膨胀影响；
     - 救回近失候选（转 on）只能经过 gate（§3.2）。
   - 记录里有 R 读过哪些题：S0 的回放会报“R 读过的题”与“没读过的题”上的配对净值之差，用来量膨胀。
4. **不泄漏答案。**
   - 特征是固定语法下的数据，两边各需 ≥5 道题；
   - v0.4 的字面量检查覆盖选项文字、特征和表；
   - 记功报告只给计数，按格和断言类汇总，不带题号和断言参数。
5. **W0 / W\* 等价。**
   - 没有表的包，或全开的表，必须发出与原包相同的模型输入和工具调用；
   - 由离线的脚本化对话测试保证，两种放置（宿主内、worker 内）都要测。

   原因：否则 W\* 对 W0 比的是两套循环，而不是一张表。
6. **可审计。** 每个探索决策都记了精确的倾向值，所以交叉拟合的策略价值和学习曲线可以只从记录算出来（§7.5）。
7. **多重比较分层处理：** 每格 n ≥ 5 与 0.8 的门槛；“题级不为负”；精修的预测净值门槛；dev gate（空候选的误收在 3 次对照读数下是 0.2～0.4%，诊断 P3）。

## 4. R 的角色：结构由 R 写，参数由 RL 定

### 4.1 分工

| 层 | 谁 | 写什么 | 读什么 |
|---|---|---|---|
| 选项（结构）| R | 文字、hook、包工具、方法；位点；触发；`not_when`；至多一个分桶特征 | train 的笔记、轨迹、接口错误表、记功报告 |
| 表（参数）| 固定代码 | 每格的动作 | learn 记录（train）|
| 去留 | gate | 装或不装 | dev（只给一位结论）|

### 4.2 R 的输出（每轮至多 3 个改动，与 v0.4 的 k = 3 共用名额）

- 新选项：放在四个位点之一，或者是方法（照方法库）。
- 修订：修订后的选项拿新的 id，计数从先验重新开始。原因：选项改了，旧计数说的是另一个东西。
- 退役：在所有有支持的格里 P(效应 < 0) ≥ 0.9 的选项。
- 每个选项至多一个新的分桶特征，以数据形式写在固定语法里。

### 4.3 R 的新输入：记功报告

只来自 train，免费：
- (a) 每个选项 × 格：n、后验均值、80% 区间、修复数、退步数；
- (b) 每个选项 × 断言类：同一题上开与关相比，从失败翻成通过的断言数、从通过翻成失败的断言数。例如 “send_review: *_not_* +4/−0, gmail_message_sent_to_with_body_contains −3”。R 据此收窄选项，或提议一个特征（如 `write_is_send`），让表能把两种情况分开；
- (c) 未覆盖的格：W0 在至少 3 道 train 题上失败 ≥50%，却没有一个选项的 P(Δ > 0) ≥ 0.5。

### 4.4 R 不能做的事

- 写表；
- 写路由、`option_decision` 的逻辑、K；
- 看 dev 的题号、轨迹或逐题翻转；
- 把近失候选直接写进 W\*。

### 4.5 改进器层的老虎机：推迟

对 R 的变异类型（新选项、修订、新特征、退役……）做 Thompson，仿真结果在每一格都是负的：
- 基准世界在 $150 / $300 / $600 时 −0.34 / −1.07 / −1.12 pp；
- het 0 世界 −0.73 / −0.46 / −0.88 pp。

原因：每次 run 只装上 0～1.5 次，奖励几乎全是 0，老虎机只会把 R 从它对失败的阅读上引开。

现在只做记录：每轮记下变异类型和它的去向（筛选、gate、安装、格离开默认）。等跨领域有 ≥10 轮再看。

## 5. 三种形式的比较

| | 上下文老虎机（OAB）| 决策点价值学习（DPV）| 进化的路由程序（路由）|
|---|---|---|---|
| RL 落在哪 | `agent/policy.py` 里的线性后验；固定的 agent 程序 | `agent/policy_table.py`，按格经验贝叶斯 | `policy/params.json`：每个选项的门控规则 |
| 探索 | 在 fold B 的 25 题上 Thompson，ε = 0.15，每轮 3 遍 | 根轨迹 + 从快照分支，一次只改一个因子，加空分支 | 因子设计：每个选项以 0.5 的概率开 |
| 估计 | 按题聚类的高斯混合模型 | 配对差 + 经验贝叶斯 + 留一交叉验证选切分 | 双稳健估计 + 题固定效应 + 14 条假设的规则类 |
| 每轮费用（finance）| $35 探索 + R + gate | 约 $118（全部 train 题）| 约 $94 加在策略上的检查 $23 |
| 宿主改动 | 无 | 快照、续跑、view 的 `rl` 字段 | 包的模式文件、mark |
| $600 基准世界，对贪心 | −3.24 | −2.14 | −2.96 |
| $600 有利世界，对贪心 | +0.75 | +2.25 | +2.31 |
| 学习曲线 E100 / E400（无 gate，pp）| +0.99 / +1.40 | +2.59 / +3.55 | +2.57 / +3.44 |
| 主要弱点 | 只有 25 道 fold B 题；情境模型输给它自己的全局消融（+2.92 对 +5.23）| 每美元效率最好，但要改可信宿主，CLI 的续跑保真度没验证 | 每轮花钱多、gate 少（1.9 次 / $600）|

学习曲线的参照：最好的单个全开选项 +3.79，最好的全开子集 +4.87，逐格 oracle +6.74。

**本稿用的形式**是方法库式的对偶孪生，加 Beta 冻结规则（§2）。它是三者的公约数：
- 因子随机化（路由）；
- 配对（DPV）；
- 冻结成贪心表（OAB）。

它的实现最小，并且与方法库共用。DPV 的分支是降低成本的手段，推迟到“值得付钱探索”被真实数据证明之后。OAB 的 Thompson 和 fold 切分删去（§10）。

### 6.1 模型

- **任务。** 55% 的题有 1～3 个失败原因：src、send、over、fin、iface、hard。原因的流行度随两个潜在情境因子变化：A 的流行度 0.3，B 为 0.5。观察到的特征以 0.9 的准确率反映这两个因子，另有两个无关特征。

### 6.4 为什么贪心赢

| $600 | 每次 run 的 gate 次数 | 进 gate 的候选的真实增益 | 接受率 |
|---|---|---|---|
| 贪心 | 11.2 | +1.8 pp | 13% |
| DPV | 3.0 | +3.7 pp | 25% |
| 路由 | 1.9 | +4.1 pp | 26% |

- **gate 是瓶颈。** RL 的候选约好一倍，但贪心在这个功效很低的 gate 上多拿 4～6 次机会。
- **贪心的筛选是定向的。** 它把 R 预测会修好的 3～9 道题全跑一遍（预测的召回率 0.85）。随机分配下，每个选项只在约一半的题上开着；它要修的那类失败，开着的只有 2～5 道。§6.7 里“RL 取代筛选”这个形式，费用比贪心的筛选还低，结果仍然 −1.9，原因就在这里。
- **学习曲线是上升的，但不是没有天花板。** 即使到 E400，学习器在基准世界里仍低于最好的全开子集（+4.87）。冻结规则只在证据足够时才偏离默认；50 道题撑不起足够的证据。

没有情境效应时，学“在哪里用”什么也不添：E = 200 时 DPV +2.62，它的全局版 +2.64。

### 6.6 有利世界与两领域世界

**有利世界。** 强烈的“这里帮、那里伤”，特征完美，15% 无用。这个世界没有按记录标定，是作为情境 RL 的上限搭的。

| 预算 | 贪心 | DPV | 路由 | OAB |
|---|---|---|---|---|
| $300 | +2.19（坏安装 0.092）| +2.63 | +2.81 | +2.47 |
| $600 | +3.48（坏安装 0.117；P(损失 > 1 pp) 0.07）| **+5.73**（0.004）| **+5.79**（0）| +4.23 |

在这个世界里，全局版只有 +0.9～+2.7。

**两领域世界**（领域之间效应冲突）：

| 方法 | $300 | $600 | $1200 |
|---|---|---|---|
| 贪心，一个共用的包 | +2.20 | +3.84 | +5.72 |
| **贪心，每领域一个活动（v0.4）** | **+9.01** | **+17.22** | **+24.07** |
| OAB，合并并加一个领域特征 | +3.04 | +6.94 | +10.76 |
| DPV，合并 | +3.35 | +6.70 | +11.02 |
| 路由，合并 | +3.11 | +5.36 | +9.52 |

读法：
- 情境就是领域时，学“在哪里用”确实有效：合并的 RL 比一个共用的包高 3～5 pp。
- 但事先按领域划开不花学习的钱，结果远好于学出来。所以本层不把非方法选项跨领域合并（§2.5）。

### 6.7 本稿追加：四类混合形式

问题是：能不能让 RL 不跟贪心抢 gate？数字是 $600 时相对贪心的配对差（pp），标准误约 0.3～0.37。

| 形式 | 做法 | 基准世界 | het 0 | 有利世界 |
|---|---|---|---|---|
| 独立精修 | 贪心之外，自付 learn 读数；精修单独 gate | −1.10 | −1.21 | +0.01 |
| 只收伤害 | 同上，只把已装组件的有害格转 off | −0.45 | −0.08 | −0.30 |
| RL 取代筛选 | 每轮一次对偶孪生读数，代替逐候选的筛选；候选 = 各选项按格部署 | −1.86 | −3.04 | **+1.09** |
| 先贪心 $150，再探针，再条件切换 | 探针触发就改用 RL 筛选，否则继续贪心 | −1.23 | −1.90 | −0.11 |
| 精修随候选进 gate，自付 2 次读数 | §3.2 的规则 | −0.37 | −0.55 | +0.39 |
| **精修随候选进 gate，搭车 2 次读数** | 读数由方法库支付 | **+0.26** | **−0.24** | **+0.57** |
| 同上，搭车读数不限次数（约 7.8 次）| 上限参照 | +0.60 | −0.15 | +1.27 |

坏安装（基准世界，$600）：贪心 0.058，搭车 2 次 0.042，自付 2 次 0.046。$300 时，搭车 2 次在基准世界里是 +0.44，自付 2 次是 −0.51。

读法：
- 凡是自付探索的形式，在标定的世界里都输。
- 搭车形式的边际收益在噪声之内（−0.4～+0.6）。它之所以值得做，靠的是三样东西：
  - 坏安装更少；
  - 记功报告让 R 改得更准（模拟里没有建模这一点）；
  - 它给出第一份真实的情境差异测量（§7.8）。
- 只收伤害几乎不触发：每次 run 0.03～0.19 次精修 gate。原因是 gate 已经挡住了大多数有害的候选；已装组件里，50 道 train 题上很少能看出有把握的有害格。

### 6.8 能不能先测出我们处在哪种世界

想法：先用一次 $47 的探针读数，测“情境差异”，再决定要不要开 RL。结论是不能。

| 统计量 | het 0 | het 0.5 | 基准世界 | 有利世界 |
|---|---|---|---|---|
| 符号翻转统计 ≥ 1.28 的比例（一次读数）| 0.32 | 0.34 | 0.33 | 0.46 |
| 统计量触发时 / 不触发时，切到 RL 筛选的收益 | −2.19 / −1.87 | −2.33 / −2.22 | −1.55 / −0.79 | +1.16 / +0.68 |
| 交叉拟合的“情境减全局”价值 ≥ 2 题/50（1 / 2 / 3 次读数）| 0.57 / 0.57 / 0.63 | 0.54 / 0.62 / 0.66 | 0.57 / 0.60 / 0.62 | 0.54 / 0.61 / 0.72 |

- 在世界内部，统计量预测不了“切过去值不值”；在世界之间，它的分布几乎重叠。
- 50 道 train 题、1～3 次读数，分辨不出有利世界和基准世界。按探针切换的策略，在基准世界里 −0.5，在有利世界里 +0.5。
- 所以“要不要做完整的 agent RL”不能靠一次便宜的探针自动决定。只能靠两领域积累的 learn 读数（§7.8），由用户判断。

### 6.9 RL 不起作用的情形

- **情境效应弱或没有，或者特征有噪声。** 情境学习器打平甚至输给它自己的全局版。
- **选项集固定。** 对同一批选项多探索，赢不了 R 每轮写新选项：选项固定时，$600 下 OAB +0.72、DPV +2.27、路由 +2.33；R 每轮写新选项时是 +2.9～+4.0。RL 的价值被 R 的选项供给封顶。
- **小预算（$150）。** 探索加 gate 之后，只剩大约一次 gate 机会。
- **事先已知的情境，例如领域。** 按结构划开胜过学。
- **改进器层的老虎机。** 每一格都是负的。
- **在 25 题的 gate 之下逐格精修。** 一格的修正多半是 +1 题量级，单独过不了 gate（§3.2）。

### 6.10 局限

- 领域内情境差异有多大，只建立在一个数据点上（会计格，n = 6）和 v3 的跨领域翻转上。基准世界的 +8.2 / −3.6 pp 是选定的。
- 膨胀被低估了：模拟 0.26，记录 0.27～0.69。膨胀更大时，贪心的筛选与不切 fold 的学习器都更吃亏。
- 效应被简化了：每个选项对每道题的效应固定；交互只有“任何一次弄坏就失败”和“修好全部原因才算修好”；触发按题固定，所以情境不随策略变化。
- R 对所有方法用同一个按频率瞄准的规则。“记功报告让 R 瞄得更准”没有建模，这对 RL 不利。
- 三种设计的环路是对设计文档的复现：DPV 的 top-two 分配、OAB 给 fold A 轨迹打格标签、路由的 R 轮次时机都没建模。
- 精修采用的是 DPV 的经验贝叶斯估计器（z = 1.28），不是 §2.5 的 Beta 规则。S0 会用实测参数和共用的估计器重跑。

## 9. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 真实世界不是有利的那种 | 最可能的结局：没有一格离开默认，或者离开了却过不了 gate | 不另设探索预算；预注册“否定”的读法；两领域之后由用户决定 |
| 模拟的情境差异是假设的 | 只有一个真实的格（n = 6）| S1 和 S2 的 learn 读数就是第一份真实测量；S0 用实测参数重跑 |
| 精修跟着好候选混过 gate | 并入降低了归因的清晰度 | 冻结规则只在证据足够时偏离；合并后的筛选覆盖变了的格；退步上限；报告把精修与候选分开列 |
| 近失候选的膨胀 | 它们的修复题是 R 读过的 | 只能经 gate 生效；S1 量 R 读过与没读过的差 |
| 情境是内生的 | 前面的选项会改变后面的位点是否触发（例如 `start` 的选项避开了 401）| 加性模型估计的是探索分布下的效应；收据里的触发率与回放相差超过 ±20% 时报告 |
| 位点之间的交互 | 核对与结束自查都推向“克制” | `couples_with`；记功报告的断言画像把它暴露给 R |
| 特征有噪声 | 推迟措辞在两次 W0 读数里只有 36/50 题一致（401 是 45/50）| 只用一个分桶特征；每边 ≥5 题；噪声大的特征自然不离开默认 |
| `start` 位点的宿主改动 | 组系统提示属于可信宿主，影响所有活动的身份 | 只在新的 bootstrap 里生效；全开等于原包的逐字节测试；不在付费运行期间合入 |
| worker 放置 | 带代码的包在 docker worker 里跑；W0 在宿主内跑 | 等价测试在两种放置里都做；身份按 K 钉住 |
| 证据过期 | 换了模型身份、effort 或工具集，后验就说的是另一个 actor | 后验随 W0 的身份和 K 钉住；W\* 变了，计数取半权 |
| 实现错误不显形 | 倾向值或标记的 bug 会悄悄污染学习 | 收据检查、拒绝测试、可重算的表，都排在付费之前（先文档后执行）|
| 与方法库冲突 | 估计器、名字、精修的进入方式 | 估计器、阶段、收据全部沿用方法库；只提一条修订（§7.1），对齐之后才写代码 |
| 范围膨胀 | 改进器层的老虎机、R 加位点、每回合决策、测试时随机策略 | 全部推迟或删去（§10）|

## 10. 考虑过、不做

| 做法 | 不做的原因 |
|---|---|
| 把 agent RL 做成主引擎，取代 v0.4 贪心环（OAB / DPV / 路由按原设计）| 标定的单领域世界里，$600 时输 2.1～3.2 pp；它们的 gate 机会少 1.5～6 倍（§6.4）|
| RL 取代筛选（每轮一次对偶孪生）| 基准世界 −1.9，het 0 −3.0，只有有利世界 +1.1；推迟到真实数据显示属于后一种世界 |
| 先用一次探针决定要不要开 RL | 50 道题分辨不出世界（§6.8）；按探针切换，在基准世界里 −0.5 |
| 包内 Thompson 抽样做探索 | 目标是冻结后的策略，不是 train 上的遗憾；在 n = 25～50 时不比平衡分配好；倾向值不精确，配对也没了 |
| fold A / B 切分 | 仿真里不切 fold 更好（+3.81 对 +2.92）；收住伤害对膨胀是保守的，救回只经过 gate |
| 按回合的后验（每个回合一条事实）| 过度自信：空选项的部署随轮数增长 |
| TD 或自举的价值函数 | 至多 4 个决策、奖励在最后、状态混叠；配对的蒙特卡洛无偏且更省 |
| 每个回合都决策（而不只在第一次出现时）| 格数成倍增加，数据不增加 |
| DPV 的快照分支与续跑（v0.5）| 每美元效率最好，但要改可信宿主、要验证 CLI 的续跑；在“值得付钱探索”被证明之前，省下的钱没有用处 |
| 精修候选总是单独 gate | 被接受的比例约 10%，浪费 gate 钱；改成低于分辨率时并入（§3.2）|
| 非方法选项跨领域合并 | 行为文字的符号跨领域翻转（v3 rulesmem；仿真 65%）；按领域划开胜过学（§6.6）|
| 改进器层对 R 变异类型的老虎机 | 每一格都是负的；只记录变异类型及其去向 |
| actor 在回合内查询价值表（“价值工具”）| 回合内没有奖励；让 LLM 自己读价值来决定，就不再是一个固定策略，也无法记倾向值 |
| 在 dev/test 上在线学习，或用随机策略 | 留出证据就不成立了；dev/test 只用冻结的贪心表 |
| 让 R 写表、写概率或写特征代码 | 学到的部分会被 R 的叙述左右；特征只能是固定语法里的数据 |
| 买 dev 学习曲线快照（每点 $12）| 25 题上的差约 0.5 题，读数噪声 ±1 题；train 上的交叉拟合曲线免费，功效更高 |
| 训练权重 | v1 不训练（v2 再议）；本设计的全部论点就是参数可以放在表里 |
