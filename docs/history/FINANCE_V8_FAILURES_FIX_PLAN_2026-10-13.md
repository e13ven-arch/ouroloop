# finance-v8 的 63 道失败 train 题：逐题读法与修法（2026-10-13）

> 来源：finance-v8 的 150 道 train 首遇里 63 道失败（51 道在 v7 也失败）。每道由一个读者读完整轨迹写下"要求什么、agent 做了什么、为什么错、哪种 harness 改动能让它过且不写任何一道题的值"；一个归并者把 63 条记录并成 8 类机制；每类由一个反驳者读 4～6 道样题（含可能被弄坏的题）核验。原始记录（含轨迹引文）在 `examples/automationbench/workspace-finance-v8/analysis/`（git 忽略）。本文只到 train；test 没有读过。

## 1 结论

- 63 道失败题里，读者认为 48 道可以由代码（不调模型的 tool / hook）从请求、读过的文档与写入里机械地检出或做掉；53 道的修法是 hook、7 道是 tool。
- 归并成 8 类机制，归并者估计合计可翻 36 道；反驳者逐类读样题后，8 类里 8 类"成立但要改"、0 类被驳倒；按核验过的样题比例，诚实的合计约 18～20 道。
- 像噪声（重跑可能自己过）的 9 道：operations.cross_department_budget_reconciliation, operations.hubspot_ticket_escalation, operations.safety_certification_gap_analysis, finance.xero_bill_entry, hr.compliance_training_enrollment, operations.zoom_deal_review, hr.docusign_policy_acknowledgment, hr.offboarding_multi_system, hr.pto_reconciliation。
- harness 改不了的 3 道：finance.quarterly_tax_estimate, hr.probation_review_reminder, operations.hubspot_ticket_escalation。
- 8 类里 5 类是同一种基础设施：写守卫在某个站点 hold 一次，hold 的文字由代码从本次运行的请求、读到的文档和写入里算出（没有证据就不 hold，原样重发即放行）。站点分别是：发消息、第一次写记录、第一批创建、finish。这一点决定了实现顺序：先把"带证据的 hold"做成一个通用件，再逐类加证据行。

## 2 机制（按归并者的实现顺序）

### message-lint

- 载体 hook；机械 True；工作量 medium；归并者估计翻 8 / 14 道
- 目标题：hr.benefits_open_enrollment_processing, hr.compliance_training_enrollment, hr.calendly_manager_office_hours, operations.docusign_lease_renewal, operations.mailchimp_ecommerce_sync, hr.mandatory_meeting_compliance, finance.grant_expense_tracking, finance.commission_calculation, operations.google_ads_budget_alert, finance.xero_bill_entry, operations.cross_department_budget_reconciliation, operations.hubspot_ticket_escalation, finance.tax_prep_summary, operations.calendar_airtable_gmail_maintenance_notice
- 可能弄坏：finance.qb_sales_receipt_batch (subtotal + tax = grand total is a required chain; the breakdown-vocabulary gate must cover 'subtotal'/'grand total'); operations.cross_department_budget_reconciliation (actual - budget = overrun is required in the per-head emails; one hold, resend unchanged); change-notice tasks whose message must state the old value (body_contains old value); privacy tasks that must omit full names or per-person figures; external-register messages where the request's verb reads oddly; requests that prescribe a line-per-item layout

**归并者的改法。** Site: the write guard's existing hold-once on outbound messages (gmail messages.send, slack chat.postMessage, SMS, ticket/record comments). First decode the body as the receiving system stores it (raw/base64 -> RFC 2822 To/Cc/Subject/body; payload.body.data; text) and echo that rendering, not the raw JSON; show every draft of a parallel batch in one hold instead of stopping the batch at its first unheld call. Replace the unconditional generic hold with evidence lines computed in code from the request text and the run's own tool results; the hold fires only when at least one line has evidence, and a resend goes through unchanged. Lines: (1) superseded value: from '<moved|rescheduled|changed|transferred|corrected|replaced> from X to Y', 'no longer X', 'Y instead of X', 'was X, now Y' in read documents, and from per-row read->write cell diffs keyed by the recipient's address (old cell values not among the new ones); if the body contains X as a whole word, quote X and the source line: 'state only the current value; resend unchanged only if the request asks you to report the change'; skip when the request text itself contains X or previous/old/what changed. (2) newer-notice entity: for each entity in the body that also sits in a read row linked to this recipient, if a later-dated line mentions it, print both lines and ask whether it is still current for this recipient. (3) request content clause: text after 'confirming that / to confirm that / stating that / saying / noting that / letting them know that / with the message / that says', or a quoted string in a sentence with a send verb, not preceded by a negation, must appear verbatim (case/whitespace-insensitive, minus a leading 'that' and trailing period) in the matching message. (4) deliverable verb: for the message the request names as '<X> summary/report/update/recap' to an internal channel, require X's completed form (generic inflector) and the count of completed plan items in the first line; skip when the count is 0. (5) name as recorded: for each To/Cc matching an email-shaped cell in a read row, if the row's multi-token name cell is absent from the body while its first token appears alone, quote the cell. (6) negation form: a term T from the request or a read document that the body negates as un-/non-/in-/dis-T or 'not (a|an|the|one of|among) ... T' without the adjacent 'not T', when no read document uses that form itself. (7) calc chain: numeric figures in the body forming a+b=c or a-b=c (tolerance 0.01), not all three present in one read result, and no breakdown vocabulary in the request (breakdown, itemized, subtotal, grand total, line items, show the calculation, before and after): 'keep the final figure and the source values; working goes in plan_changes'. (8) assumed constant: the assistant's text since the last read states an assumption with a numeric constant absent from the request and every read, while read numeric fields are used nowhere in the stated computation: list those fields. (9) placeholder: runs of */X adjacent to digits or dashes, [redacted], TBD, N/A, pending in a labelled field, with the unmasked form never read: quote it, name the tool result it came from and the catalog source families not yet fetched. (10) readable time: ISO datetimes with no standalone HH:MM or date token outside them: add them beside the verbatim stamps. (11) phrase placement and figure consistency: a quoted template phrase with a placeholder from the request ('...: $X') must sit in the first lines; figures an earlier sent message attached to an item must appear in a later message about the same item to another destination, skipped when the earlier destination is a person and the later one a channel the request did not pair with those items. Benchmark-agnostic: every X, Y, T, name, clause and figure is read at runtime from the request, the read documents and the draft; the package carries no value. Improver companion (not a harness change): before R picks targets, mark numeric *_body_contains/_cell_equals literals that no expression of up to four operands over the served data reaches as 'not derivable', drop them from R's target list and the regression denominator (finance.quarterly_tax_estimate), so rounds stop chasing them.

**核验：holds_with_changes。** 样题：hr.benefits_open_enrollment_processing（翻）, hr.compliance_training_enrollment（翻）, hr.calendly_manager_office_hours（不翻）, operations.docusign_lease_renewal（翻）。

**核验后的改法。** Keep the site (write guard's hold-once on gmail messages.send / slack chat.postMessage / SMS / comments), the decoded RFC 2822 rendering the guard already prints, and the batch rule (evaluate every draft of a parallel batch; execute the ones with no evidence; show all held drafts in one stop). The hold is keyed by (destination, subject) and fires at most once per key regardless of edits, so an edited resend that still has evidence is never held again. Replace the generic text with evidence lines; no evidence, no hold. Ship only lines A, B, C below now; lines (4)-(11) of the proposal have no evidence in the four trajectories read, two of them ((5) name-as-recorded on 'Hi Bob', (10) if it counts bare ISO dates like 'Expiry Date: 2026-03-31') would fire as noise in these very tasks, and (7) is admitted to threaten cross_department_budget_reconciliation; verify each on its own target trajectories before adding it.

A. Superseded value (per held draft, per To address). Sources of (X, Y, source_line), all read at runtime:
 A1. Read documents (mail bodies, Slack text, sheet cells, ticket comments): regex (moved|rescheduled|changed|transferred|corrected|replaced|updated|switched|moving|transferring)\s+(\S+\s+){0,6}?from\s+X(\s+to\s+Y)?, 'no longer X', 'Y instead of X', 'was X, now Y', 'previously X'. X ends at ' to ', ',', ';', '.', ')' or end of line.
 A2. Row diff: for every sheet/table write in this run, pair it with the last read of the same range; for each row whose cells contain the draft's To address, every old cell value that equals no new cell of that row is X (its new cell is Y).
 A3. The draft itself: the same regex as A1 applied to the draft body (e.g. 'corrected your enrollment from Basic to Premium', '(moved from March 25)') -- order-independent, covers runs that send before writing the sheet.
 Drop X shorter than 3 characters, booleans (yes/no/true/false/none) and empty cells. Fire when X appears in the body as a whole token sequence (boundaries = non-alphanumeric, so '$200' and 'March 25' work). Line text: "Your draft to <To> contains '<X>'. <source_line or 'tracker row N: <col> <X> -> <Y>'>. The current value is '<Y>'. State only the current value; remove '<X>' (for example the phrase '<draft phrase around X>'). Resend unchanged only if the request asks you to tell this recipient what changed."
 Skip the line when the request text contains X itself, or contains a report verb (tell|let .{0,20}know|inform|notify|mention|include|state|note|report|announce|explain) within 60 characters of (previous|old|original|prior|former|what changed|the change|changed from). Do NOT skip on bare 'change'/'changes'/'changed' (the three HR requests say 'check for corrections', 'check for any schedule changes', 'managers who changed roles' and all must still fire).

B. Replaced holder for a row's address (the calendly case; no sheet write needed). For each held draft and each read row R that contains the To address A as a cell: K = the row's key person = a multi-token name cell whose tokens match the local part of an email-shaped cell of R (david.okonkwo@ -> David Okonkwo), with K's own address != A. If a dated read line (Slack ts / mail date) mentions K together with a change verb (moving|moved|transferred|transferring|leaving|left|stepping down|no longer) and 'from <C>' where C is another cell of R, AND the same line (or the same dated message) names an entity Y with 'take(s|n)? over as <C>', 'new <C> (manager|lead|owner|contact)', 'replac(e|es|ing) K' or 'will lead <C>', then K is superseded for A with current value Y. Fire when the body contains K: "<A> is the address recorded on the row for <C>, whose <header> is <K>. Notice (<date>): '<line>'. Current <header> for <C>: <Y>. Name only the current holder in this message; mention <K> only if the request asks you to announce the change to this team." No Y -> no line (so product-team's draft, where Priya leaves and nobody takes over Product, is untouched and the required 'Priya' survives). Never fire on a draft whose To is K's own address.

C. Request content clause. In the request text, for each sentence containing a send verb (email|send|message|post|notify|reply|write|dm) and not containing a negation before the cue (don't|do not|never|without|not), take the text after 'confirming that|to confirm that|stating that|saying that|saying|noting that|letting (them|him|her) know that|with the message|that says|informing (them|him|her) that' up to the sentence end; strip a leading 'that' and a trailing period; also take any quoted string in such a sentence that contains no [placeholder]. Matching message: if the sentence quotes a subject template, the outbound message whose decoded subject matches it with [..] as wildcards; else a message to a recipient named in the sentence; else every outbound message of that kind (email vs chat). Fire when the clause is absent from subject+body after lowercasing and collapsing whitespace: "The request requires this message to state verbatim: '<clause>'. It is not in the draft. Add it word for word (you may keep your own wording around it)."

Hold text order: lines first, then the decoded draft(s). If several drafts in a batch carry lines, one stop lists each draft with its lines. A resend of a held (destination, subject) always executes.

**风险。** 1) Holds are advisory: the agent can resend unchanged; benefits (subject 'Correction Applied' shows intent to report the correction) and calendly (deliberate 'David has moved' sentence) are the likeliest to resist; expect roughly 3 of these 4 to flip, not all. 2) The proposal's expected_fixes 8/14 is not supported by what was read: only 4 trajectories were checked (3 flip as written, calendly only with rule B); the other 10 named fixes and the finance.quarterly_tax_estimate improver companion are unverified here. 3) Line A will strip old values from messages that legitimately report a change when the request phrases that need in words outside the report-verb regex (the could_break 'change-notice tasks' case); the narrow skip regex trades that risk for not silencing the three HR cases, whose requests all contain 'change*' words. 4) Short/boolean cell values and multi-value cells can produce false X; the length/boolean filter and whole-token matching limit but do not remove this. 5) Rule B relies on a name<->email-local-part match and on the notice containing 'from <cell>' plus a takeover phrase; other phrasings (e.g. 'X steps down, Y joins as head of C') will not fire, which is the safe direction. 6) Line C can fire on a clause that the agent paraphrased for good reason (tense, pronoun); adding the literal alongside is harmless for graders but may read oddly to a human recipient. 7) The per-(destination, subject) hold-once key means a draft edited to a new subject could be held a second time; acceptable, bounded by the number of distinct subjects. 8) Lines (4)-(11) are excluded from this package on evidence grounds, not refuted; if shipped anyway, (5) and (10) will add noise to every personal email and every ISO-dated email, and (7) must gate on 'subtotal'/'grand total'/'actual'/'budget'/'overrun' vocabulary or it will undo cross_department_budget_reconciliation.

### evidence-bearing-scope-hold

- 载体 hook+tool+prompt；机械 False；工作量 large；归并者估计翻 7.5 / 14 道
- 目标题：finance.capex_approval, operations.equipment_calibration_scheduling, operations.zoom_deal_review, hr.airtable_learning_path_assignment, operations.parking_allocation_management, operations.safety_certification_gap_analysis, operations.training_compliance_check, operations.space_utilization_analysis, hr.expense_report_audit, operations.loading_dock_scheduling, hr.return_from_leave, hr.break_schedule_processing, hr.jira_security_access_review, finance.slack_receipt_capture
- 可能弄坏：hr.contractor_renewal (PIP rows must get 'Pending VP Approval' and a VP email, not be dropped as minority-status rows); hr.handbook_acknowledgment (the on-leave row is already excluded correctly; a hold that invites re-inclusion would regress it); inclusive actions (notify all, pay all, invite) where annotated or minority-status rows must still be included; additive conditional clauses ('also cc HR for medical cases') if the branch line is read as replacing the main line; hard-requirement resources ('reject if unavailable', 'needs requester approval before moving'); policies of the form 'do not X yourself; email <team> to X' where the message to the executor is the required write; tasks near the 50-step budget that rely on parallel creates (one extra turn per held batch); the earlier 'exclude on-leave rows' regression shape if any line defaults to drop instead of asking

**归并者的改法。** Site: the write guard's hold-once, extended from message sends to the first record write and the first create batch of a run (sheet values.update/append, task/ticket/record/event/meeting creates), echoing every body of a parallel batch in one hold; plus plan_changes. Two mechanics: (a) reads-before-creates: when one assistant turn contains both read calls (GET/search/query/find) and non-idempotent creates, run the reads, return their results, hold the creates once with 'a lookup in this step is still pending; re-issue after reading its result'; when the catalog has no DELETE for the service, say the create cannot be undone here. (b) The hold text is built in code from the run's own data for each row/entity the write names, replacing the generic category list; no evidence line, no hold. Evidence lines, each quoting the row or sentence verbatim: cells of that row in columns the request's own column list does not enumerate (Notes/Comments/Remarks) together with one computed line 'Today: <request-stated or reference date, else the latest date in the records read>'; a status-like column (header contains status/state/standing/eligib/active) where the row's value is the minority among the candidate rows ('<col>=<value>; majority <modal>; the request does not mention <value>'); a cell of the same row containing a role/party word of the new value within a few tokens of approv-/confirm-/authoriz-/waiv-/exempt- ('the row's own record already states this; decide whether the policy's condition is met'); identifiers from any earlier plan_changes excluded entry that appear in this write, with that entry's reason as written, and plan_changes refuses a revision moving an entry from excluded to changes without a reason citing a source read after the previous plan; a request-stated window/threshold (dates, amounts) with each item outside it on either side ('an item before the start is as out of scope as one after the end; urgency does not widen a window'); for sheet updates, the changed cells beside the values read, with 'writing the old value back later is still an update; a row still awaiting a required sign-off, or whose decision the policy does not state, is not written'; a create whose status field or plan item carries a defer/hold/until-they-return word while sibling creates to the same table carry the action's status ('a deferred action has no record in the action's destination; a note about it carries none of the action's fields'); list lines in the agent's own draft that carry a hedging clause (note:/confirm/verify/pending/subject to/before ...) beside that row's note cell ('an item on which the recommended action needs sign-off or whose source marks it reserved/closed/on hold is outside the list unless the request asks for flagged exceptions; recompute totals'); a rejection whose stated ground is unavailability/incompatibility, with the header word that names the option (preference/preferred/requested vs required/must/only) and the catalogue rows already read that satisfy the hard constraints at the requested time ('if the option is a preference and an alternative exists and nothing forbids substitution, schedule there instead'); policy sentences with prohibition / sole-executor / 'shared only with <party> via <system>' forms whose verb stem is in the body and whose named party or document address is a recipient ('this asks the executor directly; send only through the channel the clause names; add no notification the request or policy did not ask for'); a request conditional clause (a subset named by condition with a different verb: flag/hold/escalate/route/needs X before) matching a row whose 'Required/Needed' column is Yes or whose category cell matches ('this row is on the clause's branch; a main-line send to its contact, event or completion status needs a one-line reason'); a per-unit limit (per person/day/night/item) in the rule quoted for an excluded entry, with the unit count the item's description supports; and, when the request has a validate/check-against clause, every written value that is a verbatim copy of its own request with no other source read, the groups by a numeric sheet attribute (hours, level) with the within-group outlier and any item dated outside the batch's date range. The hold asks for a per-item verdict (keep, quoting the request clause; drop; or the branch action) and lets an unchanged resend through. Prompt: bound 'send what the source supports' to missing details, not a subject the source itself marks inactive, held or deferred, and bound 'contact everyone affected' to procedures that name no routing. Benchmark-agnostic: column names, majorities, dates, clauses and identifiers are computed from the request and the fetched documents at run time; the hold decides nothing itself.

**核验：holds_with_changes。** 样题：finance.capex_approval（翻）, operations.equipment_calibration_scheduling（翻）, operations.zoom_deal_review（翻）, hr.airtable_learning_path_assignment（不翻）。

**核验后的改法。** Site and once-ness. Keep the existing hold-once on message sends. Add two more hold-once sites per run: (i) the first record write (sheets values.update/append, PATCH/PUT to a record endpoint) and (ii) the first batch of non-idempotent creates (POST to a task/ticket/record/event/meeting create endpoint). A parallel batch is one hold: echo every body in it. A hold fires only when at least one evidence line exists for an entity the write names; the one exception is a sheet update, whose evidence (changed cells beside the values read) always exists once the range was read. An unchanged or amended resend goes through without a second hold at that site.

Reads-before-creates. If one assistant turn contains both read calls (GET/search/query/find) and creates of kind (ii), execute the reads, return their results, and hold the creates with: 'a lookup in this step is still pending; re-issue after reading its result'. Merge this into the create-site hold (one hold, carrying the pending-lookup line plus the evidence lines) rather than spending the create site's once on it. Append, computed from the api_search results seen in the run: 'no DELETE endpoint has been seen for <host>; a created <object> stays' when no DELETE for that host appeared in any catalog result.

plan_changes. Reject a revision that moves an identifier from excluded to changes unless the reason cites a tool result read after the previous plan whose content contains that identifier (an error body or a catalog listing that does not contain it does not count). The refusal message repeats the previous exclusion entry verbatim. A refused plan_changes stops the remaining calls of that turn the same way a stopped write does today, so creates that name the identifier do not execute in that turn.

Evidence lines (built in code from the run's reads; each quotes the cell, row or sentence verbatim; the write's entities are matched by identifier, email, or the row's first-column value appearing in the body). Verified against the four trajectories:
1. Sheet update: for each row the range touches, the cell's read value -> written value, and 'a range that spans a row writes that row; writing the old value back later is still an update; rows you are not changing are left out of the range and the others written as separate ranges'. Sign-off sub-line, only when the written value is a decision word (contains none of pending/awaiting/hold/review/escalat) and the row has a cell in a column whose header contains approv-/sign-off: quote that cell and the policy sentences read that contain 'required'/'must' and a party word, and ask 'quote the policy sentence that states the outcome when a required approval is missing; if none, leave this row out of the range'. The written-value condition is what keeps it off hr.contractor_renewal, where 'Pending VP Approval' is itself the write.
2. Prior exclusion: an identifier from any earlier plan_changes excluded entry that appears in this write, with that entry's reason as written.
3. Window: fire only when the request contains a window phrase (next N days/weeks/months, within N days, by <date>, between <date> and <date>, before/after <date>) and the write names an item whose date (from the body or the row read) falls before the start or after the end. Show 'Today: <request-stated date, else the latest date in the records read>', the request clause verbatim, and 'an item before the start is as out of scope as one after the end; urgency does not widen a window'. Ask: keep by quoting a request clause that includes items outside the window, or drop.
4. Unlisted-column cells: cells of the row in columns the request's own column list does not enumerate whose header contains note/comment/remark, together with the Today line.
5. Minority status: a column whose header contains status/state/standing/eligib/active where the row's value is held by fewer rows than the modal value among the rows read: '<col>=<value>; majority <modal> (n/m)'. If the request contains all/every/each over the row set, quote that request clause on the same line so inclusive tasks see both.
6. Deferred create: a create whose status field or notes contains defer/hold/sabbatical/until/await/recall while sibling creates in the same batch to the same table carry a different status. Say: 'a record in this table that carries the item's identifier and the siblings' fields is the action's record; name the sentence that puts the note here, or where the policy puts it; if nowhere was read, the note goes in the report'. This is the line closest to deciding; it is the only way hr.airtable_learning_path_assignment flips and it stays a question.

Hold text ends with the per-item verdict request: for each flagged item, keep (quoting the request or policy clause), drop, or the branch action with its destination; then re-issue (unchanged if it fits).

Prompt change limited to: 'send what the source supports' covers missing details, not a subject the source itself marks inactive, held, deferred or awaiting an approval; 'contact everyone affected' covers procedures that name no routing.

The remaining lines in the proposal (role/party word near approv-, per-unit limits, hedged draft lines, preference-vs-required, prohibition/sole-executor clauses, conditional-clause branches, validate/check-against copies, numeric-group outliers) are not exercised by these four trajectories; each needs its own trajectory check before it is included, and each adds a false-trigger surface.

**风险。** Likely fixes among the four read: capex (~70%), zoom_deal_review (~80%), equipment_calibration (~50%: both LAB-2008 and LAB-2011 must flip), airtable_learning_path (~40%; the rule's own text 'Note the deferral in Airtable' pulls toward a record and only a zero-record outcome passes). Expect about 2.5 of these 4, so the proposal's 7.5/14 is optimistic unless the other ten trajectories show the same shapes. Regression surfaces: (a) the sign-off line as originally phrased ('a row still awaiting a required sign-off is not written') would drop the 'Pending VP Approval' write in hr.contractor_renewal; the written-value condition above is required, not optional. (b) The minority-status and unlisted-column lines fire on every annotated row named in an inclusive write (notify all, pay all, invite); the ask-not-drop framing plus quoting the request's all/every clause limits this but the earlier 'exclude on-leave rows' regression shape is one bad verdict away. (c) The window line would drop past-due items in tasks whose request wants them ('process overdue invoices') unless the request clause is quoted beside it; a request that names overdue items supplies the keep clause, but an agent that does not quote it drops. (d) The deferred-create line is wording that leans toward no record; the host may read it as writing the decision into the hold. (e) Sheet-update holds fire on every run's first sheet write, adding one turn each; the three sites plus reads-before-creates can add up to four turns per run, which matters for tasks near the 50-step budget (these four used 12-17 steps). (f) The plan_changes refusal stopping the rest of the turn is new semantics; it must not stop reads in that turn, only writes naming the identifier. (g) Window parsing from phrases like 'next two weeks' is the fragile part of the calibration fix; if it fails, LAB-2008 stays. (h) Could-break tasks were not read here; the conditions above are inferred from the proposal's own descriptions and need their trajectories checked before the package is screened.

### record-write-lint

- 载体 hook；机械 True；工作量 medium；归并者估计翻 4.5 / 7 道
- 目标题：finance.expense_policy_violation, hr.employee_transfer_approval_workflow, finance.po_three_way_match, finance.invoice_file_organization, hr.docusign_policy_acknowledgment, finance.qb_sales_receipt_batch, hr.return_from_leave

**核验后的改法。** 保留的核心是三条确实能翻转断言的机制（(3) 备选标识符、(2) 把请求 id 当 key、(8)/(A3) 请求里紧邻目标的容器 id 被漏送），加上 PostToolUse 的'空过滤结果'注记和有界的 404 路由回退；删除 (9)，收窄 (1)(6)(7)。所有 hold 都是 advisory：hold 一次，按 (规则, host, 值) 计键（同一轮里并行的多个写只被 hold 一次，agent 照做后不再逐个重 hold），原样重发即放行，从不改写 body。

读取的材料：api_search 返回并缓存的该 URL+method 的目录项（parameters 里 location=path 的占位符、request 串里 'X: {A or B}' 形式的备选、可选 body 字段名）；本次运行所有读结果（GET 响应）中每个 id/key/name/number 类字段的值以及表格单元格、邮件正文等文档文本；请求文本中的 id 形 token（正则 ^[a-z]{2,6}_[a-z0-9_]+$）及其所在句子。

A. 写守卫（api_fetch POST/PUT/PATCH/DELETE）：

Off conditions that keep it away from opposite-requirement tasks: never fires when any write to the destination or party exists in any channel; fires only on the agent's own excluded/redirected entries or on request-named destinations with zero writes; every refusal is once and a one-line reason clears it (the only hold is on an entry the agent itself filed as redirected, and it can withdraw it); any sentence in the request or documents of the form 'notify only X', 'do not contact Y', 'keep it between us' registers the other parties as blocked destinations that no refusal may name; a request-named destination absent from the hold document never gets owner=yes. The hook quotes the sentence and the address; it never contains the word 'send' as an instruction to a specific address beyond quoting the document's own line.

**风险。** Honest expected value is ~2.2 fixes, not 2.5: negotiation ~0.7, job_board ~0.6, bad_debt ~0.5 only with the branch-as-action refinement (as written it is 0: legal@company.example.com appears in no read result, so neither destination path fires, and the model must derive the address from the domain pattern, which it declined to do unprompted in v8), ratio_analysis ~0.45 because three assertions must all pass and the 'no 1.29 in the CFO mail' one depends on the model omitting figures while the request says to preserve values verbatim. Break risks: (i) hr.jira_security_access_review: 'only Security performs' vs 'only the Committee approves' is separated by a verb regex; a neutral once-only question is low-risk but the agent may still email security@ when it previously did not; mitigate by counting a Jira write assigned to or naming Security as satisfying the party and by the blocked-destination rule when the policy says not to contact them. (ii) 'notify only the manager' requests: handled by the blocked-destination registration, but a document that lists several addresses near an exclusion line will still produce one refusal per unwritten address, costing turns and nudging over-sending. (iii) Generic freeze clauses: the computed owner regex ('the board will decide') can mark a request-named board@ as owner and demand a hold notice where the grader wants silence; the 'quote the line that says not to contact it' escape exists but the model must use it. (iv) Descriptive addresses: header fields and signatures are excluded, but a sheet 'Email' column adjacent to a party name (e.g. hiring-manager tab) can still be matched if the party token appears in the same row; restrict adjacency to prose or to a row whose header cell names the party. (v) The scope-check hold still holds every redirect message once ('items a policy excludes'), so each fix costs at least one extra turn and the model occasionally rewrites rather than re-issues. (vi) Screening: the verb list and the owner-word list are generic English, but V0's heuristic_terms check may count them; keep them as one shared list in the hook, not per-task words, and keep the prompt text additive. (vii) Replay false triggers: the request-named-destination record fires on every task where a request-named address got no write for a legitimate conditional reason ('email X if any ratio is out of range'); allowing the request itself as the clause source with a one-line reason keeps it under the 0.2 budget but adds another branch to test. (viii) The whole package is three regex families plus ledger matching; it is mechanical, but each path must be unit-tested on these four trajectories and on the could-break ones before a paid stream, and the fix for bad_debt rests on the model inferring an address the data never states, which the host could read as benchmark-shaped if the refusal text mentions domain patterns; phrase it as 'look it up or derive it from the address form the documents use'.

### source-coverage-before-write

- 载体 tool+hook；机械 True；工作量 large；归并者估计翻 3 / 7 道
- 目标题：hr.job_posting_refresh, hr.pto_balance_alert, hr.pto_reconciliation, operations.mailroom_package_routing, operations.vendor_compliance_audit, finance.timesheet_to_invoice, finance.tax_prep_summary
- 可能弄坏：decoy sources (an older mail or chat line contradicting the authoritative sheet, prior-year rate cards, archived agreements) that the agent then applies; requests that restrict the input ('use only the Hours Tracker'); finance.invoice_file_organization shape, where a found document (the controller's column list) competes with the record's own schema; tasks near the 50-step budget (each first write adds 2-5 reads); policies requiring masked identifiers if a full value is found elsewhere; a content noun that appears incidentally in an unrelated result (the check passes vacuously)

**归并者的改法。** Site: api_fetch's error path, the first-write hold of the write guard, and a hold on plan_changes. (1) Not-connected 401/403 for service S (message matches a no-account/not-connected/no-credentials pattern): the harness runs the catalog search itself twice, once with the failed endpoint's own description words, once with the request's quantified noun phrase (the words after each/every/all/any), excludes S, keeps GET/list/values/query/search endpoints of other services, and appends them to the error text under 'Same facts may be reachable at:' with ids and urls. (2) First-write source coverage, hold once: if the request has a universal quantifier over a noun, a not-connected error occurred, and no list-type endpoint outside mail/chat (sheets values, drive files.list, airtable/trello/jira/notion records) has returned data ('the request acts on each <noun>; you have read N records, all from mail/chat; read a list source or name the record that lists them'); or a chat/messaging service in the catalog was never read; or the mailbox was only listed with a keyword filter on every call ('list the mailbox without a filter and read the chat channels; look for any approval, cancellation or change notice about a person on your list, since a later notice overrides the sheet'); skip when no chat service exists or the mailbox was listed unfiltered. (3) Procedure by reference: the request contains our/the ... process|policy|procedure|standard|guidelines|SOP|playbook with no inline content, and a document-listing endpoint from the api_search results (files.*.list, drive.files.list, *.pages.search, pins.list, attachments, company files) is uncalled: hold plan_changes once quoting the clause and the endpoints: 'read any document that defines statuses, flags or escalation recipients before planning; copy its exact status terms; send escalations to the recipient it names'. (4) Container coverage: a request-named spreadsheet read only through values/<named sheet> without a spreadsheets.get listing of its worksheets, or a channel about to be posted to whose history/pins were never read: hold once naming the ranges read. (5) Content-term coverage: the request says a message must include a named content noun ('with/including the instructions|procedure|policy|template|guidelines') that occurs in no read result: 'locate the source instead of writing your own'. (6) Join gap and entity cross-reference: on the first-write hold, compute id/name sets across the JSON tables read and print entities present in one source and absent from another; for each entity in the write body (customer/vendor/person names, mailbox domains) with no search in a second source, run the generic name searches (Drive name/fullText contains, Slack search.messages, Gmail q, CRM search) and append the hits (name, id, date, snippet): 'these mention an entity in your write and you have not opened them; open the ones about rates, agreements, discounts, corrections or holds, then re-issue'; with zero hits the write goes through. (7) The message-lint placeholder check lists the unfetched source families. Benchmark-agnostic: nouns, entities and endpoints come from the request, the catalog and the trajectory; the hook requires reading, never an exclusion.

**核验：holds_with_changes。** 样题：hr.job_posting_refresh（翻）, hr.pto_balance_alert（翻）, hr.pto_reconciliation（翻）, operations.mailroom_package_routing（翻）。

**核验后的改法。** Site: the write guard's generic first-write path - the first non-GET api_fetch of the run that is not a search/list endpoint (gmail send, slack chat.postMessage, twilio, sheets values.update/append/batchUpdate, any PUT/PATCH/DELETE) - plus api_fetch's not-connected error path. Release conditions are checked mechanically against the call log, never 'once' and never by a sentence from the agent. One combined hold message per call: if the existing scope check also applies, its text is appended to the same message instead of a second consecutive hold (the trajectories show the agent treating a second hold as noise and re-issuing unchanged).

Gate A - container coverage (no cue needed; fires in mailroom and pto_reconciliation):
A1: every spreadsheetId seen in a values/ GET with no spreadsheets.get on that id -> hold: 'Spreadsheet <id>: you read ranges [<list>] but never listed its worksheets. GET spreadsheets/<id> (url from catalog) and read each worksheet you have not read, then re-issue.' Released when spreadsheets.get/<id> has been called.
A2: a chat.postMessage whose channel (id or #name) has no conversations.history or pins.list call -> hold: 'Channel <x>: its history and pins were never read. Read them (conversations.list first if you only have the name), then re-issue.' Released when a history or pins call for that channel id/name exists (if the name was unresolved: conversations.list plus one history call).
If the request restricts inputs ('only'/'solely' + a named source), A2 is skipped and A1 runs only on that named spreadsheet.

Gate B - record-source and notice coverage (fires in job_posting_refresh and pto_balance_alert). Cue required, either: (i) a not-connected/no-account/no-credentials 401/403 occurred this run, or (ii) the request contains a policy/change cue by grammar, not by value: (current|our|the) ... (polic(y|ies)|process|procedure|standard|guidelines|SOP|playbook), 'recent changes', 'holds', 'approval requirements', 'most recent data', 'latest'. Without a cue Gate B is off (mailroom: off, correctly).
B1 (list source): the request has a universal quantifier (each|every|all|any) over a noun and no non-mail/chat record endpoint (sheets values, drive files.list, airtable/notion/trello/jira/hubspot list/search) has returned data -> the harness looks up the catalog BY ID PATTERN (not semantic search): *.files.list, *.spreadsheets.get, *.conversations.list, *.records.list, *.bases.*, *.pages.search, *.search.messages, excluding services that returned not-connected; hold: 'The request acts on each <noun>; the N records you read are all from mail/chat. These listing endpoints exist and are uncalled: <id, url, ...>. Call the file listing with no filter and the channel listing, read what they return, then re-issue.' Released when at least one listed endpoint has been called. No 'or name the record' exit.
B2 (notice coverage): the mailbox was listed only with a q/query filter on every call (labelIds-only counts as unfiltered), or a chat service exists in the catalog and no conversations.history/search call was made -> hold: 'List the mailbox without a filter and read the channel histories; look for any approval, cancellation or change notice about an entity on your list - a later notice overrides the sheet.' Released when an unfiltered messages.list exists and, if chat exists, a conversations.list or history call exists.

Not-connected error path (replaces proposal part 1): append to the error text the same id-pattern catalog listing of uncalled generic listing endpoints of other services under 'Same facts may be reachable at:', not a semantic re-search keyed on the failed endpoint's description.

Dropped from this package: (5) content-term coverage and (6) join-gap/entity cross-reference - neither is needed by the four tasks, (6) carries the largest decoy and step cost, and the invoice_file_organization conflict comes from the prescriptive 'copy its exact status terms / send escalations to the recipient it names' wording of (3)/(5). (3) survives only as cue (ii) of Gate B. (7) survives as the 'uncalled families' line inside the hold text.

Hold wording rules: ask only for reads; quote endpoint ids and urls from the catalog; state which ranges/channels/messages were already read; never say skip/exclude/apply; nouns and ids come from the request, the catalog and the call log. Bounded cost: 1 call (A1), 1-2 (A2), 1-3 (B1), 2-3 (B2).

**风险。** 1) The missing sources are inferred, not observed: job-posting list (probably a Drive sheet, by the sibling-task pattern), Carol's exemption (a mail or chat notice), the reconciliation process (second worksheet), mailroom rules (third worksheet or #mailroom pins). If one lives elsewhere (an attachment, a doc not in Drive), the gate opens the wrong door and the task stays failed, not worse. Expected: 2-3 of the 4 flip; job_posting_refresh is the least certain because after finding the list the agent must still apply the 90-day and hold logic across 8 roles. 2) Decoys: reading more surfaces older contradicting notes (could-break item 1); the hook cannot adjudicate - it relies on the system prompt's 'later overrides older' rule and says only 'read'. A decoy touching Alice would break pto_balance_alert's passing assertions. 3) Could-break set: 'use only X' requests - Gate B and A2 are skipped by the restriction clause, A1 stays on the named container; invoice_file_organization - the schema conflict came from prescriptive copy-terms wording, which this version removes (read-only holds); masked identifiers - untouched, no instruction to use found values; near-budget tasks - gates are bounded to 1-3 calls each, the four tasks used 8-17 of 50 steps. 4) Gate B's grammatical cue list is still a word list; the host must accept it as benchmark-agnostic (policy/process/procedure are catalog-independent English, not train-task values). 5) Interplay with the scope check: two holds on one call must be merged or the agent re-issues unchanged (seen 6 times across the four trajectories). 6) The first-write site must cover sheets PUTs and Twilio POSTs, not just message sends - the scope check today holds only messages, which is why pto_reconciliation's PUTs went straight through. 7) The api_search catalog is noisy; B1 must use an exact id-pattern scan (or fixed family queries filtered by id), otherwise the hold lists nothing useful and the agent re-issues.
