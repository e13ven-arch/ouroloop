## 0. 结论先行

**做什么。** 给框架加一个**验证过的经验库**（VEL，verified experience library）。它从 train 题的尝试里提炼“何时、做什么、避免什么”的条目，按题检索给 agent，每条按 train 奖励记功、该退役就退役，整库定期作为一个快照走现有的筛选和 dev gate。见过的 train 题越多，库越大、越准；库通过 gate 才进入 W。贪心环（v0.4 的 R 轮次）保留，排在库的轨道之后（下称 L+G）。

进化发生在条目这一层：提炼和合并是变异，按功劳退役是选择，快照经 gate 进入 W 是遗传。类 RL 的部分也落在这里（§2.4 的对照表）：train 上的首遇尝试是 rollout，判分器是奖励，和 W 自己读数的差是组相对优势，从验证过的成功与对比对里提炼是“语义梯度”，按条目记功是价值估计，Reflexion 重试是探索，gate 是策略评估。权重不动，dev/test 不回流。

**仿真说了什么（§3）。** 四类机制放进同一个标定世界，等预算比较。下表是相对 v0.4 贪心环（G）的真实 test 增益差，单位是 25 道 test 中的题数，括号里是配对标准误：

|---|---|---|---|---|---|
| finance $150 | −0.05 (.06) | −0.01 (.06) | −0.16 (.06) | **+0.19 (.05)** | +0.17 (.06) |
| finance $300 | −0.13 (.07) | −0.09 (.07) | −0.14 (.07) | +0.10 (.06) | **+0.17 (.07)** |
| finance $600 | −0.20 (.07) | −0.11 (.07) | −0.12 (.07) | −0.01 (.06) | **+0.17 (.07)** |

- 库的符号取决于三个还没有任何记录量过的参数：检索的召回、无关条目的伤害、提炼的命中率。取悲观值时符号翻转。

**为什么另外三类不赢（§3.7）。**
- **选择的天花板低。** 筛选若能在 3 个候选里完美挑中最好的（G_opick），也只多 +0.06～+0.13。B-Race 和老虎机改的都是“挑哪个”，上限就在这里。gate 若知道真相（G_ogate）能多 +0.3～+0.8，但 gate 是冻结的。
- **样本内的修复大半是过拟合。** 统一世界里样本内修复率 32%，没见过的题上约 6%（v3：dev 上 11～19%，空候选约 10%）。合并把两个候选的过拟合修复并起来，同时继承两份伤害。
- **数据太少。** 每个领域 10～40 个候选、每个算子 7～10 次拉动、奖励标准差约 2 题，老虎机学不动；跨领域带走臂的后验，四个领域依次是 +0.04、0.00、−0.21、+0.07。
- **库赢在进 gate 的候选质量，不在次数。** $300 时库快照进 gate 时的真实增益 +0.75～+1.02 题，贪心的候选 +0.20～+0.35；库的 gate 次数反而少（4.6 对 6.4）。这和 AGENT_RL §6.4 的结论一致：瓶颈是 gate 和候选质量。

## 1. 现在的循环为什么只是贪心爬山

### 1.1 循环的形状

v0.4 每轮：R（一次 LLM 编码会话）从当前 W 提出 k = 3 个候选；train 筛选给每个候选读一次它的失败集和 6 道通过样本（每轮重抽）；合格的（≥1 修复、≤1 样本退步）里净翻转最大的进 dev gate；gate 用 W 的三次合并读数作对照，`min_gain` 0.05（25 题上 ≥ 1.25 题），第一读数、确认读数单独、两次合并都要清过；退步是每题均值降幅 > 0.5，比例 ≤ 0.1；成本项 β0 0.10、β1 2.0。过了就装上，没过就丢；连续 2 轮没装上就停（patience 2）。

这就是一条谱系上的贪心爬山：每代只留一个，其余全丢；搜索策略本身不变。

### 1.2 缺陷，用记录里的数

| 缺陷 | 记录里的数 | 后果 |
|---|---|---|
| **一代只留一个，其余全丢** | finance 第 1 轮：send_review 修 3 坏 2、finish_deferral 修 2 坏 1、source_memory 修 9 坏 1，三者修的题互不重叠、改的是三个不同的文件；只有 source_memory 进 gate 并装上 | 另外两个候选在 train 上真实做成的 5 道题，除非 R 碰巧重提，就丢了 |
| **经验不累积** | 第 1 轮 41 次筛选尝试里，14 次在 W0 失败的 train 题上成功；v0.3 五领域三轮都被拒，除了笔记什么都没留下 | 验证过的成功只有在整个候选被装上时才留下；没装上的候选里的好做法下一轮从零开始 |
| **同样的修复被反复重新发现** | v3 的 rulesmem 与 writemem 各修好 finance dev 的一道题（两道在 W0 的四次读数里都是 0/4），都只是 +1 题，低于 1.25 题的门槛；v0.4 的 source_memory 又修好了这两道（其中一道只在确认读数里）| 能修的题是一个反复出现的小集合；一个记得住“上次怎么修好的”的东西比每轮重想更省 |
| **筛选把噪声当信号** | finance 两次 W0 train 读数（v3、v4，同一划分）有 6/50 道不一致；第 1 轮 18 次翻转里 6 次（33%）落在这 6 道上；xero_bank_reconcile 在全部 3 个候选下“退步” | 噪声被记成某个候选的修复或伤害；R 追着它跑（诊断 RC2） |
| **样本内修复不迁移** | v0.3 样本内修复率 27～44%，dev 上 11～19%（空候选约 10%）；finance 第 1 轮样本内 14/23 = 61%；source_memory 在 16 道 W0 稳定失败的 dev 题上修好 3 道 | 筛选里的“修 9”大半到不了 dev；按样本内修复排序、合并、给奖励，都在放大过拟合 |
| **gate 的赢家诅咒** | 统一仿真里被接受的候选，第一读数 +2.74 题，真实增益 +0.96 题；source_memory 第一读数 +2.33、确认 +3.33 | dev 上的增益是过程数字；真实增益大约是读数的三分之一 |
| **搜索策略不学习** | v0.3 与 v0.4 的 12 个候选里 0 个工具、0 个 agent，其余全是文字与 hook（仿真据此把 R 的习惯设为文字 45%、guard 25%、finish 25%、工具 3%、agent 2%）| 哪类改动有效，没有任何东西在学 |
| **见题再多也不变好** | 统一仿真：同样 $300，train 题 25、50、100、200 道时 G 是 +0.71、+0.71、+0.64、+0.63 | 贪心只用 train 去找失败；成功不进任何积累 |

### 1.3 两个约束决定什么能帮上忙

1. **gate 是瓶颈，而且冻结。** 历次 14 次 gate 装了 5 次；四个主张领域 4 次 gate 装了 1 次。仿真里知道真相的 gate 多 +0.3～+0.8，能完美挑选的筛选只多 +0.06～+0.13。所以“更聪明地挑候选”的上限很低，“产生更好的候选”才有空间。
2. **n 很小。** 每领域 50 道 train、25 道 dev，每活动 3 轮 × 3 个候选。任何要靠几十次以上反馈才学得动的搜索策略（老虎机、父代选择、岛屿），在一个领域里都学不动。

这两条一起指向一件事：要让框架随经验变好，应当把**每道 train 题上验证过的成功**留下来、并按题复用，而不是在每代 3 个候选上做更复杂的选择。

## 2. 四类机制

每类写：机制、在我们循环里怎么做、文献证据、仿真结果。各类自己的设计仿真与统一仿真不一致时，两个都写，并说明差在哪里；§3 说明为什么以统一仿真为准。

### 2.1 档案 + 帕累托 + 合并

**机制。** 保留所有筛选过的候选（档案），每个成员带每道 train 题的通过估计；修好别人修不了的题的成员留在“前沿”上；每轮由固定代码把两个修复互补、互不伤害的成员机械地合并成一个子代，与 R 的新候选一起筛选；只有 W 的后代可以进 gate。

**在我们循环里怎么做（候选设计的要点）。**
- 档案成员：id、包引用、父代、算子（new | mutate | restraint | merge | reconcile）、组件（路径、哈希、位点、载体）、状态、train 读数、成本、gate 结论（不含 dev 题号）。写进 `experience.jsonl`，R 不能写。
- 每题估计 p̂(m,t) = (通过 + 先验)/(n + 1)，先验取父代的 p̂；W0 的先验用同一身份下全部有效读数。两次 W0 读数不一致、或在两个不共享组件的成员下都“退步”的题，标为不稳定，权重 0.5。
- 相对 W 的修复集 F 与退步集 R；前沿 = F 非空且未安装的成员。
- 每轮至多 1 个合并：(W, A) 的“变基”，或前沿上的 (A, B)，要求 F_A\F_B 与 F_B\F_A 都非空、F_A∩R_B = F_B∩R_A = ∅；三方文件合并，manifest 取并集，双方都改过的文件交给 R 调和。
- 合并子代的筛选读 F_A∪F_B∪R_A∪R_B（至多 16 题）+ 6 道样本；gate 只挑 W 的后代，est_net ≥ 1、Σw(R) ≤ 1。
- K 的新表 `search`（`mode = "population"` 等），约 400～600 行代码。

**文献证据。**
- GEPA（arXiv 2507.19457）：帕累托选择在 Qwen3-8B 上合计 +12.44%，对 SelectBestCandidate +6.05%、BeamSearch +5.11%；系统感知的 Merge 在 GPT-4.1-mini 上 +1.14 个点，在 Qwen3-8B 上 −2.45 个点，作者自己说何时合并、预算怎么分还需要研究；迁到 EvoAgentBench 的留出任务只有 +1.2～+5.7，有负格。
- DGM（arXiv 2505.22954）表 1：完整 DGM 50.0% / 38.0%，去掉档案 23.0 / 14.0，总从最好的分支 39.7 / 30.0。样本内、单跑、算力不等。
- HGM（arXiv 2510.21614）：分数不是好的父代指标；选择信号与后代产出的相关，DGM 0.285、SICA 0.444、HGM 0.778。
- AlphaEvolve（arXiv 2506.13131）、FunSearch（Nature 2024）、MAP-Elites（arXiv 1504.04909）、ShinkaEvolve（arXiv 2509.19349）：都在数千个样本的规模上运行。
- 反面：Wang 等（arXiv 2607.12227），同预算的并行采样 72.3 胜过演化的 harness 67.4，留出 +1.2 / 0.0 / −1.4。

**仿真。**
- 候选设计自己的仿真：finance 3 轮 M − G = +0.21 ± 0.07 题，9 轮 +0.44；全部增益来自合并，只有档案、没有合并（P0）等于贪心；帕累托抽样对最好父代 1.01 对 1.04。
- 统一仿真：finance M −0.05 / −0.13 / −0.20（$150 / $300 / $600）；不合并、只留克制与扩展名额的 M_nomerge +0.07 / −0.05 / −0.11，support $150 时 +0.13。
- 按算子看进 gate 的成员的真实价值：新候选 +0.19、合并 +0.11、克制 +0.40、扩展 +0.22；接受率 .13、.07、.09、.05。
- 两个仿真的差：统一世界里没见过的题上修复率约 6%（按 v3 dev 与 source_memory 标定），合并并起来的大多是样本内的“修复”；候选设计的世界里同原因的题修复概率 Beta(2,3)，迁移高得多。

**结论。** 合并删；档案行免费保留作记录；克制变异由 AGENT_RL 的近失开关承担（§4.2）；近失候选里验证过的成功由经验库提炼（§4.3）。

### 2.2 自适应评估（B-Race）

**机制。** 把筛选变成贝叶斯赛跑：每题对 W 有稳定性信念（稳定失败、稳定通过、有噪声，按 W0 读数的经验贝叶斯混合）；候选的证据按组（目标、见过未瞄准、隐藏留出、稳定通过）记；用知识梯度把尝试分到最能提高“选对”的地方；按 gate 规则的后验预测概率 P_acc 决定送不送 gate。

**在我们循环里怎么做（候选设计的要点）。**
- 每领域每划分一个三类混合先验（finance train (0.32, 0.36, 0.32)，dev (0.62, 0.32, 0.06)），基线时冻结进 K。
- 6 道 P(稳定失败) ≥ 0.75 的 train 题作隐藏留出，每个工具族至多一道，R 只见计数。
- 每个候选先读 2 道最确定的目标题 + 2 道稳定通过题（12 次），再按每批 3 次的知识梯度分配，到 42 次或增量 < 0.01 题为止。
- 送 gate：E[增益] 最大者，P_acc ≥ 0.15 且 P(增益 > 0) ≥ 0.5；否则本轮不付 gate。gate 与确认逐字节不变。
- 约 600～900 行代码。

**文献证据。** Hoeffding races（NeurIPS 1994）、F-Race / irace、successive halving（AISTATS 2016）、Hyperband（JMLR 2018）、BOHB（ICML 2018）；知识梯度（SIAM J. Control Optim. 2008）、OCBA、top-two Thompson；TRIPLE（arXiv 2402.09723）把提示选择做成最优臂识别；MIPROv2 的小批量贝叶斯优化；tinyBenchmarks（ICML 2024）用 IRT 挑信息量大的题；Miller（arXiv 2411.00640）的配对与聚类误差棒。

**仿真。**
- 候选设计自己的仿真：在“迁移异质”的世界里（一半候选泛化、一半很窄），把尝试挪到留出与稳定通过题上，finance 每轮增益 +45%（0.90 → 1.30 题），support +40%，marketing +60%；在“迁移同质”的世界里反而 −6～−14%，知识梯度大致持平。送 gate 规则少付 7～45% 的 gate，坏安装少 25～45%。
- 统一仿真：finance B −0.01 / −0.09 / −0.11；support $150 +0.17，$600 +0.09；sales 约 0。
- 两个仿真的差：统一世界的样本内加成对所有候选相同，即“同质”世界，所以对 B-Race 不利；可它也说明了天花板：完美挑选只多 +0.06～+0.13（§1.3）。B-Race 的优势只在 ρ（没瞄准的题上的修复率 / 瞄准的题上的修复率）跨候选差别大时成立。这个量还没测过。
- 真实回放（第 1 轮，免费）：贝叶斯规则同样选 source_memory（P_acc 0.38，E[增益] 1.25 题）；xero_bank_reconcile 的“退步”只值 0.41 nat（有噪声的题），send_review 在 qb_sales_receipt_batch 上的退步值 2.43 nat（真伤害的证据）。

**结论。** 推迟。免费的一半保留：稳定性标签进 R 的输入与筛选行，只记录、不改选择。ρ 的异质性由方法库 learn 读数顺带量出（§5.3），够大再重开。

### 2.3 类 RL 的搜索策略（算子老虎机）

**机制。** 把 R 的候选分成算子臂（工具、guard、finish、文字、agent、重组），每轮用 Thompson 抽样分配 k 个名额；奖励来自一块 R 看不见的 8 道 train 题（盲切片）和 dev 第一读数；按“机制有没有作用”记功；跨领域分层先验。

**在我们循环里怎么做（候选设计的要点）。**
- 臂在 K 里冻结；准入把每个声明的（载体、位点）映射到臂；`slot_mismatch` 拒绝。
- 盲切片 B：8 道 W0 失败的 train 题，从笔记、轨迹、api_errors、样本里排除。
- 候选价值 v_c = N_f·(b_c − b0)/8 − N_p·r_c/6；记功只算机制作用了的尝试；共模的样本题记为噪声。
- 每臂正态后验，前 2 轮强制每臂至少一个名额；记录倾向值供离线评估。
- 约 400～600 行代码。

**文献证据。** 进化算法里的自适应算子选择（DaCosta 等 GECCO 2008；Fialho 等 2010；Li 等 IEEE TEC 2014）；Thompson 抽样（Chapelle & Li 2011；Russo 等 2018）；EoH（arXiv 2401.02051）用固定比例的五种变异提示；HGM 的 Thompson 式扩展；GEPA 把反馈小批量与选择集分开；可复用留出（Dwork 等 Science 2015）。

**仿真。**
- 候选设计自己的仿真：算子名额 +13%，再加盲切片 +27～29%（每活动多花约 $19）；Thompson 与均匀分配在“异质”世界里一样，只在“工具独大”的世界里学得动（最好臂的份额 0.23 → 0.38，oracle 0.67）；控制名额检验的功效在 24 轮时只有 0.10～0.12。
- 统一仿真：finance T −0.16 / −0.14 / −0.12。finance 世界里每个交付候选的真实价值：文字 +0.30、工具 +0.08、finish −0.02、agent −0.06、guard −0.26；奖励标准差约 2、每臂 7～10 次拉动，分配几乎停在均匀；强制探索花掉 −0.12～−0.16。
- 在“工具独大”的世界（toolbig，工具每个候选约 +0.6）：T 在 $300 / $600 是 +0.41 / +0.67，而均匀随机名额 +0.43 / +0.62。全部增益来自强制多样，没有来自学习。贪心加 1 个强制非习惯名额（G_div）：toolbig +0.22～+0.32，finance −0.09～−0.18。
- 真实回放（免费）：xero_bank_reconcile 在第 1 轮被标为共模（finish_deferral 在那题上从未触发），send_review 的样本退步 2 → 1，finish_deferral 1 → 0，source_memory 1 → 0；声明“窄”的 hook 其实不窄：send_review 12/12、sendcov 11/14、finish_deferral 3/10 次尝试里都作用了。

**结论。** 推迟。算子台账、作用率与共模标记免费保留，只记录。让 R 写工具这件事由方法库承担（方法就是包工具）；方法的遥测会顺带量出“工具臂”的真实价值（§4.6 的触发条件）。

### 2.4 经验累积：验证过的经验库（VEL）

**一句话。** 经验库是 agent 在上下文里的“策略参数”。每见一道 train 题，框架做一步策略迭代：在 train 上首遇尝试（rollout）、和 W 自己的读数比出优势、从验证过的成功与对比对里提炼条目（语义梯度）、按条记功、按效用检索；整库定期作为快照走 gate。权重不变，test 不碰。

#### 2.4.1 数据结构（引擎侧，只追加，写进 E；只有条目正文进包）

**条目 `library_entry`：**
- `entry_id`：正文的 sha256。
- `shelf`：工具或意图族，例如 xero、quickbooks、sheets-reporting、email-slack、approvals-policy。
- `kind`：workflow | insight | api_note。
- `title`（≤ 80 字符）、`when`（触发条件，≤ 300）、`body`（≤ 1000，值写成 `<amount>`、`<vendor>` 这样的占位符）、`avoid`（克制条款，≤ 200；来自 over_action 笔记的 insight 必须有）。
- `source_hashes`：来源题及其 train 近似重复题（相似度 ≥ 0.6）的题目文本哈希的前 12 位。
- `provenance`：train 题号与尝试 id，只在引擎侧，永不进包。
- `origin`：w0_success | contrast | reflexion；`born_at_n`；`status`：active | retired | merged。
- `stats`：`n_shown`、`adv_sum`、`harm`、`fixes`。

**快照 L_n**（内容寻址）：活动条目、n（见过的 train 题数）、编译出的包部件 `skills/library.md`。每条用段标记 `<!-- entry: id shelf=... -->` 分开，与 AGENT_RL 给 memory.md 加段标记是同一个做法。不新增包种类。

**流状态（每领域）：** train 划分的一个冻结排列（种子由 (`order_seed`, 领域) 定，哈希进计划）；游标 n；每题的读数（版本、库哈希、成功、部分得分）；b(t) = W_base 在该题上全部有效 train 读数的均值。

#### 2.4.2 一道 train 题上发生什么（只在 train）

1. **免费的经验。** 流走到题 t 时，本领域里 t 的全部有效 train 尝试进入提炼队列，包括 W0 的基线读数、历轮筛选与安装后重跑。一次成功做“成功提炼”；同一题有成功也有失败，就是一个对比对。
   - 原因：finance 的记录里已有约 23 道两次 W0 都通过的题、6 个 W0 内部的对比对，以及第 1 轮筛选里 14 个“W0 失败、候选成功”的对比对。这些成功今天全被丢掉。
2. **首遇读数。** W_base ⊕ L_n 在 t 上读一次。来源哈希含 t 或 t 的近似重复题的条目不检索（留一）。
   - 原因：这一次是“第一次见到这道题”的诚实读数，学习曲线（§6）就画它。
3. **同期对照。** W_base 单独在 t 上读一次，与首遇读数的先后随机。
   - 原因：给每一个 n 一个同时代的反事实，消掉回归均值和漂移；也是一份新的 W_base train 读数，给 b(t) 和稳定性标签用。
4. **Reflexion 重试（探索）。** 首遇失败时，同一包再试一次，附上那次失败的断言类型与参数投影（与 R 拿到的投影相同）。成功就成为一个验证过的对比对。只在 train，每题每遍至多一次。
5. **提炼。** 每道有新成功的题调用一次 LLM，用固定提示 `research.distill`（版本在 R 的策略集里）。输入：一条成功轨迹；同一题有失败时加一条失败轨迹；成功满足了哪些断言类型。输出至多 2 条。对比对要求写“语义优势”：成功做了、失败没做的，写成 when / do / avoid。
6. **固定检查。**
   - 模式与长度；
   - 现有的字面量检查（`Drafts.forbidden`，带 train 字面量索引与单题断言 `answers`）；一次自动占位替换，复查，仍不过就丢；
   - 条目的 `when` 必须在来源之外至少检索到 2 道 train 题，否则丢（只服务一道题的条目等于换了名字的答案）；
   - 去重：与现有条目的 TF-IDF 余弦 ≥ 0.8 → 一次 MERGE（对两段正文调用一次 LLM，出处取并集）；
   - 只做逐条的增量操作（ADD / MERGE / RETIRE），不整库重写；
   - 书架满了（每架 ≤ 6 条）就挤掉效用最低的一条。
7. **记功。** 每次有条目被检索出的 train 尝试（首遇、重试、之后的筛选）：`n_shown` + 1；`adv_sum` += r − b(t)；t 是 W_base 稳定通过题而 r = 0 时 `harm` + 1。`harm` ≥ 2，或 `n_shown` ≥ 3 且 adv_sum/(n_shown + 2) ≤ −0.2，就退役。
8. **检索。** 固定代码，在 `start` 位点：题目文本对条目的 `title` + `when` 做 TF-IDF（词表来自 train），过阈值，相关度排序、同分按效用，至多 3 条插进系统提示；train 上按来源哈希留一，dev/test 上不排除（dev/test 题从来不是来源）。检索记一个标记（检索到的条目、分数）。
   - 原因：检索是固定代码，不是 R 写的，结果可以复算；无关条目在仿真里是伤害的主要来源，所以只给 3 条。

#### 2.4.3 快照怎样进入 W

- 在 n = 25 和 n = 50 各编译一次快照，作为算子为 `library` 的候选，由固定代码声明。
- 筛选：W 失败的 train 题 + 6 道通过样本，都按留一检索；n = 50 那次读全部 50 道（兼作 §6 的配对剂量—反应读数）。资格与 v0.4 相同：≥1 修复、样本退步 ≤ 1（全 50 题时按 ≤ 1/6 的比例）。
- gate、确认、安装逐字节不变。装上之后，后一个快照替换前一个快照的组件，W_base 不变。
- 流走完以后，库冻结为 W 的一个组件；之后是 R 的轮次（L+G）。R 看得到库的遥测（`inputs/library.json`：条目、书架、记功计数、退役原因；只来自 train）。
- 没装上的快照，如果 AGENT_RL 被采用，可以作为近失候选进它的 learn 读数，按格学“在哪里开”（§4.2）。

#### 2.4.4 为什么算类 RL

| RL 的要素 | 在 VEL 里 |
|---|---|
| 策略 | W_base ⊕ 库 ⊕ 固定检索规则；参数是条目，不是权重 |
| rollout | train 上的首遇尝试与重试，当前策略下（on-policy）|
| 奖励 | 外部判分器：整题通过，断言级部分得分作次要量 |
| 基线与优势 | 组相对：同一题上 W_base 的读数（含同期对照）的均值 b(t)，与 GRPO 的组内基线同理 |
| 策略改进 | 提炼：从验证过的成功与对比对里写出“做什么、避免什么”（Training-Free GRPO 的语义优势）|
| 价值估计与信用分配 | 按条记功：`adv_sum`、`harm`；检索按效用排序 |
| 探索 | Reflexion 重试，只在 train |
| 信任域 | 每题至多 2 条、只做逐条增量、书架上限、退役规则 |
| 策略评估 | 快照走冻结的 dev gate；test 只在封存 final |

不是 RL 的地方，照实写：没有梯度、没有学出的价值函数、检索规则是固定的；“学会”只发生在 train，dev/test 只见冻结的快照。

#### 2.4.5 文献证据

- **ExpeL**（Zhao 等，AAAI 2024，arXiv 2308.10144）：在 train 任务上带重试地试错，从成功与失败的对比里抽取洞见（ADD / EDIT / 赞成 / 反对，带重要度计数，计数到 0 即删），评估时检索相似的成功轨迹；HotpotQA、ALFWorld、WebShop 上都有提升。本设计的记功与退役就是它的计数，换成判分器的奖励。
- **Agent Workflow Memory**（Wang 等，arXiv 2409.07429）：从过去的轨迹归纳可复用的工作流，Mind2Web 与 WebArena 上相对成功率 +24.6% 与 +51.1%（论文自报）；它的在线模式在测试流上学，我们不做（§9）。
- **Voyager**（Wang 等，arXiv 2305.16291）：经过验证才入库的技能库，按相似度检索，越用越大。
- **Training-Free GRPO**（arXiv 2510.08191）：不改权重，用组内 rollout 的“语义优势”更新一个经验库（加、删、改、留）。本设计的对比对提炼取它的做法。
- **ACE**（Agentic Context Engineering，arXiv 2510.04618）：逐条增量更新的“剧本”，论文自报在 agent 与金融基准上 +10.6% 与 +8.6%；它指出整篇重写会造成“上下文坍塌”，所以本设计只做逐条操作。
- **Reflexion**（arXiv 2303.11366）：回合内的口头强化，不验证；我们只把它当 train 上的探索，成功才入库。
- **反面与边界：** 这类工作多在测试流上在线学习，或报告样本内的数；留出、等成本的证据少（RSI_PLAN §1、§10）。ExpeL 的洞见总是开着；AWM、Voyager 按相似度检索，不按测得的价值退役。本设计多出的是：留一的首遇读数、同期对照、按奖励退役、整库经 gate 才进 W。

#### 2.4.6 仿真

- 统一仿真：finance L +0.19 / +0.10 / −0.01，L+G +0.17 / +0.17 / +0.17（$150 / $300 / $600）；support L +0.35 / +0.24 / +0.28；sales L +0.14 / +0.28 / +0.28。
- 坏安装每次安装 0.05～0.15，贪心 0.20～0.24；至少一次真实安装的概率高 0.10～0.13。
- 学习器本身（进 gate 之前，流到哪题才用哪题的记录）：finance 见过 0、10、25、50 道 train 题时，真实 test 增益 0、+0.67、+0.97、+1.17 题/25，曲线是凹的。
- 去掉重试（support 与“一次 W0 读数”两个情景）：$150 +0.01～−0.13；$300 −0.04～−0.17；$600 −0.28～−0.34。
- 符号依赖未标定的参数：悲观、有害、弱三种取值下，L+G 在 $300 时 −0.13、−0.15、−0.27。
- 详见 §3。

## 3. 仿真

### 3.1 为什么另做一个统一世界

四份候选设计各自的仿真都赢了贪心，但它们的世界不同：合并的世界里修复迁移得好，B-Race 的世界里候选的迁移异质，老虎机的世界里工具臂最好。各自的假设刚好是各自获胜的条件。统一仿真把四类放进同一个按记录标定的世界，等预算、配对种子（同一个种子下，隐藏的世界和 W0 读数对所有策略相同），这是本文结论的依据。它同样是假设（§3.8），但至少四类在同一组假设下比较。

脚本在会话临时目录 `scratchpad/evo/sim/`（`core.py` 世界与 gate，`policies.py` 五族策略，`run.py` 配对多进程运行，`calib.py` 标定，`main.py` / `seq.py` 曲线、train 规模与跨领域序列，结果在 `results/`）。S0 把它入库为 `examples/automationbench/evolve_sim.py`，与 `method_sim.py`、`agent_rl_sim.py` 并列。

### 3.2 模型

**世界（每个种子）。**
- 50 道 train、25 道 dev、25 道 test，另 200 道新题只用来量真实的总体增益。
- 题分三类：稳定失败（通过概率 0.02）、稳定通过（0.97）、不稳定（Beta(1.3, 1.3)，截在 0.1～0.9）。
- 份额：finance 0.48 / 0.40 / 0.12；support 0.45 / 0.30 / 0.25；sales 0.44 / 0.20 / 0.36。
- 失败来自 1～3 个隐藏的“阻塞原因”（概率 .65 / .27 / .08），每领域 10 个原因，频率服从 Zipf(1.3)；65% 的原因可以被某种 harness 改动修掉；每个原因有一个最合适的载体（文字 .35、guard .15、finish .20、工具 .22、agent .08），其他载体效果减半。
- 阻塞全部去掉后通过概率 0.88；被弄坏后 0.12。

**候选（R 写的）。**
- 在它起作用的地方去掉目标原因，弄坏一部分它作用到的通过题；对 R 预测会修好的 train 题另有 25% 的直接“修复”，这部分不迁移（样本内加成）。
- 载体：文字 1～4 条规则、总在作用、每条伤害 2.2%；guard 在相关题上 85%、其他题 45% 作用、作用时伤害 9%；finish 85% / 30%、8%；工具 90% / 20%、5%，被强制时 60% 交付；agent 总在作用、6%。
- 强度 Beta(3.5, 1.8)，15% 是“宽”的候选。
- R 按笔记里的频率挑原因（85% 挑对），载体习惯：文字 45%、guard 25%、finish 25%、工具 3%、agent 2%；避开已经筛掉或被拒的原因。

**费用与 gate。** 每次尝试 $0.47；R 每轮 $5（强制工具或 agent 名额时 +$1.5）；合并调和 $1.5；一次提炼 $0.15（finance 第 1 轮的笔记实测 $3.51 / 25 题 ≈ $0.14）。W0 基线（两次 train、三次 dev）共享、不计费。gate 照 `task_gate.judge`：合并对照；第一读数 ≥ 0.05 才做确认；合并与确认单独都 ≥ 0.05；退步（降幅 > 0.5）比例 ≤ 0.1。安装后对照换成新版的两次读数。成本项没有建模。

**库（没有记录可以标定）。**
- 检索：相关条目被召回的概率 0.6；无关条目过阈值的概率 0.06；至多显示 3 条。
- 一条好条目去掉它的原因的概率 0.5（文字不是该原因最合适的载体时 ×0.5）。
- 提炼：成功里每个相关原因 0.35；对比对里每个阻塞 0.6。
- 伤害：20% 的教训是坏的（显示时 10% 伤害）；显示了无关条目，伤害 0.03。
- 重试成功 0.4；每原因至多 2 条；伤害 2 次或效用 ≤ −0.2 退役。

### 3.8 局限

- **库的符号是假设。** 召回、伤害、提炼率没有任何记录可以标定；它们一取悲观值，符号就翻（§3.5）。S1-L 的任务就是量它们。
- **R 的候选很强时，库的花费挤掉了更好的 R 轮次**（marketing_big：L+G −0.03～−0.31）。
- **差距都很小。** 每个差都 ≤ 约 0.4 题/25（< 2 个点），低于一次 25 × 3 final 能分辨的量。真实比较要靠机制检查，不能靠头条数字。
- **世界偏向集中的原因。** 10 个原因、频率陡峭，对库和宽泛的文字有利；60 个长尾原因时一切都约等于 0。
- **R 的模型粗糙。** R 唯一的学习是避开失败过的原因；样本内加成对所有候选相同（对 B-Race 不利）；成本项没建模；基线不计费（200 道 train 时库的免费起步靠的就是这份不计费的基线）。
- **各族是简化版。** B-Race 的知识梯度分配简化成两级赛跑；合并的干扰率是假设的。每族自己的设计仿真都声称更多（档案 +0.2～+0.4、B-Race +40～60%、老虎机 +27%），统一世界没有复现，原因见 §2.1～§2.3。
- **R 的轮次在 v0.5 里会变**（方法库让 R 写方法），仿真里的 G 是 v0.4 的 R。S0 用实测参数重跑时一并更新。

## 4. 组合方案与推荐

### 4.1 推荐：L+G，嵌进每个主张领域的单一 v0.5 活动

一个领域一个活动（V0_4_PLAN §1.1、方法库 §5.4），活动分三段：

1. **基线**：照 v0.4（train 50 + dev 25 × 3）。
2. **库的轨道**：50 道 train 题的首遇流（每题一次首遇、一次同期对照、失败时一次重试、提炼），在 n = 25 与 n = 50 各过一次快照的筛选与 gate。
3. **R 的轮次**：方法库与 agent RL 设计的轮次（含 learn 读数与精修），库作为 W 的组件在其下。

然后是封存 final，各设计的增量都用同一次 final 里预注册的消融臂量。

原因：
- 仿真里 L+G 在三个标定世界、三档预算里都是正的，而且比 L 稳（库弱时后面的轮次托底）。
- 库排在前面，因为它不依赖 R，花的主要是便宜的 train 尝试；R 的轮次接着在一个更好的 W 上、带着库的遥测去做 R 才能做的事（写工具和方法）。
- 一个活动、一次 final，test 只读一次（方法库 §5.4）。

### 4.2 与方法库、agent 内 RL 的分层与接口

| 层 | 学什么 | 谁来学 | 数据 | 何时冻结 |
|---|---|---|---|---|
| 经验库（本文）| 何时做什么、避免什么（文字条目）| 固定代码 + 固定提示的提炼调用 | train 尝试的成功与对比对 | 快照经 gate 进 W |
| 方法库 | 只读的分析 / 搜索 / 核对方法（代码）| R | train 失败、遥测 | 装上即冻结 |
| 选项表（方法库 §3、AGENT_RL）| 每个选项在哪一格开 | 固定代码 | learn 读数的配对奖励 | 进 dev/test 前贪心冻结 |
| 包的选择（本文 §2.1～§2.3 推迟的部分）| 哪些候选进下一代 | 框架 | 筛选 + gate | — |
| R 的研究方法 | 怎么做研究 | R（带引用）| 自己候选的台账 | 每次会话记哈希 |

对两份文档的接口，只提五点：

1. **`start` 位点共用。** 库的检索与 AGENT_RL 的 `start` 位点是同一处宿主改动（组系统提示的地方）。库条目的段标记与 memory.md 的段标记是同一种格式。原因：同一处可信宿主代码只改一次、只测一次（全开等于原包的逐字节测试）。
2. **库是一个开关。** 已装组件都转成开关（AGENT_RL §1.2 第 4 条），库也是：learn 读数里库整体作为一个 `start` 开关独立随机化，表可以学出“哪些格里不给库”。没装上的快照可以作为近失候选进开关。原因：库的伤害如果集中在某一格，按格关掉就是学出来的克制，不用另造机制。
3. **近失候选的搭车测量。** learn 读数已经把近失候选作为开关独立随机化（AGENT_RL §7.3）。本文只要求它的报告多写三个数：每个近失候选在**它没瞄准的** train 题上的配对效应（ρ 的估计）、两两同时开时的交互项（合并是否可加）、按载体的效应（工具臂的价值）。原因：§4.6 的三个触发条件都读这三个数；数据已经在那里，边际 $0。
4. **记功与估计器各管各的。** 库按条记功（每次检索一个观测，r − b(t)），选项表按格用配对的 Beta 后验。两者回答不同的问题（一条文字值不值得留；一个开关在哪一格开），不合并成一个估计器。原因：条目数随 n 增长，按格的冻结规则（n ≥ 5、0.8）在条目层面几乎永远达不到。
5. **名字以先定稿者为准**（方法库 §5.5）：标记的种类（本文提议检索标记并入 `option_decision`，字段加 `entries`）、R 的输入文件（`uncovered.json` 三份共用一个）、K 的表名（本文 `[improvement.library]`）。

### 4.3 库取代合并

合并想留下的是“近失候选在 train 上真实做成的修复”。库用另一条路留下同样的东西：近失候选的成功轨迹进提炼队列，变成带触发条件、按奖励记功的条目，而不是把整个候选的代码和它的伤害一起并进来。

- send_review 修好 3 道、在 6 道通过样本里弄坏 2 道：合并会把那 2 道伤害一起带进来；库只提炼那 3 次成功“做了什么”，伤害如果出现，由记功退役。
- 原因：统一仿真里合并的真实价值（+0.11）低于新候选（+0.19），而库的快照 +0.75。

### 4.4 免费保留的部件（只记录，不改选择）

1. **稳定性标签。** 每道 train 题：W 在几次同身份读数里过了几次（同期对照让每个活动多一次），标签 stable_fail / stable_pass / noisy。进 R 的笔记与失败清单（“W 在 3 次读数里过了 1 次”），筛选行里给每次翻转标出是否落在 noisy 题上。原因：第 1 轮 18 次翻转里 6 次落在不一致的题上；v0.3 的 R 追过 ±2～3 题的波动（诊断 RC2）。
2. **共模标记。** 一轮里在全部候选下都“退步”的样本题，或者在一个从未在该题上作用的条件型候选下“退步”的题，在台账与 R 的投影里标为共模。原因：xero_bank_reconcile 被记到全部 3 个候选上。
3. **档案行与算子台账。** 每个候选的父、算子（new / mutate / restraint / library / refit）、载体、位点、作用率（hook 在多少次尝试里作用了）、筛选与 gate 去向。跨活动累计（finance → support → sales → hr）。原因：§6.2 的累计分析与 §4.6 的触发条件都读它。
4. **库的遥测给 R**（§2.4.3）。

这四项不改筛选规则。改选择的版本（加权资格、共模不计退步）在统一仿真里的天花板只有 +0.06～+0.13，等回放（§5.1）显示它们会改变至少一次真实的选择，再单独评估。

### 4.5 不是新机制、但比新机制大的杠杆：跑满计划的轮数

- 统一仿真里，照配置 patience 2 的贪心（G_pat2）在 finance 停在约 $90～99；同一预算下跑满的 G 多 +0.14、+0.39、+0.62（$150、$300、$600）。
- 这不是免费的：多出来的是花出去的钱。每 $100 的增益两者相近（G $150 时 0.36，G_pat2 0.34）。
- 所以它是一个预算决定，不是设计决定：根里给了 3 轮，就跑满 3 轮。建议 v0.5 的主张活动把 patience 设为计划的轮数。由用户决定。

### 4.6 推迟的族怎样重开（触发条件，事先登记）

一条总规则：S0 用实测参数重跑统一仿真，被推迟的族要在 finance 与 support 两个世界里都 ≥ G + 0.1（配对，> 2 个标准误），才重开设计。另外各有一个读真实数据的触发：

| 合并 | 方法库 S1 learn 读数里近失候选的效应与交互（§4.2 第 3 条）| ≥2 个近失候选在没瞄准的 train 题上配对效应各 ≥ +1 题，且两两交互 ≥ −0.5 题（大致可加）|

### 5.8 学习曲线怎么画

1. **train 首遇曲线（主图，两个领域都画）。** 横轴 n（流里的序号）；纵轴每 10 道题一个窗口的配对效应 mean(r_lib − r_ctrl)，自助法区间（按题重抽）。分三条：W0 稳定失败题上的修复、稳定通过题上的伤害、全部。次要量：断言级部分得分的配对差（同样是留一的首遇读数，属于样本外，可以用）。
2. **配对剂量—反应。** 对每道 train 题，Δ_t = r(L_50，留一) − r(L_{n_t}，首遇)。纵轴 Δ_t，横轴 (50 − n_t)/50（这道题首遇时库还差多少经验）。斜率 > 0 说明“同一道题，库见过的题越多，做得越好”。
3. **库的演化图。** 活动、退役、合并的条目数随 n；效用的分布。
4. **dev 的稀疏点。** 只有快照 gate 的读数（support 两个点），对 W 的合并对照。不另买 dev 快照（AGENT_RL §7.5：25 题上差约 0.5 题，读数噪声 ±1 题，只买到噪声）。
5. **按美元。** 已装 W 的 dev 增益（过程数字）随累计花费，旁边放 v0.4 finance 活动的同一条线，只作描述。

功效照实写：50 道题上，仿真预期的后半段对前半段的差约 0.5 题/25，单个领域测不出来；两个领域合并也只是描述性的。主张不建立在曲线上，曲线是“学习确实发生了”的过程证据。

1. **agent 层**：§5.8 的 1、2。估计量：后半段效应 − 前半段效应；剂量—反应的斜率。两个领域合并，自助法。
2. **搜索层，活动内**：每个活动报告每次 gate 的候选来源（库快照 / R 候选）、第一读数、是否被接受。预期库快照的接受率与第一读数高于 R 候选（仿真：接受率 .14～.20 对 .11，真实增益 3～4 倍）。n 很小（每活动 2 个快照），只作描述。
3. **搜索层，跨活动**：算子台账（§4.4 第 3 条）跨 finance → support → sales → hr 累计；预注册一个累计分析：攒到 ≥ 20 个被 gate 的候选之后，按来源与算子报告第一读数与接受率，并检验“同一来源的候选，随台账里先前经验的增加，第一读数是否上升”（领域作固定效应）。之前不做任何搜索层的主张。原因：统一仿真里带算子后验跨领域没有收益，老虎机设计的功效表也说明单领域测不出来。

### 6.3 怎么不自欺

| 陷阱 | 会怎样骗到我们 | 对策 |
|---|---|---|
| 回归均值 | 选“W0 失败过”的题看修复，噪声题自然会过一部分 | 同期对照；稳定性按 ≥2 次同身份读数分类；效应按配对差算 |
| 漂移 | CLI 或模型在两周里变了，曲线的上升其实是环境 | 同期对照与首遇读数同时跑、先后随机 |
| 留一失效 | 题 t 自己的条目、或近似重复题的条目被检索给 t，首遇读数变成样本内 | 来源哈希留一 + 近似重复（相似度 ≥ 0.6）；每 10 题一次审计；测试里故意放一道近似重复题 |
| 答案进库 | 条目里写进只属于一道题的金额、名字 | 字面量检查（带断言 `answers`）；占位符；“检索到 ≥2 道来源外的题”规则 |
| 顺序 | 排在后面的题碰巧容易，曲线看起来在涨 | 冻结的随机排列，哈希进计划；效应是配对差，与题的难度无关 |
| 曲线涨在“显示更多条目”而不是“条目更好” | 库变大后每题都显示 3 条，效应来自篇幅 | 报告每次显示的条目数与字符数；按显示条目数分层的效应；记功的秩相关检查 |
| 赢家诅咒 | gate 的第一读数比真实增益大约 3 倍 | dev 只作过程数字；主张只看封存 final |
| dev 的适应性复用 | 库多加了 2 次 gate，同 25 道 dev 被问得更多 | 收据上写每活动的 gate 次数；不按 dev 结果挑快照 |
| 多重主张 | 三份文档、多条臂，总有一条看起来显著 | 主假设只有 C1；各臂是预注册的次要、描述性比较 |
| 等成本 | 库让每次尝试变贵，增益其实是“多花了 token” | 报告每次尝试的成本；final 并列 W0 的 pass@k；gate 的成本项照旧 |
| 措辞 | 把 train 上的学习说成“测试时学习”或“改进器变强” | §6.4 |

### 6.4 措辞上限

- 可以说：“框架从 train 题的验证过的成功里攒下一个经验库，经 gate 进入 agent；在 train 上，agent 见过的题越多，首遇的成功率越高（过程证据）；封存 test 上 W\* 对 W0 为 X（C1）”。
- 不可以说：agent 在测试时学习；库让改进器变强；“RL 训练了 agent”。权重没动，dev/test 上只用冻结的快照。

## 8. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 库的符号是负的 | 召回低、伤害高或提炼弱时，仿真里 L+G −0.13～−0.27 | S1-L 先量；§5.7 的三分判定；L+G 而不是 L，后面的 R 轮次托底 |
| 效应太小，测不出来 | +0.15～+0.3 题/25，低于 final 的分辨率 | 主张只用 C1；库的增量作次要臂；机制靠过程检查与曲线 |
| 无关条目的伤害 | 库越大，检索到无关条目的机会越多；跨领域合并时最明显 | 至多 3 条；按效用排序；伤害 2 次退役；不跨领域合并；AGENT_RL 可以按格关掉库 |
| 答案或单题知识进库 | 条目是文字，最容易藏进一个具体值 | 字面量检查（含断言答案）、占位、来源外 ≥2 题、长度上限 |
| 留一判定漏掉近似重复题 | AutomationBench 同族题的文本很像 | 相似度 0.6 的近似重复排除；S0 在夹具上测；审计 |
| 提炼调用的成本与稳定性 | 每次约 $0.14，输出格式可能不合规 | 模式检查、只做逐条操作、失败就丢；成本进收据 |
| 库挤掉更好的 R 轮次 | R 的候选强时（marketing_big）L+G −0.31 | 有条件 GO 的中止规则；support 的等预算替代由用户选 |
| 与方法库、AGENT_RL 冲突 | `start` 位点、标记、R 输入文件、K 表名 | §4.2 的五点接口；先定稿者定名字 |
| 宿主改动影响身份 | `start` 位点在可信宿主里 | 只在新 bootstrap 生效；全关时逐字节相同的测试；不在付费运行期间合入 |
| W0 读数跨工作区复用 | 两份候选设计对 v3 与 v4 的 harness ref 是否相同说法不一致 | S0 的身份核对；不能复用就重买（+$35），或只用于提炼 |
| 仿真的模型风险 | 世界偏向集中的原因；R 的模型粗糙；各族简化 | S0 用实测参数重跑；S1-L 之后再重跑一次，才冻结 support 的计划 |
| 推迟的族其实更好 | 统一世界对 B-Race（同质迁移）和合并（迁移低）不利 | §4.6 的触发条件读真实数据；数据是搭车得来的 |
| 自欺 | 回归均值、漂移、顺序、赢家诅咒 | §6.3 |

## 9. 考虑过、不做

| 做法 | 不做的原因 |
|---|---|
| 机械合并（GEPA 式），每轮 1 个 | 统一仿真里 −0.05～−0.20；合并把样本内过拟合的修复和两份伤害并起来；近失候选的成功改由库提炼（§4.3）。触发条件见 §4.6 |
| 帕累托抽样选父代 | 候选设计自己的仿真里对最好父代 1.01 对 1.04，没有差别 |
| 父代老虎机（UCB、Thompson、DGM 的 sigmoid·1/(1+子代)）| 每领域 10～15 个成员，仿真里没有差别；HGM 的节点价值留到成员数上百时 |
| 岛屿模型、MAP-Elites 网格 | FunSearch 与 AlphaEvolve 在数千个样本上运行；我们每领域约 10 个 |
| 组件消融子代、LOO 剪枝 | 仿真 +0 增益，每活动多 $14 |
| B-Race 的知识梯度分配、隐藏留出、送 gate 规则 | 统一仿真里 ≤ 0；天花板 +0.06～+0.13；优势依赖还没测的 ρ 异质性。触发条件见 §4.6 |
| successive halving（3 → 1）| B-Race 设计的仿真里更差：弱的第一级读数会淘汰最好的候选 |
| 多买 W0 train 读数（$22.50）| B-Race 设计的仿真：Spearman 只 +0.03；同期对照已经顺带多给一份 |
| Thompson 算子老虎机、盲切片奖励 | 统一仿真里 −0.12～−0.16；单领域功效 0.10～0.12；R 看不到的 8 道题让 R 少了材料 |
| 强制非习惯名额（G_div）| 只在“工具独大”的世界里有用（+0.22～+0.32），finance 里 −0.09～−0.18；方法库已经让 R 写工具 |
| 筛选排序里的信任域惩罚、样本内部分得分 | 老虎机设计的仿真：−0.07、−0.05；样本内部分得分奖励“作用面宽”的文字 |
| 库跨领域合并 | 仿真里每个领域约 −0.2；只带共享原因的条目（神谕）也只有 +0.1。与 AGENT_RL 的“非方法选项不跨领域合并”一致 |
| 在 dev/test 流上在线学习（AWM、ACE 的在线模式、ReasoningBank）| 留出证据就不成立了；dev/test 只用冻结的快照 |
| 整库重写（单次调用重写整个库）| ACE 记录的上下文坍塌；只做逐条增量 |
| LLM 判官给条目打分 | 不确定、回放不了；记功只用判分器的奖励 |
| 向量数据库、嵌入检索 | 每领域几十条，TF-IDF 足够，而且确定、可复算 |
| R 写库条目或改记功 | 学到的部分会被 R 的叙述左右；R 只读遥测。R 改 `research.distill` 提示属于改进器层，推迟 |
| 库放在自定义 agent 载体里 | 检索必须是固定、可复算的宿主代码；agent 载体是 R 写的 |
| 第一次快照带中止规则作为默认（L?+G）| 一次 25 题读数分不开好坏世界（中止 65～67% 对 76～83%），上下行都减半；只在“有条件 GO”时用 |
| 买 dev 学习曲线的快照 | 25 题上差约 0.5 题，读数噪声 ±1 题；train 上的配对曲线免费、功效更高 |
| 生成新的 train 题来延长“见题”轴 | 需要可信的判分器，会改变任务分布；v1 不做 |
| 改 gate（加大 dev、改门槛）| gate 冻结；G_ogate 的 +0.3～+0.8 是天花板，不是可得的量 |
| 训练权重 | v1 不训练（v2 再议）；本设计的论点就是参数可以放在库里 |
