## 2. What the field does about evaluation noise and overfitting to the dev set

Concrete mechanisms, with who uses them. The striking pattern: almost every system has **one** of these; none combines repeats + held-out + statistics + pre-registration.

**Repeats per (candidate, task).**
- k=2 (coding, workspace) and k=4 (eng) inside the loop: RRSI ([domains/*/rrsi.json](https://github.com/google-research/rrsi/blob/main/domains/coding/rrsi.json)). Final test 3 reruns mean ± SD: AutoSaddler ([paper](https://arxiv.org/abs/2608.23041) lines 434–436). 2 trials per task in search, 5 for the frontier winner: Meta-Harness TB2 ([README](https://github.com/stanford-iris-lab/meta-harness/blob/main/reference_examples/terminal_bench_2/README.md)). 3 dev episodes on some BALROG suites, 5–10 test episodes × 3 repeats: HSI ([tasks.py](https://github.com/TailinZhou/hsi)).
- **One rollout, including the final**: DGM (`--num_swe_evals 1`), GEPA (issue [#139](https://github.com/gepa-ai/gepa/issues/139) open), StarHarness (`--repeats 1` passed to the held-out run too), HyperAgents (one eval at temp 0, but 5 independent *runs*).

**Larger or full eval sets per decision.**
- Whole evolve set every round, both candidates: RRSI (≈7–20k trials per run by the deep read's arithmetic). Full valset after every accepted child: GEPA ("majority of GEPA's rollout budget is spent on validation", [paper](https://arxiv.org/pdf/2507.19457v2) p.9). Full dev on accept only: AutoSaddler `full_on_accept`.
- Staged escalation to save money: DGM 10 → 60 → 200 ([self_improve_step.py](https://github.com/jennyzzt/dgm/blob/a565fd2/self_improve_step.py#L125-L178)); HyperAgents 10 → 100 (`utils/domain_utils.py`); StarHarness smoke (1 task, 20 turns) → test-flip → LLM proceed gate → 20-task selection. Adaptive subsets with unbiased estimate (−80% evaluations): Task-CoEvolve ([arXiv 2608.20169](https://arxiv.org/abs/2608.20169), code "soon").

**Held-out / blinded splits.**
- Three-way with a proposer-hidden *selection* set: StarHarness (search/selection/holdout, disjointness asserted in `validate_scenario_sets`). Group-disjoint splits by universe/repo: AutoSaddler (Table 6). Train/val/test with val-content hidden from reflection: GEPA ("direct access to the content of validation instances is restricted", p.8). Evolve set + ID held-out + OOD benchmarks: RRSI. Code-enforced deletion of val/test eval dirs from the sandbox: HyperAgents `copy_prev_eval_to_container` (but dataset CSVs leaked, [#39](https://github.com/facebookresearch/HyperAgents/issues/39)). Code-enforced: evidence builder raises on non-train evals, dev artifacts quarantined, lessons may cite train IDs only: AutoSaddler v2 ([evidence.py](https://github.com/microsoft/AutoSaddler/blob/main/src/autosaddler/v2/plugins/meta_are/evidence.py)).
- **No held-out at all**: DGM (search set = reported set), Meta-Harness TB2, HSI Setup A, RRSI inside the loop (feedback and selection on the same evolve set; paper calls it adaptive data analysis and relies on δ).

**Noise bands and variance-aware rules.**
- Hand-fixed δ = 2·sd(null ΔS) with a `calibrate` command that is unused when δ is set: RRSI ([calibrate.py](https://github.com/google-research/rrsi/blob/main/rrsi/calibrate.py)). An independent reimplementation reports the workspace rule accepting noise in 33/40 null runs **[unverified, summarizer-derived]** ([PR #28](https://github.com/Tyler-R-Kendrick/harness/pull/28)).
- LCB `μ − 0.5σ/√n`: HSI; inert at n=1.
- 40% heuristic threshold "chosen based on the noise observed in preliminary runs": DGM §4.2; `noise_leeway=0.1` in a non-default mode.
- **None**: GEPA (strict sum on 3 examples; own docs: "a large regression on one example can mask improvements"), AutoSaddler (strict > on 3 tasks: one flip = +33 points), StarHarness (> 1e-9 on 20 tasks), Meta-Harness (strict > on 2-trial average: one flip = 0.56 pp "NEW BEST").

**Regression checks.**
- Logged but not gating: AutoSaddler (fixed/regressed/still_failing classes feed reflection), RRSI (attribution scoreboard), StarHarness ("diagnostic evidence, not independent vetoes"), Meta-Harness (per-task deltas printed). Gating on "no regression on held-in and held-out": Self-Harness and AHE (sweep; no code for AHE). Canary tasks + anti-tampering: Beagle/DarwinX ([arXiv 2608.07545](https://arxiv.org/abs/2608.07545)). Flip-centered gating (fail→pass vs pass→fail): AgentDevel ([arXiv 2601.04620](https://arxiv.org/abs/2601.04620), no code).
- reharness is the only system in the deep reads where regression tolerance is part of the admission rule.

**Archives, Pareto, lineage.**
- Keep-all archive with child-count penalty so deceptive dips recover: DGM (Fig. 3 dips at iters 4/56), HyperAgents (`exp(−(n/8)^3)`). Per-instance Pareto front and system-aware merge: GEPA. EvoDAG where the evolution session may rebase to any accepted ancestor: AutoSaddler (Iter 20 and 46 rescues). Commit pool of 2–5 diverse versions + knowledge graph: HSI. Clade metaproductivity (descendants' score, not own) as the expansion signal: HGM ([arXiv 2510.21614](https://arxiv.org/abs/2510.21614), CMP correlation 0.778 vs 0.285 for score).
- Single incumbent: RRSI, StarHarness, reharness.

**Novelty and anti-repetition.**
- Reserved slot for never-exercised component types when stalled (σ_t, window 3) and novelty term ν inside the noise band: RRSI. Prompt-only ledgers of kept/discarded hypotheses: StarHarness, Meta-Harness `evolution_summary.jsonl`, AutoSaddler lessons + v1 `attempted_fixes` registry, HSI `BOOTSTRAP.md` with a meta-level lesson audit. **Nothing**: DGM, GEPA core (issue [#379](https://github.com/gepa-ai/gepa/issues/379)), HyperAgents.

**Leakage screens on the candidate itself.**
- Regex denylist of task names/verifier paths + Opus critic with repair rounds: RRSI ([critic.py](https://github.com/google-research/rrsi/blob/main/rrsi/critic.py)). Train-ID substring scan on changed files: AutoSaddler ([verification.py](https://github.com/microsoft/AutoSaddler/blob/main/src/autosaddler/v2/plugins/meta_are/verification.py)). Forbidden substrings on added lines + quoted task IDs across all splits: StarHarness ([benchmark.py](https://github.com/ServiceNow/StarHarness/blob/main/benchmarks/automationbench/benchmark.py)). Per-task `forbidden_references`: Meta-Harness Harbor pilot. Manual inspection + regex audit only: Meta-Harness TB2, DGM.

**Significance tests and intervals.**
- HyperAgents alone: 5 runs/method, bootstrap CI, Wilcoxon signed-rank. AutoSaddler: mean ± SD over 3 reruns of one optimization run. Everyone else: point estimates. The critique paper ([arXiv 2607.12227](https://arxiv.org/abs/2607.12227)) finds harness evolution at 67.4 below parallel sampling at 72.3 on TB 2.1 at matched budget and +0.6 pp on a disjoint held-out split.

**Pre-registration.** None of the eight. reharness's committed plan before the test run has no analogue in the set; the nearest is the Discovery Certification Protocol ([repo](https://github.com/cxcscmu/Discovery-Certification-Protocol), 0★).

## 3. How reharness's measured results compare in kind

What reharness reports: +13.0 [+2.2, +26.1] then +4.3 [−10.9, +19.6] on a 23-task sealed test with 2 repeats, paired bootstrap over task families; dev gate on 25 tasks × 1 repeat, 1 candidate per round, 3 rounds per segment; W0 itself moved 41.3% → 47.8% between two finals with nothing changed; research slot inconclusive (`docs/RESULTS.md`).

- **Magnitude is inside the field's held-out band.** Frozen-model harness evolution reports roughly +2 to +30 pp on tasks the proposer did not see: StarHarness AutomationBench Finance +29.3 (holdout 50, 1 repeat, GPT-5.4); AutoSaddler +9.0/+9.6/+10.0 (3 reruns); RRSI OOD +1.8 to +4.7 (single runs, ≈1–2 SE); HyperAgents paper-review 0→0.71 but Polyglot full 0.084→0.267; Meta-Harness TB2 +1.7 on the search set itself. reharness's +13 is a mid-range number; its +4.3 matches what RRSI and the critique paper see on genuinely unseen tasks.
- **Dev-to-test shrinkage is universal, not an reharness defect.** reharness: dev 80–84% vs test 52% for W*. AutoSaddler: dev peak 72.3 → test 62.0. StarHarness: evolution-set vs held-out gains ITBench +45.0 vs +31.7, EnterpriseOps +22.0 vs +15.1 (AutomationBench went the other way, +23.0 vs +29.3). GEPA's own blog: val→test gap 9 points for single mutation vs 2 for 2×4 proposals. RRSI Table 2: unregularized 92.8 evolve / 40.3 OOD vs regularized 90.5 / 43.6.
- **Measurement is stricter than any comparator.** Nobody else pre-registers; only HyperAgents reports CIs from independent runs, and its sandbox contained the test labels. DGM's headline is in-sample; Meta-Harness TB2 is in-sample; StarHarness's final is 1 repeat with no interval; RRSI measures held-out post hoc once; HSI Setup B tests on 2–4 tasks. reharness's "process figures vs the claim" framing (gate numbers select the winner, test is the claim) is the discipline the critique literature asks for and does not find.
- **Statistical power is the same problem everywhere; reharness is the only one that says so in its report.** One task is 4 points on 25 and 8 on 12; AutoSaddler's accept gate is 3 tasks (33 pts per flip); Meta-Harness 2 trials × 89 (0.56 pp); StarHarness 20 tasks × 1 (5 pts); ITBench 5 tasks (20 pts). The W0 41.3→47.8 drift reharness measured is the same ±6 the deep reads infer for HyperAgents (0.59–0.75 per-run spread) and MAGE's 5-seed GEPA variance (~7%, [arXiv 2607.11944](https://arxiv.org/abs/2607.11944)).
- **Acceptance rate.** reharness accepted 2 of 6 worker-round candidates in v0.2 and 1 of 3 in v0.1 with a 5-point `min_gain`. AutoSaddler accepted 20 of 39 (strict > on 3 tasks); StarHarness 4/12/5 patches (N not stated); DGM keeps every compiling child (≈51% of children even edit code). reharness's low acceptance is the expected consequence of a gate that has a margin; the others' higher counts include noise promotions by construction.
- **Cost reporting.** reharness: $153 and $373 per activity, per-call ledger. AutoSaddler: $14.56 optimizer spend per patch, no run total. DGM: ≈$22k/run. GEPA: $86 for one benchmark table. Meta-Harness: ~$500/iteration. RRSI, HSI, StarHarness: no search cost at all. reharness is the only one that can state total cost of a claim including failed rounds.
- **The recursion claim.** reharness: C4 designed as R0-vs-R1 by downstream W*, result inconclusive (both arms rejected everything on 12-task inner gates). HyperAgents: meta-agent editable, validated only by lineage task score and one ablation, 5 runs with CI. HSI: meta-on vs meta-off single runs (TextWorld +19), meta edits validated syntactically. Nobody has a positive, controlled, held-out R-on-R result; reharness's "untested, not refuted" is the honest state of the field too.

## 4. Borrowable mechanisms, ranked

Ranked by expected effect on gain or measurement reliability per unit of cost, given the ±6-point noise floor and the $300–400 per activity budget.

| # | Mechanism | Source | Expected effect | Cost / complexity |
|---|---|---|---|---|

## 5. Traps to avoid

1. **Strict-improvement acceptance on single rollouts.** StarHarness (> 1e-9 on 20 × 1), AutoSaddler (> on 3 × 1), Meta-Harness (> on 89 × 2), GEPA (sum > on 3). reharness's own W0 moved 6 points between identical finals. Do not lower `min_gain` or repeats to raise the accepted-patch count. ([GEPA gotchas](https://github.com/gepa-ai/gepa), [StarHarness evolving_harness.py](https://github.com/ServiceNow/StarHarness))
2. **Searching on the scored set and calling it discovery.** DGM's 50.0% and Meta-Harness's TB2 76.4% are in-sample; RRSI later measured such gains shrinking OOD; the critique paper found +0.6 pp held-out. ([arXiv 2603.28052](https://arxiv.org/abs/2603.28052) §4.3; [arXiv 2607.12227](https://arxiv.org/abs/2607.12227))
3. **Objective hacking whenever the scorer is reachable.** DGM's agent deleted hallucination markers and faked test logs ([sakana.ai/dgm](https://sakana.ai/dgm/)); GEPA's KernelBench prompt wrapped the reference implementation; RRSI's eng SKILL.md says verifier gaming "is not hypothetical"; Roesner & Kohno got HyperAgents to disable certificate validation ([arXiv 2609.17817](https://arxiv.org/abs/2609.17817)). Keep gate evidence (tool/hook event logs) written by fixed code, never by the package; the `on_finish` hook is where a future candidate would learn to short-circuit.
4. **Leakage control by prompt instruction or regex instead of information separation.** StarHarness hides selection files by instruction while writing per-task selection scores into a file the proposer is told to read; HyperAgents shipped test CSVs into the sandbox ([#39](https://github.com/facebookresearch/HyperAgents/issues/39)); Meta-Harness's "CANNOT modify meta_harness.py" is prose under `--dangerously-skip-permissions`; AutoSaddler v1 showed oracle events for train tasks. reharness's split filtering in fixed code is the stronger boundary; add regex only as a cheap extra.
5. **"Self-improving improver" by naming.** DGM's diagnoser is a hidden fixed o1 prompt; HyperAgents' meta edits ride along with task edits and are never validated alone; HSI validates meta edits syntactically and reports single-run meta-on/off deltas; RRSI's "recursive" means re-running on new traces. The recursion claim needs reharness's two-arm downstream comparison, and that comparison needs enough attempts per inner gate (12 × 1 cannot see anything).
6. **Widening the mutable surface toward the loop core, model or provider.** HyperAgents leaves `agent/llm.py` editable; StarHarness opens the whole `vendor/stirrup/`; Meta-Harness allows "raw API calls"; HSI's prompt encourages replacing LLM decisions with BFS inside the harness, contradicting its own paper. Keep K's frozen component kinds; add an explicit rule for how much task logic may move into package code.
7. **Accumulation and bloat.** AutoSaddler Iter 46 cherry-picked 8 hooks and lost 12.3 pp; Decagon's GEPA prompts +75% length, −2%; RRSI needs a pruner. reharness's "merge/disable duplicate components" rule needs the cost criterion (#4) to have teeth.
8. **"You must ship a candidate" and fixed iteration counts.** RRSI forces two full evaluations per round with no stop rule; DGM/Meta-Harness run to `max_generation` regardless of evidence. reharness's abandon conditions and budget root are the right shape; do not import forced proposals.
9. **Trusting self-written lessons.** HSI's meta-evolver exists because the evolver "may blame the LLM when the harness was at fault, claim a mechanism works when traces show it was never invoked"; reharness's v0.1 round 1 was exactly such a false lesson (clipping marks). Lessons in the ledger should carry evidence IDs and be checkable against fixed-code event logs.
10. **No matched test-time-scaling baseline.** The critique paper's objection applies: evolution spend ($81–303) is extra search budget. The report should say so and, when affordable, run a best-of-k W0 arm at matched deployment cost ([arXiv 2607.12227](https://arxiv.org/abs/2607.12227)).

**What the comparison shows.**
- *Loop shape* is nearly uniform: single-agent ReAct with a finish protocol; nobody in the set has a planner/executor split or cross-task memory in the base agent. Differences are in context management (RRSI/Meta-Harness summarize; DGM/HyperAgents do nothing) and finish discipline (RRSI's todo gate, Meta-Harness's double confirm, StarHarness's finish-alone turn). reharness's three hook points are the same surface Harness-R1/Harnyx expose as four lifecycle hooks and AutoSaddler as `PreToolUse` middleware.
- *Mutable surface* splits into "whole repo" (DGM, HyperAgents, Meta-Harness TB2, StarHarness), "typed component vocabulary" (RRSI's K, AutoSaddler's θ, reharness's package kinds), and "text only" (GEPA). reharness and RRSI are the only two with a frozen component taxonomy enforced in code; AutoSaddler enforces by path allow-list.
- *Change representation*: unified diffs (DGM, HyperAgents, StarHarness), full-file deltas or commits (AutoSaddler, RRSI, HSI), whole-module replacement (GEPA, Meta-Harness), patch-into-draft with content-addressed release (reharness). AutoSaddler's `sha256(git ls-tree)` identity and append-only event log are the closest engineering analogue to reharness's object store; AutoSaddler and RRSI additionally make the proposer declare per-edit metadata, which reharness does not yet require.
- *Sandboxing*: only DGM, HyperAgents and reharness run candidate code in containers; of those, only reharness denies the candidate scorer/provider handles (DGM passes API keys into the container, HyperAgents leaves `llm.py` editable and `network_mode=host`). RRSI, StarHarness, Meta-Harness and HSI execute proposer-written Python in the host or control-plane process.
- *Signal*: everyone reads traces; the distinguishing choices are whether the proposer sees ground truth of the tasks it is scored on (DGM, RRSI, AutoSaddler v1, StarHarness search tasks: yes; GEPA val, reharness dev/test: no), whether success traces are shown (RRSI, AutoSaddler, Meta-Harness: yes; reharness: failures only), and whether summaries or raw logs are given (Meta-Harness's ablation favors raw).
- *Anti-repeat*: only RRSI (edit history + reserved exploration slot + novelty term) and AutoSaddler (mandatory history analysis + lesson registry) make it structural; HSI adds a meta-level audit of lessons; the rest rely on a ledger the proposer may or may not read. reharness has the idea in R1's prompt text; making it an engine artifact is item #2 in §4.

## 7. Positioning

reharness is ahead of every surveyed system on the measurement side and behind on search breadth and proposer context. Ahead: a comparison plan sealed and committed before the test split is touched, with paired bootstrap intervals and a stated noise floor (no other system pre-registers; only HyperAgents reports CIs, from a sandbox that contained test labels); a per-call budget ledger with reservations and full cost of claims including failed rounds (RRSI, HSI and StarHarness report no search cost at all); an admission rule with a margin and regression tolerance (every comparator promotes on strict improvement over single rollouts or keeps every compiling child); train/dev/test information separation enforced in fixed code rather than by prompt or regex; container isolation that denies the package scorer, provider and credential handles; and an R-on-R protocol that compares R0 and R1 by the W* each produces, which no other system attempts (HyperAgents and HSI validate meta edits by lineage task score or syntax). Behind: one candidate per round against a single incumbent, where AutoSaddler, DGM, HyperAgents and GEPA keep archives or DAGs that rescued runs from dips; a proposer that sees failure summaries only, where Meta-Harness's ablation and RRSI's success lens argue for raw traces and passing behaviors; no engine-owned ledger of hypotheses, predictions and causal attribution (AutoSaddler, RRSI); no cost term in the gate (RRSI); no confirmation re-run before install (DarwinX, Meta-Harness `--full-eval`); gates and inner research gates whose resolution (4–8 points per task) is the same arithmetic the field's noisy acceptance rules suffer from, so the recursion claim remains, as the field's does, untested rather than refuted. On raw gain reharness's +13 and +4 on held-out tasks sit inside the +2 to +30 band that held-out harness-evolution results occupy, and its dev-to-test shrinkage matches AutoSaddler's and StarHarness's; the honest external framing remains "bounded, single-generation RSI prototype with a sealed same-model gain", plus a matched test-time-scaling baseline as the next comparison the critical literature ([arXiv 2607.12227](https://arxiv.org/abs/2607.12227)) would ask for.
