# 演示与结果呈现（v0.5）

> 2026-09-27。主场景为 AutomationBench Marketing，协议见 [DESIGN.md](DESIGN.md)，任务交付见 [ROADMAP.md](ROADMAP.md) M6，研究递归交付见 M7。
> 本文是演示设计，当前尚无该 benchmark 的实测结果。所有示意字段使用“待实测”，不能填造出的上涨分数。

## 1. 观众应理解的结果

一个 agent 执行业务任务后，框架从失败中提炼行为要求，更新 prompt、规则、工作流或小决策模型，再用更新后的版本完成新任务。完整 RSI 演示还要展示研究方法本身如何被更新并参与下一轮改进。观众应看清：

1. 原来在哪里失败，研究员依据什么提出改动。
2. 改动怎样进入实际执行；小模型负责哪个判断，何时回退。
3. 在独立任务上，相对原版本和业界领先模型表现怎样，付出了多少成本。
4. 研究员原先怎样浪费实验或漏掉问题，新研究策略改了什么，下一轮是否实际使用、是否带来更好的研究结果。

主视觉是**完整任务通过率与成本**。局部准确率和模型调用数量不替代业务结果。模型训练产生的增量价值单独说明；没有增量时不将其包装为成功案例。

业务阶段可先展示前三项，并标明研究递归尚未完成。完整框架演示包含第四项；有回用记录但缺独立效果证据时标记“递归机制已验证，C4 未证实”。

## 3. 展示一次真正发生的改进

选择有完整证据的任务轨迹，按以下顺序播放：

- 任务要求、允许工具与初始业务状态。
- 原版本的关键选择及其最终错误状态。
- train/dev 中的失败诊断、提案、完整版本差异。
- 行为要求：当时应该做什么、实际做了什么、证据与验收；随后再展示为什么选择该策略载体。
- 若发生训练：标签来自哪里、训练了哪个决策点、产出了哪个模型。
- 新版本在新任务上的决策和实际工具行为。
- 实际装配的策略版本、是否触发、提出与执行的动作，以及是否被默认或规则覆盖。
- 最终环境核验与这次任务的结果。

训练任务示例可以解释学习过程，但“学到了可复用判断”应由独立任务支持。展示任务按预先声明的规则选取；同时给出全部任务索引和回归案例，不能只播放最好的一次。选择演示片段不改变汇总结果，也不能回过头修改已测试的版本。

适合展示的决策形式包括：继续收集规则还是开始执行、空结果后换查询还是结束、是否补一次可用验证。最终选哪个取决于 M2/M3 的证据，不为了视频效果增加决策点。

## 4. 迭代曲线与版本记录

报告按阶段分开：

- **开发曲线：** 各候选完整任务通过率、实际预算、接受/拒绝/无效状态；同时画原始候选点和保留版本，不用累计最好值隐藏退步。
- **最终测试：** 锁定版本的一次预定评测活动，包含全部重复运行与区间；不画成每代都偷看测试的曲线。
- **版本记录：** 父版本、prompt/workflow 差异、决策模型 ref、训练数据版本与反馈方法、实验费用。
- **轨迹索引：** 每个任务与尝试可定位到输入、执行、终态、官方评分与用量。

报告分别给 C1、C2、C3 写结论：同底座迭代是否改善，相对领先模型的位置，小模型是否具有增量价值。任何一项未被支持都保留在首屏结论中。

M7 完成后增加研究证据页：`R0 → R1 → R1 产生 W2`，显示经验来源、研究策略差异、固定评测裁决和实际回用记录。R1 多看了历史或获得更多预算时，不能把结果单独归因于研究方法变好。

| 研究配置 | 相同起点与预算 | 最终 W 的外部任务表现 | 全部研究成本 | 到达预设质量所需成本 |
|---|---|---|---|---|
| 固定 R0 | 待实测 | 待实测 | 待实测 | 待实测／未达到 |
| 更新后 R1 | 待实测 | 待实测 | 待实测 | 待实测／未达到 |

此表按独立配对 campaign 汇总，只用于 C4；不混入领先基础模型的任务榜。每支内部用开发任务选 W，外部结果不能回流内部选优。公开模型仍是任务能力的外部参照，R0/R1 是同一框架的研究方法对照。

## 5. 讲解脚本

业务阶段使用以下 90 秒脚本；完整 RSI 演示追加约 30 秒研究递归片段。

| 时间 | 画面 | 讲解内容 |
|---|---|---|
| 0–12 秒 | 独立任务结果表，标注范围与成本 | 这个版本相对原始 agent 和领先模型实际取得了什么结果 |
| 12–28 秒 | 一段原始执行与终态检查 | 哪个业务要求没完成，错误怎样发生 |
| 28–45 秒 | 诊断、提案与版本差异 | 执行反馈怎样变成改动；需要训练时说明样本来源 |
| 45–62 秒 | 新任务的决策与操作 | 更新后的策略怎样改变实际行为 |
| 62–78 秒 | 开发曲线、拒绝和回归、最终测试 | 哪些尝试有效，哪些无效，独立任务是否支持提升 |
| 78–90 秒 | 累计成本、配置和复现入口 | 运行成本与改进成本，如何检查证据和复跑 |

旁白使用最终实测数字。没有胜过领先模型就说明差距；质量保持而成本下降时，说明事先设定的质量界限。不能将部分完成率替换成成功率，不能宣称每代必然进步。

研究递归片段只展示一条真实链：过去实验反复遗漏的研究问题 → R0 提议修改诊断/经验检索/辅助检查 → R1 经固定比较后安装 → 下一轮研究实际采用 → C4 结果或未证实说明。不要把人工改好的研究 prompt 当作系统自行提出的案例。

## 6. 两种体验

**证据回放：** 从已发布结果生成静态报告、播放已记录的执行，不调用模型，不重新训练。可以无 key 运行，但界面必须显示“回放”及原始运行时间、版本。

**真实复跑：** 安装锁定的 benchmark 环境，准备模型凭据及训练资源，按冻结配置重新执行。需要时间和预算，不承诺免费或十分钟内完成。

命令（已实现；`improve` / `research` / `evaluate` 需要先冻结对应计划并在 `[rsi]` 里命名，缺引用时阶段会在调用模型之前说明缺什么）：

```bash
ouroloop bench --config examples/automationbench/marketing.toml --phase baseline
ouroloop bench --config examples/automationbench/marketing.toml --phase collect
ouroloop bench --config examples/automationbench/marketing.toml --phase improve
ouroloop bench --config examples/automationbench/marketing.toml --phase research
ouroloop bench --config examples/automationbench/marketing.toml --phase evaluate
ouroloop bench --config examples/automationbench/marketing.toml --phase report
```

阶段可运行不等于已有成绩：本仓库尚未用真实模型跑过其中任何一个，演示用的数字目前只来自离线夹具。

`ouroloop demo` 的离线合成一轮保留为本地机制检查，不用它的数字代替业务能力。报告先用静态 HTML、SVG 和文件索引，不增加实时服务。

## 7. 发布前核对

- 所有数字从原始结果重算一致，报告包含完整有效任务分母、重复数和无效尝试。
- 比较双方的任务、模型设置、工具、预算与 fallback 可以核对。
- 隐藏评分没有参与最终任务的在线执行；test 没有参与候选选择。
- 样本、模型卡、版本、用量和证据索引可追溯，公开材料不含凭据。
- 回放与真实运行分开；示意稿、待实测数据和历史场景结果不进入正式成绩。
- 看完后，读者能说出改进了哪个行为、完整任务效果如何、相对领先模型的位置以及花费。
- 完整 RSI 演示有研究策略的提出、验证和回用证据；工程闭环与 C4 收益分别标明。
