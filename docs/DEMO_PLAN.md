# ouroloop 演示方案

> 目的：开发者，以及有业务、也想做 RSI 的企业，第一次接触 ouroloop 时就能感受到 RSI 真的在发生。
> 2026-09-26 起草。先做框架的 demo：贪吃蛇（§2）。行业场景（§4）优先级降低，以后再做。

## 0. 原则

1. **不让业务污染内核。** 内核只加通用能力；行业词汇只出现在场景包里。换一个场景就是换一个场景包，内核不动。
2. **每个数字都来自真实运行，落盘可查。**
3. **内置的编码 agent 只作参考实现和测试台**，不出现在演示里。

## 1. 框架的 aha

他们想知道：这个框架有什么别人没有的？答案是循环真的闭合了。

| 时间 | 做什么 | 看到什么 |
|---|---|---|
| 最初 5 分钟 | `git clone`，然后 `ouroloop demo` | 本地跑完一个完整的 RSI 循环，连续几代，蛇一代比一代活得久：模型在规则蛇会走错的地方接管，增益（每局修对减弄错的步数）逐代上升，被模型走错过的局始终在预算内；门拒掉一个看上去更好、其实没有增益的候选；目标达到就不再训练；演示一次回滚 |
| 第一个小时 | 在自己的 agent 里加 `ask` 和 `outcome`，大约 3 行 | 第一次看清自己 agent 的判断：一天做多少次、哪些反复出现、哪些有结果可学、哪些最值得交给决策模型。agent 的行为不变 |
| 之后 | 积累数据 → 训练 → 过门 → 接管 | demo 里那条曲线，在自己的数据上重现 |

**RSI 要真的在发生，而不是一段动画。** `demo` 必须真跑，每一步都能追查：

- 下一代的数据真的来自上一代：每一代开始时打印这一代的数据由哪个模型版本产生，session 事件里记着这个版本。
- 训练、过门、晋升都真实发生，输出里的每个数字都来自这次运行。
- 拒绝也是真的：故意放进一个坏候选（用打乱的标签训练），它走同一个门，被拒，数字摆在那里。
- 全部落盘、可以核对：运行结束时告诉他，每个决策在 `ledger/`，每个判定在 `gates/`，每个版本和它的父版本在 `models/`。
- 中途环境变了：已部署模型走错的局变多，监控发现并撤销这个版本；下一代用变化后的数据重训，把增益重新拿回来。

这对他们意味着：

- **开发者**：不用再为判断类的工作手调 prompt 和规则。agent 多了一个会从结果里学习的判断层，自带风险预算、门和回滚，全部本地、开源。
- **想做 RSI 的企业**：RSI 不必从训练大模型开始。今天就能从决策层起步：用自己的数据，先 shadow，每次改动都过门、有审计、能回滚。

## 2. 贪吃蛇

结果一目了然（死没死、吃没吃到），数据无限而且快，跟任何行业都无关。

### 2.1 故事线

这也是 ouroloop 自身来历的缩影：TDE 就是 Claude 设计实验、跑训练练出来的。

1. **目标**：研究 agent 收到的目标是"把贪吃蛇玩得更好，做一个像 Jev 那样的决策模型"。
2. **研究 agent 做实验设计**：它清楚自己的运作逻辑，也清楚训练管线。在这个已知环境里，它能用的工具是有限的；结合目标，它要训练的是一个小模型，于是给出实验设计：决策点怎么定义（在合法方向里选一个）、棋盘怎么渲染成输入、标签怎么从环境里得到、选哪个 backbone、训练配方。
3. **研究 agent 不断尝试**：训练，送去过门，读判定，诊断失败（比如模型原地绕圈，就改标签或输入），再训。
4. **一代代变好**：默认回答者是一条简单规则蛇。决策模型只在有把握、而且和规则蛇不同的步上接管，和规则蛇一样的步不算接管；风险是它接管过的局里至少走错一步的局的比例，受预算约束。曲线看的是增益和走错过的局，不是接管比例上升：和规则蛇一样的步既没有价值，也没有风险。模型越好，蛇活得越久、越长，走到规则蛇从没到过的局面；下一代就在这些更难的局面上训练，于是更好。**更好的策略 → 更难的数据 → 更好的策略**，这就是看得见的 RSI。中途换棋盘大小，演示退化、撤销、重训、恢复。

它展示的分工正是主张本身：**LLM 负责推理（当研究员），小模型负责决策（当玩家）。**

### 2.2 决策点和标签

| 决策点 | 类型 | 标签 |
|---|---|---|
| 下一步往哪走 | 在合法方向里选一个（最多 3 个） | 环境往前看：这一步之后会不会死、能不能吃到 |

标签来自环境本身，和当前模型玩得好坏无关。此前在 jev 仓库 `integrations/snake` 里的实验（2026-09-24）可以作为研究 agent 的起点：用 BFS 标签监督，8×8 上平均吃到 27.5 个；用 Monte Carlo playout 的结果当目标只有 11.4；从零样本模型自己的策略做 rollout 失败；零样本通用模型为 0。

### 2.3 两个版本

- 笔记本版：CPU 上的小模型，5 分钟跑完，不需要任何 key。
- 完整版：GPU 主机上用 TDE，一小时内跑完多代。

可以复用 jev 仓库的 `integrations/snake`。

## 3. 内核要加的通用能力

| 能力 | 做什么 |
|---|---|
| `ouroloop demo` | 跑贪吃蛇的多代循环，画出曲线：下一代的数据来自上一代；埋一个会被门拒掉的坏候选；中途环境变化，演示撤销和恢复。全部落盘可查 |
| 决策的可见性报告 | 每个决策点的次数、结果覆盖率、默认回答者的准确率、风险预算内可自动化的比例、逐代曲线。场景相关的指标由场景包通过钩子提供 |

贪吃蛇本身作为一个场景包放在 `examples/snake/`，内核只调用它。

## 4. 行业场景（以后再做）

先后顺序定为补货与降价，然后是客服；决策点在做的时候再定。数据已经调研过：

- 补货：**FreshRetailNet-50K**（叮咚买菜，Hugging Face，CC BY 4.0，约 115 MB，不需要登录）。898 家门店、5 万个门店×商品序列、90 天训练加 7 天评测；每小时的销量和缺货标记、折扣、节假日、天气；销量做过归一化，没有价格和成本；约 20% 是自然缺货，销量被库存截断。M5（Walmart）不用：许可证没核实，没有缺货标记，下载要接受比赛规则。
- 客服：τ²-bench（Sierra，MIT），结果按数据库状态核验。以后可能加的通用能力：`ouroloop import`（把历史记录变成决策和结果）和回放。

没选的场景：编码（只作测试台）、营销获客（结果难以衡量）、医美视频制作（样本少、结果慢、无法归因；以后可以作为客户试点，只取合规审核和选讲法两个决策点）。

## 5. 跑通：在 GPU 主机上的端到端测试

- 训练、校准和推理都在 GPU 主机上，开发机上不跑模型。模型用小的 TDE，每轮训练几分钟，跑 2～3 代。
- 研究 agent 的 LLM 由 `manual` provider 顶替：每次调用把请求写成文件，读结果、写回答，循环接着跑。
- **`manual` provider 和 API provider 的数据协议完全一致**：同一个 `ChatProvider` 接口，同样的请求（system、messages、tools）和同样的回复（文本、工具调用、结束原因、用量）。manual loop 跑通，换成 API provider 也就跑通。
- 验收：逐代曲线（自动决策比例、实际风险、蛇的平均长度和存活步数），每次晋升都有冻结的门记录和新的测试 session。

## 6. 叙事规则（来自对其他产品和框架的调研）

1. **让现有做法在同样的决策上失败给人看。** 规则蛇、以及让商用大模型逐步来玩，都在同样的局面上跑，错误和我们的并排摆出来。
2. **评测器就是产品，被钻空子会毁掉整个故事。** Darwin Gödel Machine 曾删掉幻觉检测标记、伪造测试通过的日志，是改动谱系把它暴露出来的。我们的做法：标签来自研究 agent 碰不到的环境代码；测试集冻结；埋进去的坏候选在屏幕上被门拒掉；谱系公开。
3. **报可靠性，不只报平均值。** 多个种子；每一代都给出 Clopper-Pearson 上界，以及实际错误率对比预算。
4. **成本和延迟放进标题。** 自己测每 1000 个决策的成本和 p50 延迟：小模型每步几毫秒，大模型每步几秒。
5. **几行代码接入，接入期间原有逻辑照常决策。** 展示加上 `ask` 和 `outcome` 前后的代码差异；shadow 阶段衡量的是结果，不是和原有逻辑的一致率。
6. **自动化比例永远和实际错误率、代价一起出现。** Klarna 宣传"AI 处理了三分之二的客服对话"，一年后 CEO 承认质量下降，又开始招人。
7. **可视化借 Darwin Gödel Machine 的做法：** 版本谱系树（节点按分数着色，边是父子关系）加逐代的最好成绩曲线。

## 7. 定位

ouroloop 里的每一块，别处都有：

- 把反复出现的决策交给一个 API、之后按回报学习：Microsoft Decision Service 和 Azure Personalizer（Rank / Reward，apprentice 模式；Personalizer 将于 2026-08-25 退役，官方指向开源的 microsoft/learning-loop）。
- 有把握时用便宜的模型、否则用强模型：LLM 路由和级联（RouteLLM、FrugalGPT），训练信号是偏好或回答质量，不是业务结果。
- 从回报改进 agent：agent RL 框架（OpenPipe ART、Agent Lightning），调的是 LLM 本身。
- 自我改进：DSPy、Darwin Gödel Machine、AlphaEvolve，改写的是 prompt 或代码。

ouroloop 做的是把这些放进同一个开源、本地的循环里：

- 一个小的 typed 决策模型，只用观察到的结果训练，从不用 LLM 的回答当标签；
- 每个决策点一个风险预算，用校准过的统计上界决定模型在哪里可以执行，其余地方走声明的默认回答者（这是 selective prediction 和 Learn-then-Test 的既有方法，不是我们发明的）；
- 冻结的晋升门，有谱系、能回滚；
- 一个 LLM 研究 agent，每一代都在上一代产生的数据上设计实验、重新训练。

在我们调研过的产品和框架里，没有找到把这几样合在一起的。
