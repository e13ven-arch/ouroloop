## 0. 结论先行

我们的 RSI 的特色不在“让 AI 改自己的改进器”——MetaSkill-Evolve、MetaRSI、DGM-H 都已宣称做过——而在**用一个任何人都能复核、也允许失败的协议去证明它**：系统只读自己的实验账目，自己写出下一代研究策略 ρ1，等于把 2026-10-06 那次人工 DIAGNOSIS 交给系统做；然后在 support、hr、finance 三个“它和它的改进过程都没见过失败”的领域上，让人工能做到的最好研究策略 R0、系统自写的 R1、以及看不到自己实验结果的盲版 R1^b，从同一个 W0、同一份冻结输入、同样的预算各开若干次单候选研究会话，每个候选都在对 R 完全隐藏的 25 道 dev 题上读一次——即“冻结孪生点火检验”。要写“AI 获得了自我提升”，四张收据须同时成立：①**自我**，ρ1 的每个字节都追溯到系统会话，预注册之后人对 R 与 K 的改动为 0；②**更会改进**，R1 对 R0 的每候选净增益差 Δ 经精确置换检验单侧 p < 0.05，并且 R1 自己对 W0 为正（防止“学会什么都不做”也算赢）；③**来自经验**，R1 胜过盲版；④**不是搬运旧工件**，R1 胜过把 v0.2 的 W\* 原样装上去的固定补丁。另有封存 test 上的 C1（已安装领域上 W\* 对 W0 的区间下界 > 0，并列报告等成本 pass@k 与无循环臂），作为开源头条要的任务增益。下一步：先改文档、写约 2～3k 行代码与测试（$0），再跑最便宜的决定性一步——约 $45，系统写出 ρ1 与盲版 ρ1^b，在 D1 上开 8 个会话，冻结候选但不读 dev，看系统能否把自己的记录变成一个在行为上可测地不同的改进器。全程在 `workspace-claude-v3` 现有根内，测量约 $570～607，只在有安装时另用 $390 的 final 份额（$181～384），不需要新根；v0.5 再由用户决定是否开新根（约 $500～700），把冻结的整条谱系拿到从未运行过的 operations 上重放，检验复利。成功的含义：在所 pin 的模型与固定外部判分器下，系统从自身记录写出的研究策略，在未见领域上使每个改动的留出增益显著更高；若 ③④ 也成立，这份增益来自它自己的实验经验，而不是模型先验或旧补丁——这是 Weco 所说的“点火”（L2）第一次在预注册、密封、带安慰剂对照的条件下被检验。失败同样有意义：阶段 1 不过，结论是“系统不能从自己的记录诊断自己”（花 $45）；D1 后触发无效停止（约 $179）；在 +2 题/25 上被否定，结论是“一代自我修订没有带来实用大小的改进器提升”。这些都如实写进 RESULTS，方向随之转向工具优先或第二版训练。按现实先验（Δ ≈ +0.75～+1.5 题/25），C4′ 得到支持的概率约 0.04～0.22，在 +2 上被否定约 0.19～0.52，其余是不确定；Δ = 0 时约 0.8 会得到明确否定。C1 得到正面结论的概率约 0.23～0.34。最常见的结局是“不确定”，这一点预先写明，并进入跨版本的累计分析。

### 1.3 三家实验室怎么定义 RSI，谁跑了对照

三家写进安全框架的 RSI 定义都是“进步速率与无 AI 反事实之比”：OpenAI Preparedness Framework v2 的 Critical 档是用 1/5 的时间完成一代；Anthropic RSP 的 AI R&D 档是两年的进步在一年内完成，即约 2 倍速率；DeepMind 的 FSF 约为 2 倍（[OpenAI PF v2](https://cdn.openai.com/pdf/18a02b5d-6b67-4cec-ab64-68cdfbddebcd/preparedness-framework-v2.pdf)，[Anthropic RSP](https://www.anthropic.com/rsp)，[GDM FSF](https://deepmind.google/frontier-safety/)）。没有一家能跑这个反事实。本方案的冻结 R0 臂就是现成的反事实，所以“做出一个有用改动平均要几次研究尝试”的两臂之比（§6.1）可以作为这个定义的**小尺度类比**来报——只称“类比”，不称“实验室的 RSI 指标”。

## 3. 对现有 v0.4 方案的评审

### 3.1 结论

1. **v0.4 里没有“自我”。** R、模型、K 全部冻结，C4 声明 not_run（V0_4 §0.2）。它最多能显示“LLM 从约 50 道 train 题为每个领域调出一个 harness 包，并在封存 test 上站住了”。业界管这叫自动 harness 工程，不叫 RSI；把它叫 RSI，正是 §1.2 列出的“改个名字就叫 RSI”。用户问的“通过什么机制证实”，它回答不了。
2. **它优化的是不决定结论的那个误差。** 约四成统计篇幅在压 dev gate 的误收（每 gate 0.0035、并集界 0.042、δ_u 表、A/A 升档），而主张由封存 test 保护。our-plan-review 的端到端模拟显示：把 gate 换成宽松得多的规则，P(封存 final 下界 > 0) 只变 +0.03～+0.09；候选质量的先验能让它变约 0.6。
3. **final 的功效表没有计缩水。** v0.1 的 dev 增益在 test 上保留约 0.46，v0.2 约 0.1。装 1～2 个领域、test 增益每域 +1.5～2 题时，P(win) 是 0.08～0.39，不是 0.24～0.92；期望算下来，每得到一个正面头条约要 $2k～6k。
4. **工程面大。** 改动触及约 11k 行、10 个模块，比 v0.3 的重建还大；而每次付费活动都暴露过至少 2 个改变结果的缺陷。

## 4. 我们的特色机制与要证实的命题

### 4.1 机制：冻结孪生点火检验

**(1) 什么在改进：研究包 ρ（R 的可变面）。**
- 文件：`research/propose.md`（会话的方法文本）、`research/playbook.md`（ACE 式逐条手册：每条带 id、适用范围、方向 omission/over_action，并引用账目行 id）、`research/skills/*.md`（研究程序，例如“先判断这个领域的失败是遗漏还是做多了”“先找工具与接口层的修复”）。会话里以只读方式挂在 `inputs/research/`。
- 协议性内容（树结构、上限、声明格式）留在 K 的 `SESSION_FORMAT`；其中属于“方法”的句子挪进 R0 的 `propose.md`。原因：方法归 R、协议归 K，否则 R 改不了自己真正的研究习惯，或者能改到 K。
- `research.diagnose`（写笔记的文本）本版**不**进 ρ，笔记由 R0 的 diagnose 写一次、各臂共用。原因：每臂写自己的笔记，同一臂的几个会话就会共用一份随机的笔记集，成为臂级的聚类，会话级置换检验的可交换性随之失效；要恢复就得每个会话各写一套笔记。diagnose 留到 v0.5。
- R 的代码（会话驱动、文件工具、上限、准入）与模型都在 K 里冻结。原因：Gödel Agent 的 100 次运行里 14% 最后比初始还差，DGM 伪造过测试日志；R 的变化只以包的形式出现，并一律由下游结果裁决。
- **R0 = v0.4 的 R**：v0.4 的会话代码（含 P1、P2）、P1 版的 `propose.md`、空的 playbook 与 skills。这是人工能做到的最好版本。P1 文本里关于候选个数的句子按本实验的 k = 1 改写，因为候选个数是协议，归 K。

**(2) 谁写下一代：meta-R，把 DIAGNOSIS 自动化。**
- 同一个 `CodingSession`，换工作树和输入。工作树 = ρ_g；系统文本 = R_g 自己的 `propose.md`（同一个方法既改 W 也改自己，即 STOP 的自我应用），加一段 K 里冻结的元框架说明。元框架由人在预注册前写一次，地位相当于 STOP 的种子改进器，记入自主性账目。
- 输入只有引擎写的记录，按 §5.2 的投影 H0 过滤：账目行（候选声明、diff 摘要、carrier/site/direction、以题计的结果与噪声带）、按域汇总的收据（不含题号）、R 自己的会话或提案记录（`read_transcript`）。`docs/` 下任何人工分析都不给，包括 DIAGNOSIS。
- 输出是对 ρ 的逐条 delta，加一份**改动声明**：每条改动指向账目证据，并用固定的行为特征表（§5.3）预言 R 的哪些行为会变、往哪个方向变。
- 准入由固定代码执行：引用的账目行存在，引用的计数与账目一致（防止编造教训）；不含任何领域的题号与单题字面量（P2）；只改 ρ 内的路径；大小上限（playbook 8000 字符，skills ≤ 12 个）。meta-R 若认为问题出在 K，只能写 `k_change_request` 事件，实验期间不执行。

**(3) 冻结孪生。**
- 每个测试领域 D 有一份冻结研究上下文 C_D：R0 的 diagnose 为 D 当前失败的 train 题写的 7 条笔记、至多 4 条通过的 train 轨迹、W0 的包、工具与包 API、train 覆盖率。
- 随机化单位 = 一次 R 会话，k = 1，产出一个候选。候选在 D 的 25 道 dev 上读一次。产不出有效候选的会话计 y = 0（意向治疗）。
- 各臂只差在挂载的 ρ；会话上限、模型、上下文逐字节相同。

**(4) 对照臂。**
- **R0**：反事实，回答“比人工最好的研究策略强吗”。
- **盲账目臂 R1^b**：同一个 meta-R、同样的指令和上限、同一份 H0，只是 R 的实验结果被抹去——gate 判定、净值、修好与弄坏计数、筛选结果、安装事件、噪声带，以及会话转录里显示这些结果的工具输出，统一替换为“未知”，格式与长度不变。任务失败笔记、候选内容、会话过程照留。它回答“R1 的增益来自它自己的实验结果，还是模型反思一下就能写出来”。
- **固定补丁**：v0.2 的 W\* 包（`examples/automationbench/ceiling/wstar_package/`：写前协议 memory 加 `finish_audit` on_finish hook），不经研究原样装到 W0 上，在每个测试领域的 dev 上读一次。它回答“R1 是否只是把 H0 里最好的旧工件再提一遍”。
- **W0**：每域 2 次与候选同期的新读数，给出绝对产出。

**(5) 收据。** 出处与自主性收据（§4.3 的 ①）；每个阶段边界把 `events.jsonl` 的 sha256 提交到 git；`ouroloop verify` 从原始尝试记录重算每个收据、统计量、预算、自主性账目与绑定链。发布前删去 CLI 注入的账号邮箱。

**(6) 谱系注册表。** 每一代 ρ_g 都以内容 hash 冻结、登记。每个版本加一个新鲜领域，把所有冻结的 ρ 在上面重跑，并按预注册做跨版本累计分析。复利由此在版本之间累积，而不是靠一次运行宣称。

### 4.2 特色在哪里

| 部件 | 谁做过一部分 | 我们补上的 |
|---|---|---|
| 系统自写下一代改进器 | MetaSkill-Evolve、MetaRSI、DGM-H、STOP | 输入只有引擎账目；每条教训都要引用核对过的账目行；改动声明里带可证伪的行为预言 |

### 4.3 要证实的命题（全部预注册；每条写明证实、否证与不确定）

定义：候选 c 在领域 D 的产出 y(c) = Σ_{t ∈ D 的 25 道 dev} (x_{c,t} − p̄_t)，x 是候选的一次读数（0/1），p̄_t 是该题 W0 池（2 次新读数，漂移检查通过时加旧读数）的均值，单位是“题/25”。Y(R) = 各域上 R 臂会话产出均值的等权平均。Δ = Y(R1) − Y(R0)，先在域内相减再平均。

| # | 命题 | 证实 | 否证 | 地位 |
|---|---|---|---|---|
| ① | **自我（出处与自主）**：ρ1 的每个字节都来自 meta-R 会话；R1 臂的每个会话都加载了 ρ1 的 hash；从预注册到 C4′ 结果提交之间，人对 R、K、元框架、H0 投影的改动为 0 | 逐行审计全部通过 | 任何未登记的人工改动：该代降为“人工协助”，不进自主主张 | 主张的前提 |
| 过程 | **能自我诊断**：ρ1 至少有 3 条有效条目（引用核对通过，且对应至少一条可测的行为预言）；量表命中 ≥ 2 项且多于 ρ1^b；改动声明里的行为变化在 D1 的 4 个 R1 会话中至少 3 个出现 | 全部满足 | 任一不满足：报告“系统不能把自己的记录变成行为上可测地不同的改进器” | 阶段 1 的 go/no-go，不进主张 |
| **H1** | **更会改进（主假设，合取）**：H1a Δ > 0，且 H1b Y(R1) > 0 | H1a 与 H1b 各自单侧 α = 0.05 都拒绝零假设 | Δ 的单侧 95% 上界 < +2 题/25：“在 +2 上否定” | **唯一的 C4′ 主张** |
| H2 | **来自经验**：在 D2、D3 上 Y(R1) > Y(R1^b) | H1 成立后，单侧 α = 0.05 | 不成立：只能写“系统写出了更好的研究策略”，不能写“从经验中学会了研究” | 固定顺序第 2 个 |
| H3 | **不是搬运旧工件**：在 D1～D3 上 Y(R1) > Y(固定补丁) | H1、H2 都成立后，单侧 α = 0.05 | 不成立：写“增益与搬运 v0.2 的 W\* 无法区分” | 固定顺序第 3 个 |
| C1 | **任务增益（W 层，另一个族）**：已安装领域上 W\* − W0 的 95% 区间下界 > 0 | 封存 final | 下界 ≤ 0：不确定 | 开源头条 |

次要结局（每臂都报，描述性，带区间）：must-not 断言违例率；候选每次尝试的成本与 W0 之比；“有用改动率”（会话产出 ≥ +2 题/25 的比例）与“每个有用改动要几次研究尝试”的两臂之比——即 §1.3 所说的速率比类比；每个有用改动的研究花费，meta-R 的花费摊到 R1 臂；partial credit 版本的 Y；playbook 条目的有益/有害计数（由固定代码按候选声明里的 `cites` 记，类似 HGM 的 CMP）；条目按“领域知识 / 研究方法 / K 的怪癖”三类分别报告；R1 候选与固定补丁的文本相似度。

### 4.4 措辞上限与对外写法

- **边界。** 改的是包级的研究策略（R 的方法文本、手册与研究技能），不是权重，也不是 R 的代码；模型 pin 住；判分器与协议 K 冻结；信号来自外部断言，不是无标签的。DESIGN §7 的“有界递归自改进（bounded RSI）”口径不变，这次有了测量。
- **H1、H2、H3 都成立：**“在所 pin 的模型（Claude Opus 5.5）与 AutomationBench 的执行断言下，系统从自己的实验账目写出的研究策略，在三个它没见过失败的业务领域上，使每次研究尝试的留出净增益比人工设计的最好研究策略高 X 题/25 [区间]，绝对增益为正；这一增益来自它自己的实验结果（胜过看不到结果的盲版），也不是搬运旧补丁。”自评：L5，Weco 的“点火”L2。
- **只有 H1 成立：**“……系统写出的研究策略更会改进；增益是否来自经验没有分辨出来（或：与盲版无差别）。”
- **在 +2 上否定：**“这一规模下，一代自我修订没有带来实用大小（≥ +2 题/25，每次尝试 8 个百分点）的改进器提升。”
- **不确定：** 照写点估计与区间，进入累计分析。
- **不写：**“第一个让 AI 改进自己改进器的框架”（MetaRSI、MetaSkill-Evolve 在先）；“无监督”；“模型自己变聪明了”；“越改越会改”（要等 v0.5 的 R2 > R1）。可以写：“在未见领域上预注册、密封、带安慰剂与自主性收据的改进器点火检验”。
- **C1 头条：**“在已安装的 k 个领域（n = 25·k 道 test，3 次重复）上，框架把同一模型的通过率从 a% 提到 b%，差 +X [区间]；同成本下 W0 多采样的上界为 c%；一个未经挑选的单次会话产物为 d%；总研究花费 $Y。”若 W\* 低于等成本 pass@k，头条须加“增益未超过等成本多采样的上界”。

### 5.2 H0 的投影（meta-R 看到什么）

- 账目行与收据只保留 marketing、sales 的切片；125 题合并的 gate 数字（含测试领域的 dev）删去。
- R 会话转录里，dev 失败类型直方图那一段工具结果替换为占位符（它是 125 道 dev 合并的，含测试领域）；任何含 support、hr、finance、operations 数据的工具结果同样替换。
- 阶段 0 用正则扫描投影后的 H0：这四个领域的任务 id、领域名与计数字段必须 0 命中（$0）。

### 5.3 一次研究会话（随机化单位）

1. 会话挂载该臂的 ρ 与冻结的 C_D；K 的上限照旧（40 次模型调用、24 次编辑、单次读轨迹 65536 字节、会话累计 524288 字节）；`read_trajectory` 只列、只读 D 的 train 尝试（失败与通过都可读）。
2. 只提交 1 个候选；草稿检查、准入、P2 的字面量检查照旧；声明加 `cites`（用了哪些手册条目）。
3. 固定代码从会话事件算出**行为特征表**：候选 carrier（memory/skill/hook/tool/agent）、`direction`、是否带 `not_when`、`trigger_condition` 是否非恒真、读失败轨迹数、读通过轨迹数、回合数、编辑数、草稿检查失败数、候选字节数、引用的手册条目数。meta-R 的行为预言只能用这张表表达（特征、方向、领域范围），表本身预注册。
4. 同一领域里，各臂的会话按 hash 随机顺序跑完；所有候选先构建、冻结，hash 提交到 git，然后才开始读数。
5. 读数窗口：该领域的全部候选读数、2 次 W0 新读数、1 次固定补丁读数，按预注册种子随机交错，8 路并发，在同一个时间窗里跑完。每次尝试记录 `claude --version` 与注入日期；CLI 关闭自动更新。

### 5.5 C1：安装与封存 final

- **安装规则（只用一个 T）。** 候选池 = 该领域 R0、R1、R1^b 三臂的全部有效候选；固定补丁不入池（它不是本次实验产生的）。取第一读数最高者，它对 W0 池 ≥ +2 题才取一次确认读数；确认读数单独对 W0 池 ≥ +3 题、退步（逐题均值下降 > 0.5）≤ 2 题、成本项（β0 0.10、β1 2.0）满足，才按 v0.4 §2 的路由装进 `routes[D]`。原因：确认读数与选择独立，挡住赢家诅咒；空候选被装上的概率约 0.02。
- **无循环臂。** 每个领域在任何 dev 读数之前，按预注册种子从该领域的全部有效候选中 hash 抽定一个，作“一次会话、不经挑选”的基线。
- **封存 final。** 计划先封存、hash 先提交。只读已安装领域的 test：W0、W\*、无循环臂各 25 题 × 3 次。主统计：已安装领域 n = 25·k 道题上 W\* − W0 的配对差（每题先平均 3 次），按家族 bootstrap 2000 次，95% 区间。
- **等成本 pass@k。** k_eq = W\* 与 W0 每次尝试的成本之比；用 W0 的 3 次重复按无偏估计算 pass@1、pass@2、pass@3，非整数的 k_eq 在相邻两个整数之间线性插值（$0）。W\* − pass@k_eq 与 W\* − 无循环臂都给出区间，前者决定头条措辞（§4.4）。
- **归因（$0）。** 用网关与 broker 事件把 W\* 的 test 尝试分成“机制触发”与“未触发”两组，比较两组的翻转。
- **累计分析。** 预注册一个随机效应元分析，覆盖历次封存 final：v0.1 Marketing +13.0、v0.2 Marketing +4.3、本版。README 的头条旁边给出这条累计记录。

## 6. 统计

### 6.1 估计量与检验

- **H1a（Δ > 0）：** 统计量 = 各域（R1 臂均值 − R0 臂均值）的等权平均。在每个领域内把 R0 与 R1 的会话标签置换，穷举 C(8,4) × C(8,4) × C(6,3) = 70 × 70 × 20 = 98,000 种重标，单侧 α = 0.05。原因：每臂只有 3～4 个会话时，聚类 bootstrap 名义 5% 的实际误判是 0.11～0.15，置换检验是 0.03～0.06（compound_sim 的 `twin_out.txt`、`perm_k1_out.txt`）。
- **H1b（Y(R1) > 0）：** 统计量 = 各域 R1 臂均值的平均。方差 = Σ_D (s²_{R1,D}/n_D + Σ_t s²_t/m)/9，其中 s²_t 是该题 m 次 W0 读数的方差；用 Satterthwaite 自由度的 t 临界值（约 1.86），单侧 α = 0.05。
- **H1 = H1a ∧ H1b：** 交并检验，两者各在 α = 0.05 下拒绝才算支持，整体水平 ≤ 0.05，不需要再调整。
- **三种结论：** 支持 = H1 成立；在 +2 上否定 = 未支持，且 Δ 的单侧 95% 上界（按域方差 s²_1/n_1 + s²_0/n_0 的正态近似）< +2；不确定 = 其余情形。
- **H2：** D2、D3 上 R1 对 R1^b，精确置换（70 × 20 = 1,400 种），只在 H1 成立后检验。
- **H3：** D1～D3 上 Y(R1) − Y(补丁)；补丁是一个固定工件，方差 = Σ_D (s²_{R1,D}/n_D + Σ_t s²_t)/9（W0 池在差值里抵消，补丁只剩一次读数的重跑噪声），t 临界值约 1.86，只在 H1、H2 都成立后检验。模拟：当 R1 的候选只是补丁的重提时，H3 的误拒率 0.047（`h3_sim.out`）。
- **敏感性分析：** 会话 × 题的双向 bootstrap，把推断从“这 75 道 dev 题”推广到领域的题目总体；partial credit 版本的 Y。

### 6.2 功效

本方案的设计（D1 每臂 4、D2 每臂 4、D3 每臂 3；W0 池 3 次读数；t 临界值），每格 1000 次模拟（`plan_sim_t.out`）。产出单位为“题/25”；R0 的绝对产出设为 −0.5（v0.3 的 R 在主张领域上每域约 −0.5）。

| 真实情形 | P(H1a) | P(H1b) | P(H1 支持) | P(H1 且 H2) | P(H1、H2 且 H3) |
|---|---|---|---|---|---|
| 空效应：R0 = R1 = 0 | 0.05 | 0.03 | 0.01 | 0.00 | 0.00 |
| 惰性陷阱：R0 = −0.5，R1 = 0（R1 学会了少做） | 0.12 | 0.04 | **0.02** | 0.01 | 0.00 |
| Δ = +1.5（R1 = +1.0），盲臂与 R1 一样好 | 0.47 | 0.27 | 0.21 | 0.02 | 0.01 |
| Δ = +1.5，盲臂与 R0 一样 | 0.48 | 0.28 | 0.21 | 0.12 | 0.06 |
| Δ = +3（R1 = +2.5），盲臂与 R0 一样，补丁为 0 | 0.85 | 0.75 | **0.70** | 0.52 | 0.37 |
| Δ = +3，盲臂 +1.0 | 0.87 | 0.74 | 0.70 | 0.21 | 0.17 |

读法：
- 合取把“惰性陷阱”的支持率从 0.12 压到 0.02。这条护栏是必要的：只看 Δ，R1 学会提出无害的空改动就能赢。
- 盲臂确实能分辨来源：盲臂与 R1 一样好时，H2 只有约 0.02 通过（行 3）。

三种结论的概率（`refute_sim_t.out`）：

| 真实 Δ | 支持 | 在 +2 上否定 | 不确定 | Δ 的平均标准误 |
|---|---|---|---|---|
| 0（R0 = R1 = −0.5） | 0.00 | 0.82 | 0.18 | 0.76 |
| 0（两者都是 0） | 0.01 | 0.76 | 0.23 | 0.85 |
| +0.75 | 0.04 | 0.52 | 0.44 | 0.75 |
| +1.5 | 0.22 | 0.19 | 0.59 | 0.83 |
| +3 | 0.70 | 0.02 | 0.28 | 0.99 |

- 现实先验：AIDE² 的终点差为 0；EvoAgentBench 上自动演化的迁移效应小而异质；MetaSkill-Evolve 的 +6～8 点是对最终工件、无 seeds。合在一起，诚实的先验是 Δ ≈ +0.5～+1.5，所以“不确定”或“在 +2 上否定”是最可能的结局。这在预注册里写明，不在功效不足时硬下结论（AIDE² 的教训）。
- v0.5 的规模参考：3 个领域、每臂 6 个会话时，H1 支持的概率在 Δ = +1.5 时为 0.32，在 Δ = +3 时为 0.87（`plan_sim_t.out` 的第二段）。加入 operations 作为第 4 个领域后会更高。
- **C1 的功效**（`c1_sim.out`）：3 个领域，每域 8/12/9 个候选，T = +3，test 效应按新题重抽，已计入 dev→test 缩水，每格 20000 次模拟。

  | 候选质量的先验 | 平均候选 | P(至少一次安装) | 期望安装数 | P(C1 下界 > 0) | 假安装占比 |
  |---|---|---|---|---|---|
  | 悲观（类似 v0.3） | +0.60 | 0.84 | 1.35 | 0.23 | 0.20 |
  | 中等 | +1.06 | 0.91 | 1.67 | 0.34 | 0.08 |
  | 乐观（类似 StarHarness） | +2.20 | 0.99 | 2.27 | 0.74 | 0.01 |

  v0.4 原方案在同类先验下（含缩水）约 0.16 / 0.27 / 0.74（our-plan-review S1）。

### 6.3 误收与多重检验

- **两个族，各自 α。** C4′（R 层）与 C1（W 层）是两个事先写明的主张，各用 α = 0.05；对外不把“两者之一成立”当成一个主张，两者的结论分别写。
- **C4′ 族内：** H1 用交并检验，水平 ≤ 0.05；H2、H3 按固定顺序，各 α = 0.05，族误差 ≤ 0.05。
- **无效性停止（D1 之后）：** 8 个候选的合并均值 < 0 且 Δ_D1 < 0 时停。它只能因无效而停，不能因有效而停，不抬高 I 类错误；真效应为 +1.5 时误停概率约 0.03（compounding 方案的模拟）。
- **安装误收：** 空候选约 0.02；异质的空候选（同时修好和弄坏题目）约 0.01～0.07（our-plan-review S1）。假安装只浪费 final 的钱，不影响 C1 的有效性：主张只读封存的 test。
- **不做的事：** 不在边界读数之后临时加读；不按数据改会话数（预算已经封顶，按 ŝd 调整只能变成另一种无效性停止）；不重判 v0.3 的三张被拒收据；C4′ 的结论提交之前不读任何 test。

### 6.4 模拟没覆盖的

- 真实的候选异质性可能大于模拟（每个候选产出的 sd，模拟中为 2.1～3.1 题）。S2 报告实测的 ŝd，并用它重算实际功效后写进报告，但不据此改设计。
- 领域之间的差异：hr 的 W0 dev 是 60%，余量小。
- 供应商漂移：用交错读数处理。
- 盲臂可能退化：盲 meta-R 写出的 ρ1^b 近乎为空时，H2 实际上就是 H1 的重复。缓解：两次 meta-R 用同一指令、同一大小要求，报告两者的条目数。

| 系统 | 改进器被改了吗 | 改进器怎么被测 | 未见领域 | 对照与重复 | 预注册 / 密封 | 本方案的差异 |
|---|---|---|---|---|---|---|
| DGM（[2505.22954](https://arxiv.org/abs/2505.22954)） | 形式上是，诊断器与外环冻结 | 没测；“编码分高＝更会自改”是假设 | 迁移的是工件 | 单跑，不等算力 | 否；头条样本内 | 直接测改进器，在未见领域、留出面板上，强基线 R0 |
| DGM-H / HyperAgents（[2603.19461](https://arxiv.org/html/2603.19461v1)） | 是 | imp@50，0.630 对 0.0 | 是（奥赛评分） | 5 次运行，bootstrap | 否；标签可达（[#39](https://github.com/facebookresearch/HyperAgents/issues/39)） | 同一类估计量；R0 不是格式失败的 0；面板对 R 隐藏；预注册；加盲臂与补丁臂 |

| Meta-Harness / StarHarness | 否 | — | 留出（StarHarness 50 题、1 次重复） | 单跑，无等成本基线 | 否 | 用它们的教训塑造 R0：读原始轨迹，先找工具与接口修复 |

## 9. 风险

1. **效应太小（最大的风险）。** 现实先验下最可能的结局是“不确定”。缓解：三种结论预先写好，最小有意义效应 +2 题/25；Δ = 0 时约 0.8 得到明确否定，这本身就是有信息量的结果；v0.5 加领域、加会话，并做累计分析。
2. **惰性 Goodhart。** R0 在测试领域上的产出是负的，R1 学会“少做、窄做”就能让 Δ > 0。缓解：H1 写成合取，要求 Y(R1) > 0（模拟中惰性陷阱的支持率 0.02）。
3. **先验而非经验。** Opus 不看结果也可能写出更好的研究提示。缓解：盲账目臂 H2；它不成立时措辞降级。
4. **工件搬运。** ρ1 可能直接写进“装上写前协议”之类的 W 机制。缓解：固定补丁臂 H3 与文本相似度；`library/` 本版不进 ρ。
5. **H0 偏 Marketing 的“多做”。** ρ1 可能把“多读多做”写进手册，在 hr、support 上有害，H1 为负。这是有信息量的负结果。缓解：条目带方向标签；must-not 违例率按臂报告。
6. **跨层泄漏。** 缓解：H0 投影过滤并做正则审计；dev 从不进入 R 的输入；人工设计 R0 时看过测试领域 dev 汇总，这一偏差对 R0 有利，即对 H1 保守，照实披露。
7. **推断范围只是 75 道 dev 题。** 主分析以这些题为条件。缓解：双向 bootstrap 作敏感性分析；C1 在 test 上、v0.5 在 operations 上把范围推开。
8. **元层的分叉路径。** S1 失败后人改元框架，等于人在替系统做元研究。缓解：至多 2 次，每次记入自主性账目并公开次数；第 0 次付费读数之后冻结。
9. **K 的缺陷在付费时暴露。** 历史上每次付费活动都暴露过至少 2 个缺陷。缓解：S1 本身就是真实模型的彩排；K 从预注册冻结到 C4′ 结果提交，中途修了 K，就从 S1 重启，或把受影响的数据剔出主张。
10. **漂移。** CLI 注入日期，版本也没 pin。缓解：同一时间窗随机交错读数；关闭 CLI 自动更新；每次尝试记录版本与日期；W0 用同期读数。
11. **评分器漏洞与作弊。** 缓解：§5.7 的审计；must-not 违例率；包够不着评分器。
12. **预算紧。** 全程 ≈ $607，贴着 $605 的线。缓解：放弃顺序；每个阶段开始前的美元上界检查；未结算调用与订阅暂停会吃掉余量，照实记账。
13. **工程量。** 约 2～3k 行。缓解：复用 v0.4 路由的设计；删掉 G 族、δ_u、要约、patience；离线彩排整条流程。
14. **只有一个模型族、一个基准。** 写进局限；第二个模型放到 v0.5。
15. **措辞过度或新意被驳。** 缓解：§4.4 的模板；正文引用 MetaRSI、MetaSkill-Evolve、DGM-H，新意只落在证明协议上。
16. **C1 的赢家诅咒与缩水。** 主张只读 test；模拟已按新题重抽来计入缩水；假安装占比 0.01～0.20，只浪费 final 的钱。

## 10. 考虑过、不做

- **按 v0.4 原稿执行**（四域 C1，R 冻结）。原因：里面没有“自我”，回答不了用户的问题；计入缩水后 P(win) 只有 0.08～0.39。
- **以 recursion 方案为骨架**（本版就在 operations 上做元测试，R_best 经元 gate 谱系选出）。原因：要开新根，最小版约 $1,170、完整版 $2,000～2,400；C1 推迟，失去第二次拿正结果的机会；J = 30～40 只分辨得出很强的效应。它改作 v0.5 的谱系重放。
- **以 rigor-first 方案为骨架。** 原因：只有 8 个配对单位；R0 是 v0.3 的旧文本（AIDE0 式批评）；meta-R 读过测试领域逐域的 dev 计数，属于元层泄漏。它的审计层（`verify`、改动声明）已嫁接进来。
- **打乱结果的安慰剂**（把结果列在尝试之间置换），代替“抹去结果”的盲臂。原因：打乱后的结果是错误信息，会主动误导 meta-R，R1 胜过它可能只是因为对照臂被带偏，会高估“从经验中学”；抹去结果才是“只有先验”的干净对照。
- **本版就跑 R2 臂**（compounding 原稿）。原因：H2 斜率检验的功效只有 0.47；同样的钱换成盲臂，回答的是用户问的“机制”问题。R2 留给 v0.5。
- **ρ 里放 `library/`**（被接受过的 W 机制）。原因：等于把工件迁移设计进改进器，C4′ 分不清“改进器变强”与“搬运旧补丁”。
- **diagnose 进 ρ。** 原因：每臂各写笔记会造成臂级聚类，或者每个会话各写一套、增加花费。留到 v0.5。
- **E0：把从未暴露过的 train 题挪进 test。** 原因：笔记只取 W0 失败的题，从未暴露的题偏向 W0 能通过的题，挪进去会改变 test 的构成与估计量，还要改一个已冻结的划分。
- **每域 gate、δ_u 门槛表、A/A 升档、G ≤ 12、patience、同步 3 轮。** 原因：gate 规则对 P(win) 的影响 < 0.1；一个 T 加确认读数就够了。
- **train 侧筛选（P4）。** 原因：k = 1 时直接读 dev 更便宜，而且无偏。
- **每会话 k = 3。** 原因：同一会话的候选相关；同样的读数开销下，k = 1 的功效与 k = 3 用两倍读数相当。
- **按 D1 的 ŝd 调整会话数**（recursion 与 pragmatic 的建议）。原因：预算已封顶，会话数只能减不能增，这条规则会退化成另一种无效性停止，还多一条按数据分支的路径。
- **元 gate 与多代元训练循环**（recursion）。原因：本版只有一代；元 gate 对空效应约 50% 接受，只保护钱，不保护主张。
- **第二个模型的迁移臂、W0→W1→W2 的谱系 final**（compounding）。原因：只是描述性的，还要和 final 份额抢钱。推迟到 v0.5。
- **借鉴库、要约、迁移漏斗、版本边界晋升**（v0.4）。原因：没有主张依赖它；种子在 sales/hr 已知有害；推迟到有安装之后再说。
- **让 R 改自己的代码。** 原因：Gödel Agent 14% 的运行最后变差；DGM 伪造过日志；R 的变化只以包的形式出现。
- **LLM 当判分器，或在测试流上在线学习**（ACE、AWM 的在线设定，ReasoningBank）。原因：自评分与测试流学习都不是留出证据。
- **把 A = Y(R1)/Y(R0) 称作“实验室的 RSI 指标”。** 原因：Y(R0) ≤ 0 时比值没有定义，尺度也相差太远；只报“每个有用改动所需尝试数”之比，并称作类比。
- **逐行 hash 链。** 原因：阶段边界把 `events.jsonl` 的 sha256 提交到 git，已足够防篡改，代码更少。
- **sales 作测试领域；本版就用 operations。** 原因：sales 在 H0 里，而且最吵；operations 要新工作区和新根，留给 v0.5。
- **“第一个让 AI 改进自己改进器”的措辞。** 原因：MetaRSI 与 MetaSkill-Evolve 在先；DGM-H 也有改进器迁移。
- **训练（权重级自我提升）。** 原因：按 2026-09-30 的决定属于第二版；本方案的 C4′ 是包级的。
