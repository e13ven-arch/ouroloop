## 2. 首版的必要取舍

首个业务后端是 AutomationBench；包代码采用固定 Docker worker/API/broker。首版复用 M0～M7，不建立第二状态机/插件市场；M8、LoRA SFT/Tinker 和新训练验证属于第二版保留设计，不是首版依赖。

首版可生成包内工具/中间件 Python 及技能/经验材料；可变目录和 API 有明确定义，代码不在控制面 import。修改仓库核心/评分/权限/依赖锁不属于包演化；新宿主能力按工程接入。旧 finish 提示正文不等同中间件，必须证明实际 hook 生效。

首版固定 actor 证明 harness 效果，旧 controller 行为保持兼容；新增分离训练与收益检验第二版做。无需先拆尽组件贡献，整体效果与实际执行可查；宣称独立贡献时再做相应对照。

## 3. 开发前已识别的风险

首版新增检查点：包接口/代码测试不等于任务有效；生成代码/测试不能在控制面 import；所有内部工具调用必须经过原权限/预算；after_tool 异常不能重放已执行操作；export 与评测必须使用同一运行 bundle/隔离配置。以下教学/训练风险保留为第二版检查项。

- `model` 旧路径与探针偏向 `.decide()`：新增 generation binding 必须到真实 ChatProvider；不只加字段。
- Agent 当前立即追加返回消息：review 必须前置到写历史和执行之前；拒绝草稿/隐藏签名不进入学生输入。
- actor imitation 与决策事实标签必须分流；当前两类标签准入不能机械复用，采集前/后分别检查。
- 源方法和教师参考若在同一含 dev 答案的上下文生成会污染训练；建立实际的 train 受限调用，而非删一个字段。
- 源/目标工具能力不等价、上下文超长或 renderer 不一致可能使方法无法固化；失败应可诊断，不能用辅助教师分数顶替部署成绩。
- 现有 campaign 接入生成训练必须保持分支隔离、共享总预算和真实 actor 装配；方法更新的成功不能由 R 自评。
- Marketing 家族和成功轨迹数量可能不足以训练或证明收益；先统计、冻结协议，不预设一定涨分。
- 云端 optim step 与业务工具存在不确定副作用；保留未知预算占用，不能通过盲重试制造重复执行。

## 4. 验收与主张分开

**工程完整性**：首版验收诊断输入、能力包文本/代码演化、冻结前草稿检查/修复、隔离边界、回归、发布/独立部署与递归回用；至少一项工具/hook 行为变化。教师/SFT 用例保留为第二版，未运行不算首版缺项；fixture 标 scripted，不能充真实效果。

**真实可运行性**：首版实际 provider 生成受限包代码、隔离工具/hook 执行、同 actor gate/导出和有界 R 比较留有记录；不要求 Tinker/teacher。第二版再记录真实训练链。预算未具备时真实验证标未完成。

**有效性**：同底座独立任务提升支持 C1；同 actor controller 对照支持 C3；R0/R1 下游任务改进比较支持 C4。R1 真实装载证明回用，不单独证明 C4。效果无提升时，说明效果目标未达到，保留基线继续分析；不人为让每次测试必涨。

C2 默认来自领先模型公布数字，仅为外部背景；任务集不同不能宣称胜负。首版不预先取消 C4 验证，也不宣称工程用例证明了真实递归收益。[路线图](ROADMAP.md)列出实现与真实实验的分别完成条件。
