# v0.6 演示与证据交付

> 首版展示：给出任务和资源，框架自动演化能力包代码/材料，验证并发布 app，更新/回用改进策略。教学适配和训练是第二版展示。首版链路已实现并经离线 fixture 验证（脚本研究员，不是真实自动发现），尚未用真实模型运行；以下不是成绩。

## 1. 让用户看到的过程

1. **启动。** 输入任务环境、目标、基础工具权限、初始 actor 和预算；加载默认 runtime、空/初始能力包和 R0，列明固定 package API/隔离资源。不要求 trainer/teacher 或预先优化工作流。
2. **发现并生成。** 起点真实运行暴露失败；R 从 train/fit 失败摘要与断言明细逐题写笔记后汇总，先生成技能/经验，再生成 tools/middlewares 代码与 manifest patch；展示对应证据，不直接改仓库。反馈不足时自动收集合法任务结果再提案。
3. **草稿检查与执行。** 展示冻结前草稿检查与有界修订；纯文本包展示注入/读取事件，含代码的包展示固定 worker 内的接口/测试结果、包摘要和实际工具内部调用、hook 条件/触发/反馈及材料读取。至少一项实际执行机制改变，不能只展示 prompt 前后文本。
4. **验证与继续演化。** 保持 actor 身份/推理配置，在完整固定 dev 清单上比较当前版本与候选，展示整体收益与逐题退化；达到冻结门槛才采用新包。下一轮使用已采用包处理新失败，展示合并/修正/停用候选与拒绝记录；无收益时保留原版本。
5. **交付 app。** 展示 gate/安装、干净目录运行和依赖清单。首版保留更好的能力包/工作流（同 actor），采用训练模型属第二版；报告质量、部署费用和全部改进投入。
6. **递归回用。** 展示 R0 的实验失败模式、R1 的具体改动和隔离比较；通过后下一次真实改进请求采用 R1。若不通过则保留 R0，展示未达门槛的原因，不强行演示成功。

离线脚本 fixture 始终标“脚本夹具”；真实自动提案、真实 SFT、完整评测分别列证据。重放标“回放”，不伪装现场训练。下一业务 session 用 W1 与下一改进步骤用 R1 要分别展示。

第二版在以上有效 h* 后展示教学适配、学生 PASS/REPLACE 真实执行、成功轨迹/SFT、无教师模型验证；沿用 M2/M8 规格，不把它作为首版演示前置。
