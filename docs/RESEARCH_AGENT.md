# 研究员：从任务失败提出可执行改进（v0.4）

> 2026-09-27。配合 [DESIGN.md](DESIGN.md) 与 [ROADMAP.md](ROADMAP.md) 的 M3～M5。
> 本文中的 Experiment、业务 Context 和自动迭代接线是目标设计；尚未实现。已有研究接口和训练作业继续复用。

|---|---|---|

## 1. 职责

研究员读取 train/dev 任务的结果、执行轨迹、可训练信号和预算，提出一个可检查的改进候选，或说明为什么暂时不做实验。它可以建议修改 prompt/workflow、决策点输入与规格、允许范围内的训练配方和数据选择。

研究员必须回答：观察到了什么失败，哪个行为可能导致它，改动怎样改变行为，怎样用完整任务结果判断改动是否有价值。最终任务分数只能支持假设，不能自动证明每一步的因果关系。

框架执行提案、构造数据、训练、运行环境、计费和选择版本。研究员不执行付费训练、不写结果和冠军指针、不修改任务评分器，也不新增未注册的模型、工具或训练目标。

一次提案可以包含围绕同一假设的多个改动；不强制单变量或多臂消融。默认一个候选，具体组件的增量主张用必要对照验证。prompt 已能解决问题时，不要求额外生成一个模型。

## 2. 实验记录

Experiment 包装现有 Candidate 及其证据与执行计划。字段设计如下；框架字段拒绝由提案覆盖。

| 研究员字段 | 含义与约束 |
|---|---|
| `hypothesis` | 失败机制和预期行为变化；非空，不能仅写“提高分数” |
| `evidence_refs` | 当前 Context 中实际提供的 train/dev 轨迹或统计引用 |
| `target_slice` | 已登记的失败切片，可为空；不能选测试任务 |
| `changes` | 一组现有候选类型的改动：prompt、spec、recipe 或已授权的数据选择；每项有目标和差异 |
| `training` | null，或已登记决策点、反馈构造器、允许配方；不能给任意数据路径或伪造标签 |
| `control` | 默认当前开发冠军；小模型增量实验指定相同 prompt/workflow 的默认策略版本 |
| `expected` | 预期任务效果或成本变化，仅作为假设，不控制通过阈值 |
| `abandon_if` | 什么开发结果意味着暂停这个方向；不得要求查看 test |
| `notes` | 局限、替代解释与后续观察 |

框架填写：experiment ID、父版本、完整候选 manifest、数据版本、固定开发评测范围、预算预留、训练作业与模型 ref、实际用量、结果、裁决及原因。

弃权沿用现有接口的无候选语义，并记录原因。重复失败且没有新证据、标签不足、预算不足都可以弃权；基础设施失败不等于研究假设被证伪。

以下是**格式示例，不代表已有实验或收益**。示例只改 prompt；之后是否训练，由反馈与结果决定。

```json
{
  "hypothesis": "业务规则搜索沿用了待处理记录的过滤范围，可能遗漏约束；分开两类查询后再执行写入。",
  "evidence_refs": ["dev/evidence/example-placeholder"],
  "target_slice": "missing_workflow_rule",
  "changes": [
    {
      "kind": "prompt",
      "target": "workflow",
      "change": "分别确定待处理记录范围与业务规则来源，规则查询使用独立的筛选条件。"
    }
  ],
  "training": null,
  "control": "champion",
  "expected": {"metric": "task_completed_correctly", "direction": "up"},
  "abandon_if": "完整开发评测没有改善任务结果，且新增查询增加了成本。"
}
```

## 3. Context：只提供可使用的证据

由框架组装序列化 Context，提案器不持有可直接读取全部工作区的能力。现有 Workspace 含 runtime 引用，不能仅删除一个 held_out 字段就宣称完成隔离；业务接口须按允许字段构造并做访问验证。

| 部分 | 内容 |
|---|---|
| `goal` | 完整任务主指标、费用与时间约束、允许变化范围 |
| `environment` | 业务工具与运行说明；不含测试断言或答案 |
| `versions` | 当前冠军、初始版本、prompt_best 的完整身份；用于比较的模型配置 |
| `task_metrics` | train/dev 的成功、部分完成、失败类别、成本和延迟 |
| `decision_metrics` | 决策点覆盖、模型实际执行比例、回退、标签来源、输入缺失；仅作诊断 |
| `failures` | 有轨迹引用的代表性失败，保留前后操作和可见工具返回 |
| `feedback` | 已登记信号构造方法、有效样本数量、歧义、分支成本与适用策略版本 |
| `experiments` | 历史开发提案、差异、正负结果、费用与被拒原因 |
| `allowed_changes` | 已实现候选类型、目标字段、配方键与规模限制 |
| `budget` | 剩余轮次、训练次数、分支次数、模型调用与 GPU/费用预算 |

train 的事后环境反馈可用于诊断和生成标签，但不能混入该次决策的输入。dev 证据可指导搜索，不作为独立泛化证据；test 的任务内容、评分和轨迹不能进入 Context、训练集或历史实验摘要。

## 4. 诊断到行动

| 观察到的现象 | 首先检查 | 可能的实验 |
|---|---|---|
| 没找到业务规则便开始写入 | 规则是否可通过合法工具发现、查询是否过窄 | 改查询流程；有重复信号后再训练是否补充查询的决策 |
| 写入对象、字段或格式错误 | 工具 schema、目标消歧、传输是否准确 | 确定性校验、结构化参数、输入表示；不用训练硬约束 |
| 声称完成但最终状态不满足 | 是否漏操作、是否看得到完成证据 | 补充可执行验证或结束决策；官方隐藏评分不能在线使用 |
| 多次无效搜索、重试 | 不同选择能否改变后续结果 | 对有限替代动作做分支比较，再决定是否训练 |
| 局部分类变好，任务分数下降 | 输入分布变化、错误位置、预算与回退 | 重新采集、修决策位置或停止使用该模型 |
| 分数提高但总成本失控 | 额外模型、验证、分支与调用是否全计入 | 收紧预算、减少无收益动作，不以局部分数掩盖成本 |
| prompt 方案已稳定有效 | 小模型是否仍有可学模式或能节约运行开销 | 保留 prompt；没有增量就不训练 |
| 新模型或 prompt 后旧标签失效 | 标签是否依赖旧后续策略 | 重验信号适用性或重采集，不能混用版本 |

研究员不被要求一定提出模型训练。对一个已经稳定的规则，最好的实验可能是停止训练并保留规则。

## 5. 执行与边界

1. 提案器收到固定 Context，返回候选或弃权。manual provider 与 LLM 使用同一结构。
2. 校验引用存在、字段可改、反馈来源合规、模型规模与资源预算满足；非法输出可带错误重试一次，仍非法则跳过。
3. 框架固定候选和本轮开发评测计划；需要训练时调用已有作业，否则直接任务评测。
4. 所有候选用完整任务结果比较；局部准确率不能独立决定晋升。
5. 接受后更新完整版本，下轮 train 数据记录新版本身份；拒绝与无效作业也写入日志。
6. 测试阶段由框架运行锁定的候选与对照；研究员不参与 test 选优或根据 test 提下一轮建议。

边界包括：不能修改评分器、基线条件、test 划分、预算或门；不能写账本结果、模型卡实测字段、冠军指针；不能持有服务凭据；不能把模型回答或 gate 结论转为 env 标签；不能把 benchmark 特定答案写进 prompt、特征或专用模型工具。

研究员默认只输出结构化提案。未来增加代码工具时，先把文件、网络和测试资源的访问范围实际隔离；自然语言约束不足以替代隔离。当前版本不以安全机制数量作为能力主张。

## 6. 预算与停止

默认每轮一个候选。只有为一个明确问题比较少量方案时才增加候选数；不建立必须遍历的实验矩阵。

框架按实际调用、分支、训练与评测成本扣预算。费用缺失不能按零参与排序。重复锁由候选内容、数据版本、环境与模型条件标识；有新数据或改变了有效条件时可以重新研究，不能仅换名字重复已失败实验。

终止条件：总预算耗尽、固定无收益耐心耗尽、没有可执行提案，或连续基础设施故障达到预定次数。达到工程停止条件不自动意味着取得性能收益。

## 7. 验收与延期事项

M3/M5 的必要验收：

- 真实失败引用能支持提案，示例中的占位引用不能执行。
- prompt-only 提案不训练；无可靠标签的训练提案不能进入 worker。
- Context、数据集、候选 manifest 的任务组与 split 可追溯，测试内容不可见。
- 改动真正进入运行版本；默认策略与小模型路线可从执行记录区分。
- 下一轮数据由上一轮选定的版本产生；全部用量、结果和停止原因完整。
- manual 路径先可执行，随后接真实 LLM；没有真实收益时不预设“几轮内必须接受”。

训练研究员自身的实验排序、让研究员改自己的 prompt、扩大专家模型池均延期。先按完整业务任务证明闭环有效，再为新研究目标设计反馈与评价。
